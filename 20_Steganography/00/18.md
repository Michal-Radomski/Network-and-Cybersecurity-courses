Sure. A **signed 16-bit audio sample** is simply a 16-bit binary number that can represent both **positive and negative
amplitudes**.

### 1. Why does audio need negative numbers?

Imagine the audio waveform:

```text
          positive
             ↑
             |
        /\   |   /\
       /  \  |  /  \
------/----\-+-/----\------ 0
     /      \|       \
    /        \        \
             |
             ↓
          negative
```

The center (`0`) represents the **middle/resting position** of the audio signal.

The waveform moves above and below that point.

Therefore, we need numbers such as:

```text
+10000
+5000
0
-5000
-10000
```

These are **signed numbers**.

---

## 2. Why 16 bits?

A bit can be either:

```text
0 or 1
```

With 16 bits, there are:

```text
2¹⁶ = 65,536
```

different combinations.

For **signed 16-bit PCM**, these combinations represent:

```text
-32,768 through +32,767
```

That's **65,536 possible values**.

So approximately:

```text
             zero
               ↓
-32768 ←────────0────────→ +32767
```

---

## 3. How is a negative number stored?

Computers normally use **two's complement** for signed integers.

For example, let's use a much smaller 4-bit example first.

A 4-bit signed number can represent:

```text
-8 to +7
```

The binary values are:

```text
0000 =   0
0001 =   1
0010 =   2
0011 =   3
0100 =   4
0101 =   5
0110 =   6
0111 =   7

1000 =  -8
1001 =  -7
1010 =  -6
1011 =  -5
1100 =  -4
1101 =  -3
1110 =  -2
1111 =  -1
```

Notice that the **most significant bit** effectively tells us whether the number is negative:

```text
0xxx → positive
1xxx → negative
```

The same principle applies to 16-bit audio.

---

## 4. Example: +5 and -5

In 4-bit two's complement:

```text
+5 = 0101
```

To get `-5`:

1. Start with `0101`
2. Invert the bits:

```text
1010
```

3. Add 1:

```text
1011
```

Therefore:

```text
0101 = +5
1011 = -5
```

For 16-bit audio, the exact same method is used.

---

## 5. What does a 16-bit audio sample look like?

Suppose we have:

```text
+10,000
```

It is stored as a 16-bit binary value.

A negative sample such as:

```text
-10,000
```

is also stored using 16 bits, but using two's complement.

The audio hardware interprets those bits as a signed number.

So:

```text
binary bits
    ↓
signed integer
    ↓
voltage/amplitude
```

---

## 6. What does `0` mean?

This is important.

For signed PCM, approximately:

```text
-32768 ─────────── 0 ─────────── +32767
                   ↑
                 center
```

A sample of `0` means the digital signal is at its **center/zero amplitude**.

For example, a simple waveform could be:

```text
Samples:

   0
+10000
+20000
+10000
   0
-10000
-20000
-10000
   0
```

When plotted:

```text
       +20000
          ●
        /   \
+10000 ●     ●
       /       \
  0  ●───────────●
                  \
-10000             ●
                    \
-20000               ●
```

The sequence of positive and negative values creates the waveform.

---

## 7. Does `+32767` mean the loudest sound?

Not exactly.

It means the **largest positive value that can be represented by signed 16-bit PCM**.

Similarly:

```text
+32767 = maximum positive sample
-32768 = maximum negative sample
```

If the desired waveform goes beyond this range, it **clips**:

```text
desired waveform:

        /\
       /  \
      /    \
-----/------\-----
```

But if it exceeds the digital range:

```text
+32767 ────────┐
               ├────
               │
               └────
```

the tops get cut off. This produces **clipping/distortion**.

---

### The whole picture

For 16-bit signed PCM:

```text
                 waveform
                    ↓
        +32767 ────●──── maximum
                  /   \
                 /     \
                /       \
       0 ──────●─────────●──── center
              /           \
             /             \
        -32768 ─────────────●── minimum
```

The **16-bit number is just the digital representation of the waveform's amplitude at one sampling instant**.

So if you have:

```text
44,100 samples/second
16 bits/sample
2 channels
```

you can think of the audio as two streams of signed 16-bit numbers, with each number describing the instantaneous amplitude
of its channel.
