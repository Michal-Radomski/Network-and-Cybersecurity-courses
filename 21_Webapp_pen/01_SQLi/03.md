## sqlmap

is an open-source, command-line penetration testing tool written in [Python](https://github.com/sqlmapproject/sqlmap) that
automates the process of detecting and exploiting SQL injection (SQLi) vulnerabilities. It is widely considered the
industry-standard tool for database takeover, allowing testers to instantly identify flaws and safely extract data during
authorized assessments.

## Core Automation Capabilities

Manual SQL injection testing can take hours or days. sqlmap speeds up this workflow by automating several complex actions:

- Vulnerability Detection: Automatically fingerprints the backend database system (DBMS) and tests multiple SQLi vectors.
- Data Extraction: Dumps entire database tables, enumerates users, roles, privileges, and reads specific rows.
- Credential Cracking: Automatically recognizes password hash formats and can attempt dictionary attacks to crack them.
- File System Access: Downloads or uploads files from the underlying operating system server if database permissions allow
  it.
- Out-of-Band Takeover: Establishes an interactive operating system command prompt (--os-shell) under specific high-privilege
  conditions.

---

## Supported SQL Injection Techniques

The tool implements five distinct SQL injection techniques to maximize its chances of success against hardened targets:

1.  Boolean-blind: Deduces data by analyzing changes in HTTP response lengths or page content.
2.  Time-blind: Measures response delays to infer database contents when no errors or text change on screen.
3.  Error-based: Forces the database to trigger descriptive error messages containing the sensitive data.
4.  UNION query-based: Appends UNION ALL SELECT commands to map and stream data directly into the web page.
5.  Stacked queries: Executes entirely separate, secondary SQL commands sequential to the primary query (essential for
    modifications or OS access).

## Essential Command Cheat Sheet

The tool requires explicit flags to direct its automation engines safely.

## 1. Basic Scan against a Target URL

Scans a specific parameter (id) on a target website to check for vulnerabilities.

sqlmap -u "http://example.com" --batch

- --batch: Automatically answers "yes" to all default interactive prompts.

## 2. Scanning Authenticated POST Requests (e.g., Node.js Login Forms)

To test a JSON or POST request (like the React/Node bypass scenario), intercept the request using a proxy like Burp Suite,
save it to a plain text file (request.txt), and pass it to sqlmap.

sqlmap -r request.txt -p username --level=3 --risk=2

- -r request.txt: Parses the full HTTP request including custom headers, cookies, and POST body.
- -p username: Forces the scan to focus specifically on the username parameter.
- --level / --risk: Extends the depth of tests to include headers or riskier payloads.

## 3. Data Enumeration Commands

Once a vulnerability is confirmed, add these flags to retrieve target structural information:

sqlmap -u "http://example.com" --dbs # List all available databases sqlmap -u "http://example.com" -D app_db --tables # List
tables inside 'app_db' sqlmap -u "http://example.com" -D app_db -T users --dump # Extract all data from 'users'

## Defensive Countermeasures Against sqlmap

Because sqlmap sends highly structured, repetitive payloads, defenders can actively monitor and block its footprint:

- Web Application Firewalls (WAFs): Systems like Cloudflare or AWS WAF identify default sqlmap User-Agents and generic SQL
  syntax patterns to drop connections immediately.
- Rate Limiting: sqlmap triggers hundreds of HTTP requests per minute. Aggressive IP rate-limiting cuts off the scanner.
- Code-Level Patching: Secure code using parameterized queries completely neutralizes the underlying vulnerability, rendering
  the tool entirely ineffective.
