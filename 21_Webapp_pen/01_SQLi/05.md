Preventing SQL Injection (SQLi) in a React and Node.js application requires strict separation of data and execution logic.
Because React runs entirely in the browser, **all SQLi prevention must be enforced on the Node.js backend**.

---

### Core Security Principles

1. **Parameterize Every Query:** Never concatenate, interpolate, or format raw user input directly into SQL strings.
2. **Never Trust Client Inputs:** Treat all data coming from React (`req.body`, `req.params`, `req.query`, headers) as
   untrusted.
3. **Use ORMs or Prepared Statements:** Let proven database drivers sanitize variables automatically.

---

### Implementation Options on Node.js

#### Option 1: Parameterized Queries (Raw Drivers like `pg` or `mysql2`)

When using native database drivers, pass values as a separate array argument. The database engine pre-compiles the SQL
structure and treats parameter inputs strictly as literal values.

```javascript
// SECURE: PostgreSQL driver (pg) using $1, $2 placeholders
const express = require("express");
const { Pool } = require("pg");
const pool = new Pool();
const app = express();

app.post("/api/users/search", async (req, res) => {
  const { username } = req.body;

  // Code structure ($1) is separated from input data
  const text = "SELECT id, username, email FROM users WHERE username = $1";
  const values = [username];

  try {
    const result = await pool.query(text, values);
    res.json(result.rows);
  } catch (err) {
    res.status(500).json({ error: "Internal server error" });
  }
});
```

For MySQL (`mysql2`), use standard `?` placeholders:

```javascript
const [rows] = await db.execute("SELECT * FROM users WHERE email = ?", [email]);
```

---

#### Option 2: Using an ORM / Query Builder (Prisma, Sequelize, Knex)

Object-Relational Mapping (ORM) tools parameterize queries under the hood by default.

```javascript
// SECURE: Prisma ORM automatically parameterizes inputs
const { PrismaClient } = require("@prisma/client");
const prisma = new PrismaClient();

app.post("/api/login", async (req, res) => {
  const { email } = req.body;

  const user = await prisma.user.findUnique({
    where: { email: email }, // Safe: Automatically parameterized
  });

  res.json(user);
});
```

> **Warning:** Be cautious when using raw SQL query methods within ORMs (such as `prisma.$queryRaw` or `sequelize.query`).
> Ensure you still use parameter placeholders instead of string interpolation inside raw blocks.

---

### Defense-in-Depth Layering

#### 1. Server-Side Input Schema Validation (Zod / Joi)

Validate type, format, and length before query execution to drop invalid inputs immediately.

```javascript
const { z } = require("zod");

const loginSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});

app.post("/api/login", (req, res, next) => {
  const parseResult = loginSchema.safeParse(req.body);
  if (!parseResult.success) {
    return res.status(400).json({ error: "Invalid input format" });
  }
  next();
});
```

#### 2. Principle of Least Privilege

Configure your Node.js database connection with an account that only holds required operations (e.g., `SELECT`, `INSERT`,
`UPDATE`). Do not connect using administrative credentials like `postgres` or `root`.

#### 3. Client-Side Input Sanitization in React

Use React validation libraries (e.g., Formik, React Hook Form) to improve user UX. _Note: This prevents user error, not
attacks, as API calls can easily bypass the browser._
