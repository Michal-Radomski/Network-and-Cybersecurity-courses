## To completely prevent SQL Injection (SQLi)

in a React and Node.js application, security controls must be applied at the database connection layer in Node.js. Because
React runs entirely in the user's browser, client-side validation can be bypassed by an attacker; therefore, the Node.js
backend must treat all incoming data as fundamentally untrusted. [1, 2]

## 1. The Primary Defense: Parameterized Queries (Prepared Statements)

The single most effective defense against SQL injection is the use of parameterized queries (also known as prepared
statements). This technique forces the database to compile the SQL query structure first, and then insert the user input
strictly as isolated data parameters—never as executable SQL commands. [3, 4, 5, 6, 7]

## Bad (Vulnerable Code)

Do not use template literals or string concatenation to build SQL strings: [8, 9, 10]

// Node.js/Express app.post('/api/users', async (req, res) => { const { username } = req.body; // VULNERABLE: Direct string
interpolation const query = `SELECT * FROM users WHERE username = '${username}'`; const result = await db.query(query); });

## Good (Secure Code)

Pass user inputs into placeholders provided by your database driver: [11, 12]

- Using pg (PostgreSQL):

app.post('/api/users', async (req, res) => { const { username } = req.body; // SECURE: Uses parameterized positional
placeholders ($1) const query = 'SELECT \* FROM users WHERE username = $1'; const result = await db.query(query, [username]);
});

- Using mysql2 (MySQL):

app.post('/api/users', async (req, res) => { const { username } = req.body; // SECURE: Uses question mark (?) placeholders
const query = 'SELECT \* FROM users WHERE username = ?'; const [rows] = await db.execute(query, [username]); });

---

## 2. Modern Defense: Use Object-Relational Mapping (ORMs)

Using a modern ORM or query builder like Prisma, Sequelize, or Knex.js handles parameterization automatically for almost all
standard operations. [13, 14, 15, 16]

## Secure Prisma Example

// Prisma automatically parameterizes values passed into fieldsconst user = await prisma.user.findUnique({ where: { username:
req.body.username }, });

- Warning: If you ever use raw queries inside an ORM (e.g., prisma.$queryRaw), you must still manually parameterize them or
  use the ORM’s specific safe-tagging syntax. [17]

---

## 3. Layered Defense: Backend Input Validation

Validating incoming request data on the Node.js backend ensures that data conforms to strict structural rules before it ever
reaches a database query. If an input field expects an email, the backend should reject it immediately if it contains SQL
syntax like ' OR 1=1 --. Using a schema validation library like Zod or Joi is highly recommended: [18, 19, 20]

import { z } from 'zod'; // Define the exact expected formatconst LoginSchema = z.object({ username:
z.string().min(3).max(30).alphanumeric(), // Rejects special characters like ' or - password: z.string().min(8) });

app.post('/api/login', async (req, res) => { // Validate data before touching the database const validation =
LoginSchema.safeParse(req.body); if (!validation.success) { return res.status(400).json({ error: "Invalid input format" }); }

// Safe data proceeds to parameterized query const { username, password } = validation.data; });

---

## 4. Database-Level Protections: Principle of Least Privilege

If an attacker manages to exploit a flaw, database configurations can minimize the damage: [21]

- Separate Accounts: Do not connect your Node.js application to the database using the root, sa, or postgres superuser
  accounts.
- Restrict Privileges: Use a dedicated application database user account restricted solely to necessary permissions (SELECT,
  INSERT, UPDATE) on specific tables. Disable execution privileges like DROP TABLE or access to file system operations (like
  PostgreSQL's COPY or MySQL's INTO OUTFILE). [22, 23, 24, 25, 26]

---

## Summary Security Checklist

| Action             | Responsibility    | Tools / Methods                                                       |
| ------------------ | ----------------- | --------------------------------------------------------------------- |
| Parameterize       | Backend (Node.js) | Use $1 / ? place-holders or standard ORM functions.                   |
| Validate Schemas   | Backend (Node.js) | Use Zod or Joi to enforce rigorous types and lengths.                 |
| Sanitize UI Fields | Frontend (React)  | Use standard React bindings (avoids basic XSS, sets data boundaries). |
| Lock Down DB       | Database Admin    | Restrict application database user privileges.                        |
