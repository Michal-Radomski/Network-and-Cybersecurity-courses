## SQL Injection (SQLi)

is a critical security vulnerability that occurs when an attacker manipulates a web application's database queries by
inserting malicious SQL code into user input fields. This happens because the application directly concatenates untrusted
input into a SQL statement instead of handling it safely as isolated data, tricking the backend database into executing
unauthorized commands.

## How It Works: A Conceptual Example

Consider a vulnerable login form where a backend PHP script constructs a SQL query like this:

SELECT \* FROM users WHERE username = '$user_input' AND password = '$password_input';

## 1. Normal Behavior

If a legitimate user enters john_doe as the username, the query looks like this:

SELECT \* FROM users WHERE username = 'john_doe' AND password = 'password123';

The database searches for a matching row and logs the user in if the password is correct.

## 2. Malicious Exploitation

An attacker inputs ' OR '1'='1 into the username field. The resulting query breaks the developer's logic:

SELECT \* FROM users WHERE username = '' OR '1'='1' AND password = '...';

## Because '1'='1' is always true, the entire WHERE clause evaluates to true regardless of the username or password. The database returns the first record in the table (typically the administrator account), granting the attacker unauthorized access without a valid password.

## Core Types of SQL Injection

SQLi attacks are generally categorized into three main types based on how attackers extract data from the server:

- In-Band (Classic) SQLi: The attacker uses the same communication channel to launch the attack and gather results. Examples
  include Error-based SQLi (forcing the database to output errors that reveal structure/data) and Union-based SQLi (using the
  UNION operator to combine attacker queries with legitimate ones).
- Inferential (Blind) SQLi: The server does not visibly display data or errors on the screen. Attackers infer data by asking
  the database true/false questions. Examples include Boolean-blind (observing changes in the page layout) and Time-blind
  (forcing the database to pause for several seconds before responding if a condition is true).
- Out-of-Band SQLi: The attacker triggers the database to send data over a separate network protocol (like DNS or HTTP
  requests) to a server controlled by the attacker. This is typically used when responses are too slow or completely
  suppressed.

---

## Potential Impact of a Successful Attack

If left unpatched, SQL injection can have devastating consequences for an organization:

- Data Breaches: Unauthorized reading of sensitive user data, intellectual property, or credit card information.
- Authentication Bypass: Accessing administrative control panels without valid credentials.
- Data Modification/Destruction: Altering, deleting (DROP TABLE), or tampering with crucial database records.
- Remote Code Execution: In some configurations, attackers can leverage database permissions to write malicious files to the
  underlying web server and take full control of the operating system.

---

## Prevention and Remediation

Fixing SQL injection requires decoupling user inputs from the executable query structure.

- Parameterized Queries (Prepared Statements): The most effective defense. Developers pre-compile the SQL query structure,
  ensuring the database treats user input strictly as literal data, never as executable code.
- Stored Procedures: Grouping SQL statements into parameterized procedures on the database side rather than generating
  dynamic SQL strings on the application side.
- Input Sanitization and Validation: Employing allow-lists to ensure inputs contain only expected characters (e.g., forcing
  an ID field to be strictly numeric) before processing.
