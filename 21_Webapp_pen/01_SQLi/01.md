**SQL Injection (SQLi)** occurs when an application accepts untrusted user input and concatenates it directly into a backend
database query. This enables attackers to break out of the data context, alter the query's structure, and execute arbitrary
SQL commands to read, modify, or delete sensitive data.

---

**How It Works: Classic Example**

Consider a login form running this insecure dynamic SQL query:

```sql
-- Vulnerable server-side code:
SELECT * FROM users WHERE username = 'USER_INPUT' AND password = 'USER_INPUT';

```

If an attacker enters `' OR '1'='1` into the username field, the query becomes:

```sql
SELECT * FROM users WHERE username = '' OR '1'='1' AND password = '...';

```

Because `'1'='1'` evaluates to true, the database returns the first user record in the database—typically the administrator
account—bypassing authentication completely without needing a password.

---

**Primary SQLi Categories**

- **In-Band (Classic):** The attacker receives the query results directly within the application's HTTP response.
- **Error-Based:** Forces the database to generate an error message containing extracted data.
- **UNION-Based:** Uses the `UNION` operator to combine output from the original query with results from attacker-crafted
  queries.

- **Inferential (Blind):** The application does not return data directly, so the attacker reconstructs records character by
  character by observing subtle changes in server behavior.
- **Boolean-Based:** Evaluates true/false statements based on whether HTTP responses change (e.g., content rendered vs.
  missing).
- **Time-Based:** Injects delay functions (like `WAITFOR DELAY` or `pg_sleep()`) and measures response times to infer logic
  states.

- **Out-of-Band (OOB):** Used when response data and timing channels are unreliable; forces the database engine to issue DNS
  or HTTP requests back to an attacker-controlled server containing the stolen data.

---

**Prevention and Defense**

1. **Parameterized Queries (Prepared Statements):** Separates query code from variable data. The database treats input
   strictly as data parameters, making structural injection impossible.
2. **Object-Relational Mapping (ORM):** Safe utilization of ORMs (like Entity Framework, Prisma, or Hibernate) parameterizes
   queries by default.
3. **Principle of Least Privilege:** Restrict database accounts used by applications so they cannot perform administrative
   operations (e.g., dropping tables or writing to the file system).
4. **Allowlist Input Validation:** Validate input types, formats, and lengths to filter out malformed payloads prior to
   execution.
