To perform or prevent an authentication bypass using SQL Injection in a React and Node.js application, the vulnerability must
exist in the Node.js backend. React code runs entirely in the user's browser and cannot communicate with the database
directly. [1, 2, 3] If the Node.js backend handles user login inputs unsafely, an attacker can manipulate the query logic to
log in as any user. [4]

---

## The Vulnerable Architecture## 1. React Frontend (The Vector)

The React component safely collects data via state and sends it as a JSON payload to the backend API.

// React login submission handlerconst handleLogin = async () => { await axios.post('/api/login', { username, password }); };

If an attacker inputs malicious payloads into these React input fields—such as setting the username string to ' OR 1=1 --
—React will pass this string exactly as written to the server.

## 2. Vulnerable Node.js Backend (The Flaw)

The vulnerability occurs if the Node.js server dynamically glues the string into a SQL query without using parameterized
safety controls (such as using raw string concatenation with a driver like pg or mysql2). [5]

// VULNERABLE Express route handler app.post('/api/login', async (req, res) => { const { username, password } = req.body;

// CRITICAL FLAW: String interpolation / concatenation const query =
`SELECT * FROM users WHERE username = '${username}' AND password = '${password}'`;

try { const result = await db.query(query); if (result.rows.length > 0) { // If rows are returned, the backend assumes the
login is valid const token = generateJWT(result.rows[0]); return res.json({ success: true, token }); } res.status(401).json({
error: "Invalid credentials" }); } catch (err) { res.status(500).json({ error: "Database error" }); } });

---

## The Attack Payloads

When the backend uses raw string concatenation, special SQL characters like ' (single quote) alter the command structure. [6]

## Payload 1: Classic Tautology Bypass

- Username input: admin' --
- Password input: (Can be anything or left blank) [7]

How the Node.js server compiles the query:

SELECT \* FROM users WHERE username = 'admin' --' AND password = 'blah'

- The Break: The single quote after admin closes the string literal early.
- The Comment: The -- syntax comments out everything after it in standard SQL (PostgreSQL, SQLite). The password check is
  completely ignored by the database. The system returns the admin user record, and Node.js issues a valid JWT token back to
  React. [8, 9, 10, 11, 12]

## Payload 2: Universal True Condition Bypass

- Username input: ' OR '1'='1
- Password input: ' OR '1'='1 [13, 14]

How the Node.js server compiles the query:

SELECT \* FROM users WHERE username = '' OR '1'='1' AND password = '' OR '1'='1'

- The Logic: Because '1'='1' evaluates to true, the database returns the first row found in the table. In most databases, the
  first user created is the root or administrator account, granting the attacker instant administrative privileges. [15, 16,
  17, 18]

---

## The Remediation (Secure Code)

To fix this vulnerability, you must update the Node.js backend to use Parameterized Queries (Prepared Statements). This tells
the database driver to separate the code structure from the user data entirely. [19, 20, 21]

## Secure Node.js Backend Implementation

// SECURE Express route handler app.post('/api/login', async (req, res) => { const { username, password } = req.body;

// SECURE: Placeholders ($1, $2 for Postgres, or ? for MySQL) are used const query = 'SELECT \* FROM users WHERE username =
$1 AND password = $2';

try { // Pass user inputs as an isolated array of values const result = await db.query(query, [username, password]);

    if (result.rows.length > 0) {
      const token = generateJWT(result.rows[0]);
      return res.json({ success: true, token });
    }
    res.status(401).json({ error: "Invalid credentials" });

} catch (err) { res.status(500).json({ error: "Server error" }); } });

When using placeholders, entering admin' -- as a username causes the database to look literally for a user whose username
contains a quote and dashes. The input can no longer manipulate the underlying SQL command logic. [22]
