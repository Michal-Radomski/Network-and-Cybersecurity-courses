Authentication bypass via SQL injection occurs in a React and Node.js stack when user input from the React frontend flows
unparsed into a dynamic SQL query constructed on the Node.js backend.

Because React operates entirely on the client side, it cannot prevent SQL injection on its own—security enforcement depends
entirely on how the Node.js backend handles incoming data before executing database queries.

---

### How the Vulnerability Works

1. **React Frontend (Data Collection):** A user submits credentials via a standard React form component, posting data to the
   backend API via `fetch()` or `axios`.
2. **Node.js Backend (Insecure Concatenation):** The API handler accepts `req.body.username` and `req.body.password` and
   constructs a raw SQL query using string interpolation or template literals instead of parameterized placeholders.
3. **Database Execution:** The database receives a modified SQL command where injected conditional logic overrides the
   intended authentication checks.

```
React Form Input  -->  Express.js Route  -->  Dynamic SQL Query  -->  Authentication Bypassed

```

---

### Insecure Implementation Example

**Vulnerable Node.js / Express Route:**

```javascript
// INSECURE: Concatenating req.body variables directly into the query string
app.post("/api/login", async (req, res) => {
  const { username, password } = req.body;

  // Raw SQL query built using template literals
  const query = `SELECT * FROM users WHERE username = '${username}' AND password = '${password}'`;

  try {
    const result = await db.query(query);

    if (result.rows.length > 0) {
      // Returns successful login session/token if query returns ANY row
      res.status(200).json({ success: true, user: result.rows[0] });
    } else {
      res.status(401).json({ error: "Invalid credentials" });
    }
  } catch (err) {
    res.status(500).json({ error: "Database error" });
  }
});
```

**Payload Execution:**

If an attacker inputs the following into the React login form:

- **Username:** `admin' --` (or `admin' OR '1'='1`)
- **Password:** _(Anything)_

The server compiles the raw query into:

```sql
SELECT * FROM users WHERE username = 'admin' --' AND password = '...'

```

The `--` sequence comments out the remaining SQL code checking for the password. The database executes
`SELECT * FROM users WHERE username = 'admin'`, returns the administrator record, and logs the attacker in as `admin`.

---

### Secure Implementation & Remediation

To prevent SQL injection in a Node.js environment, queries **must** use parameterized placeholders (prepared statements) or a
trusted Object-Relational Mapping (ORM) framework like Prisma, Sequelize, or TypeORM.

#### 1. Using Parameterized Queries (Node-Postgres / `pg`)

Parameters are passed separately from the query logic. The database treats inputs strictly as literal values, rendering SQL
commands inside inputs non-executable.

```javascript
// SECURE: Utilizing parameterized values ($1, $2)
app.post("/api/login", async (req, res) => {
  const { username, password } = req.body;

  // Database engine enforces strict separation of code and data
  const query = "SELECT id, username, password_hash FROM users WHERE username = $1";

  try {
    const result = await db.query(query, [username]);
    const user = result.rows[0];

    // Password comparison using bcrypt (never store plain text)
    if (user && (await bcrypt.compare(password, user.password_hash))) {
      res.status(200).json({ success: true, userId: user.id });
    } else {
      res.status(401).json({ error: "Invalid credentials" });
    }
  } catch (err) {
    res.status(500).json({ error: "Authentication failed" });
  }
});
```

#### 2. Using an ORM (e.g., Prisma)

Modern ORMs automatically sanitize inputs and parameterize queries under the hood.

```javascript
// SECURE: ORM abstracting query generation with parameterization
const user = await prisma.user.findUnique({
  where: { username: req.body.username },
});
```

#### 3. Client-Side Role (React)

While client-side validation in React (e.g., length, regex rules) enhances user experience, **it provides zero security
protection against SQLi** because malicious actors can easily bypass React forms and send payloads directly to your Express
API via API clients (cURL, Postman).
