## To install and use sqlmap

on Ubuntu, you can use the built-in package manager or clone the source code directly from GitHub for the most up-to-date
version.

## Part 1: Installation on Ubuntu

Choose one of the two methods below to install the tool.

## Method 1: The Quickest Way (APT Package Manager)

Ubuntu includes sqlmap in its official repositories. Open your terminal and run:

sudo apt update sudo apt install sqlmap -y

- Pros: Installs dependencies automatically; adds the sqlmap command globally to your system.
- Cons: The repository version might be slightly outdated compared to the active GitHub source.

## Method 2: The Recommended Way (GitHub Clone)

Since sqlmap is written in Python, you can run it directly from the source code without compiling anything. This guarantees
you have the latest exploit payloads.

# Install git and python if you don't have them

sudo apt update && sudo apt install git python3 -y

# Clone the repository

git clone --depth 1 https://github.com sqlmap-dev

# Navigate into the directory

cd sqlmap-dev

# Run the tool

python3 sqlmap.py --version

- Note: If you use the GitHub method, replace the command sqlmap with python3 sqlmap.py in the examples below.

## Part 2: How to Use SQLMap

sqlmap requires specific flags depending on how the web application handles data.

## Scenario 1: Testing a Basic GET Request

Use this when the target parameter is visible directly inside the URL address bar (e.g., ?id=1).

sqlmap -u "http://vulnweb.com" --batch

- -u: Specifies the target URL.
- --batch: Automates the scan by choosing the default answer for every interactive prompt.

## Scenario 2: Testing an Authenticated or POST Request (e.g., Login Forms)

When testing form fields or applications that require login cookies, the most accurate method is to intercept the traffic
with a proxy (like Burp Suite), save the raw HTTP request to a text file, and pass it to sqlmap.

1.  Paste the raw text of the HTTP request into a file named request.txt.
2.  Run the following command:

sqlmap -r request.txt -p username --level=3

- -r request.txt: Tells sqlmap to parse the HTTP request headers, cookies, and POST body from the file.
- -p username: Forces the tool to only test the username input parameter, saving time.
- --level=3: Extends testing to HTTP Cookies and Headers (Default level is 1).

## Scenario 3: Extracting the Data (Data Dumping)

Once sqlmap confirms a parameter is vulnerable, you can use enumeration flags to extract information from the database:

- Step 1: List all databases available on the server

sqlmap -u "http://example.com" --dbs

- Step 2: List tables inside a specific database (e.g., target_db)

sqlmap -u "http://example.com" -D target_db --tables

- Step 3: Dump all records from a specific table (e.g., users)

sqlmap -u "http://example.com" -D target_db -T users --dump

## Part 3: Operational Safety Tips

- Authorized Targets Only: Only run this tool against web applications you own or have explicit, written permission to test.
  Running sqlmap against unauthorized public websites is illegal.
- Session Logs: sqlmap automatically saves your scan progress. If your terminal crashes, re-running the exact same command
  will resume right where you left off.
- Cleaning Cache: If you fix a bug in your code and want to re-test the app from scratch, clear the tool's memory using the
  --flush-session flag.
