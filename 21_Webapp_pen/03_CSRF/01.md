Cross-Site Request Forgery (CSRF) occurs when a malicious website tricks a user's web browser into making an unwanted request
to a trusted web application where the user is currently authenticated.

**How the Attack Works**

1. **Authentication:** A user logs into `your-react-app.com`. The Node.js backend sends back a session ID stored in an
   `httpOnly` cookie.
2. **Exploitation:** The user visits `malicious-site.com` in another tab while remaining logged in.
3. **Trigger:** `malicious-site.com` contains a hidden HTML form or JavaScript request targeting
   `[api.your-react-app.com/user/update-email](https://api.your-react-app.com/user/update-email)`.
4. **Execution:** The browser automatically attaches the session cookie with the cross-origin request.
5. **Impact:** The Node.js server sees a valid session cookie, treats the request as legitimate, and executes the action
   (e.g., changing the email or transferring funds).

**Why Modern React + Node.js Architectures Differ** CSRF specifically targets **cookie-based authentication**. If your React
app uses JSON Web Tokens (JWTs) stored in-memory or in `localStorage` and sends them via the `Authorization: Bearer <token>`
HTTP header, your application is inherently immune to CSRF because browsers do not automatically attach authorization headers
across domains.

**Defense Strategies for Cookie-Based Apps**

- **SameSite Cookie Attribute:** Set your authentication cookies to `SameSite=Lax` or `SameSite=Strict`. This prevents
  browsers from sending the cookie on cross-site POST/PUT/DELETE requests.
- **Anti-CSRF Tokens (Double Submit Cookie Pattern):**
- Node.js generates a unique, unpredictable CSRF token upon session creation.
- Node sends this token to React in an accessible cookie or response body.
- React reads the token and sends it back in a custom HTTP header (e.g., `X-CSRF-Token`) on state-changing requests (`POST`,
  `PUT`, `DELETE`).
- Node.js validates that the header token matches the expected server-side or cookie-stored token before processing the
  request.

- **Custom Request Headers:** Browsers enforce CORS for custom headers. Requiring a custom header like
  `X-Requested-With: XMLHttpRequest` on API routes prevents simple cross-site form submissions from succeeding.
