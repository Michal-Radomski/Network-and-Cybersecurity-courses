File uploads are one of the most critical attack vectors in web applications. When an application accepts uploaded files
without thorough validation, attackers can exploit processing logic to execute code, crash the server, or compromise client
devices.

In a React and Node.js stack, security responsibilities are strictly split: **React** manages user input UX and client-side
pre-validation, while **Node.js** enforces strict file validation, sanitization, and secure storage.

---

### Core File Upload Vulnerabilities

#### 1. Remote Code Execution (RCE) via Unrestricted Uploads

If a Node.js server accepts executable files (e.g., `.js`, `.sh`, `.php`, `.exe`) or stores them inside a publicly accessible
directory with execution permissions, an attacker can upload a malicious script and trigger it via its URL to take full
control of the server.

#### 2. Cross-Site Scripting (XSS) via SVG or HTML Uploads

Scalable Vector Graphics (SVG) files are XML-based documents that can contain inline JavaScript (`<script>` tags or `onload`
attributes). If a React app renders user-uploaded SVGs directly or if the server serves them with
`Content-Type: image/svg+xml`, an attacker can trigger stored XSS to steal cookies or session tokens.

#### 3. XML External Entity (XXE) Attacks

Uploading XML-based files (such as `.svg` vector images or `.docx`/`.xlsx` Office documents) to a backend using insecure XML
parsing libraries can expose system files (`/etc/passwd`), lead to Server-Side Request Forgery (SSRF), or cause Denial of
Service (DoS).

#### 4. Denial of Service (DoS) / Storage Exhaustion

- **File Size Bombs:** Uploading massive files or zip archives (zip bombs) to consume memory, CPU, or storage space.
- **ReDoS / Parsing Crash:** Sending specifically crafted images (e.g., corrupted headers) that cause server-side processing
  image tools to crash.

#### 5. Path Traversal

If the backend uses the uploaded file's original name without sanitization (`../../etc/passwd` or `../../var/www/index.js`),
an attacker can overwrite critical system files or upload files outside the intended directory.

### How to Protect a React / Node.js Application

---

#### 1. Node.js Backend Protections (Crucial Security Layer)

Never trust the file metadata sent by the client (such as `req.file.mimetype` or `file.originalname`). Attackers can easily
spoof these parameters using tools like Postman or Burp Suite.

##### A. Validate Magic Bytes (File Signatures)

Check the actual binary content (magic numbers) of the uploaded file rather than relying on the file extension or MIME type
header.

```javascript
const express = require("express");
const multer = require("multer");
const { fileTypeFromBuffer } = require("file-type");
const path = require("path");
const crypto = require("crypto");

const app = express();

// Store files in memory temporarily for validation
const upload = multer({
  limits: { fileSize: 5 * 1024 * 1024 }, // 5 MB Limit (Prevents DoS)
  storage: multer.memoryStorage(),
});

const ALLOWED_MIME_TYPES = ["image/jpeg", "image/png", "application/pdf"];

app.post("/api/upload", upload.single("file"), async (req, res) => {
  if (!req.file) {
    return res.status(400).json({ error: "No file uploaded." });
  }

  // 1. Validate File Signature (Magic Bytes)
  const detectedType = await fileTypeFromBuffer(req.file.buffer);
  if (!detectedType || !ALLOWED_MIME_TYPES.includes(detectedType.mime)) {
    return res.status(400).json({ error: "Invalid file type detected." });
  }

  // 2. Sanitize File Name (Randomized Filename prevents Path Traversal)
  const safeFilename = crypto.randomBytes(16).toString("hex") + path.extname(detectedType.ext);

  // 3. Save file securely (or stream to S3/Cloud Storage)
  // ... uploadToS3(req.file.buffer, safeFilename) ...

  res.json({ message: "File uploaded successfully", filename: safeFilename });
});
```

##### B. Secure Cloud Storage Over Local Disk Storage

Avoid storing user uploads directly on the Node.js application server disk. Instead:

- Upload files directly to object storage services like **AWS S3**, **Google Cloud Storage**, or **Azure Blob Storage**.
- Serve uploaded files via a CDN or S3 bucket configured with **read-only permissions** and disabled script execution.

##### C. Sanitize and Process SVG Files

If allowing SVG uploads:

- Sanitize SVG content using `DOMPurify` before storing it.
- Or convert SVGs to raster formats (PNG/JPEG) on the backend using libraries like `sharp`:

```javascript
const sharp = require("sharp");

// Convert SVG or raw images directly to clean PNG format
const cleanPngBuffer = await sharp(req.file.buffer).png().toBuffer();
```

#### 2. React Frontend Protections (UX & Safety)

Client-side checks in React enhance user experience by providing immediate feedback, but they must **never** be considered
security enforcement.

##### A. Validate Size and Extension Before Request

```jsx
import React, { useState } from "react";

function FileUpload() {
  const [error, setError] = useState("");

  const handleFileChange = (e) => {
    const file = e.target.files[0];
    if (!file) return;

    // Client-side limit check (UX only)
    const MAX_SIZE = 5 * 1024 * 1024; // 5MB
    const ALLOWED_TYPES = ["image/jpeg", "image/png", "application/pdf"];

    if (file.size > MAX_SIZE) {
      setError("File size exceeds 5MB limit.");
      return;
    }

    if (!ALLOWED_TYPES.includes(file.type)) {
      setError("Only JPG, PNG, and PDF files are allowed.");
      return;
    }

    setError("");
    // Proceed to upload via fetch / axios
  };

  return (
    <div>
      <input type="file" onChange={handleFileChange} accept=".jpg,.jpeg,.png,.pdf" />
      {error && <p style={{ color: "red" }}>{error}</p>}
    </div>
  );
}
```

##### B. Avoid Displaying Untrusted Files Insecurely

- Serve uploaded user files using restrictive `Content-Disposition: attachment` headers when opened, forcing the browser to
  download rather than execute them inline.
- Render user images using standard `<img>` elements rather than inserting SVG code using `dangerouslySetInnerHTML`.

### File Upload Security Checklist

| Category          | Best Practice                                                                                  |
| ----------------- | ---------------------------------------------------------------------------------------------- |
| **File Names**    | Generate randomized filenames (UUIDs/hashes) server-side; strip original filenames.            |
| **Validation**    | Verify file signatures via Magic Bytes (`file-type`), not file extension headers.              |
| **File Sizes**    | Set strict size limits at the middleware layer (`multer({ limits: ... })`).                    |
| **Execution**     | Store uploads outside web roots or on S3 buckets with execution disabled.                      |
| **Image Uploads** | Strip EXIF metadata and re-encode/process uploaded images with tools like `sharp`.             |
| **Headers**       | Serve user uploads with `Content-Type: application/octet-stream` or `Content-Security-Policy`. |
