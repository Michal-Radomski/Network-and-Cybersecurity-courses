Broken cryptography occurs when cryptographic algorithms, protocols, keys, or random number generators are implemented
incorrectly or weak algorithms are used to protect sensitive data. Instead of properly securing information (such as
passwords, credit card numbers, or session tokens), the flaws allow attackers to intercept, decrypt, or tamper with data.

---

### Common Types of Broken Cryptography Vulnerabilities

#### 1. Use of Weak or Deprecated Cryptographic Algorithms

- **The Issue:** Relying on outdated or mathematically broken algorithms (such as MD5, SHA-1, or DES) to hash passwords or
  encrypt sensitive data.
- **The Impact:** Attackers can easily reverse these hashes using precomputed lookup tables (rainbow tables) or brute-force
  methods to uncover plaintext passwords or sensitive user data.

#### 2. Insecure Key Management and Hardcoded Secrets

- **The Issue:** Storing encryption keys directly in the source code, version control systems (like GitHub), or predictable
  locations, or using keys that are too short.
- **The Impact:** If an attacker gains access to the codebase or environment files, they instantly obtain the keys needed to
  decrypt all encrypted data or forge secure session tokens (such as JSON Web Tokens signed with weak secrets).

#### 3. Improper Random Number Generation

- **The Issue:** Using standard, predictable pseudo-random number generators (like `Math.random()` in JavaScript) to generate
  security-sensitive values such as password reset tokens, session identifiers, or initialization vectors (IVs).
- **The Impact:** Attackers can predict future values generated by the random number generator, allowing them to hijack user
  sessions or guess account recovery tokens.

#### 4. Missing Encryption in Transit (Plaintext Communication)

- **The Issue:** Transmitting sensitive data over unencrypted HTTP channels instead of enforcing HTTPS, or allowing weak
  SSL/TLS cipher suites.
- **The Impact:** Anyone on the same network (such as a malicious actor on public Wi-Fi) can perform man-in-the-middle (MitM)
  attacks to intercept passwords, cookies, and personal data in clear text.

---

### Best Practices for Proper Cryptographic Implementation

- **Use Strong, Modern Algorithms:** Employ industry-standard algorithms and hashing functions designed for security, such as
  **Argon2**, **bcrypt**, or **PBKDF2** for password hashing, and **AES-256** for data encryption.
- **Secure Key Storage:** Store encryption keys and secrets in secure environment variables or dedicated secret management
  services (like AWS Secrets Manager, HashiCorp Vault, or Azure Key Vault) rather than hardcoding them.
- **Enforce Transport Layer Security (TLS):** Always enforce HTTPS across the entire web application, use modern TLS
  configurations, and set secure cookie flags (`Secure`, `HttpOnly`).
- **Leverage Cryptographically Secure APIs:** Use built-in libraries designed for security (such as Node.js's `crypto`
  module) with cryptographically secure pseudo-random number generators (`crypto.randomBytes()`) when generating tokens or
  keys.
