Implementing cryptography securely in a **React and Node.js** stack requires understanding the boundary between the
client-side (frontend) and the server-side (backend). Because React code runs entirely in the user's browser (where it can be
inspected, modified, or debugged), **sensitive cryptographic operations, key storage, and hashing must always be handled on
the Node.js backend.**

---

### Core Best Practices for React/Node.js Cryptography

#### 1. Never Perform Cryptographic Operations or Store Secrets in React

- **The Rule:** The frontend should never hold private encryption keys, master secrets, or direct database credentials.
- **Why:** Anything placed in a React application bundle can be easily extracted by users via browser developer tools. Use
  React strictly for presentation and user interaction, sending payloads securely to the Node.js backend via HTTPS for
  processing.

#### 2. Use Purpose-Built Hashing for Passwords (Node.js)

- **The Rule:** Never use fast general-purpose hashing algorithms like MD5, SHA-1, or standard SHA-256 to store user
  passwords.
- **The Practice:** Use computationally intensive and memory-hard algorithms specifically designed for password security,
  such as **bcrypt**, **Argon2**, or **scrypt** on your Node.js server. These include built-in salting to protect against
  rainbow table attacks.

```javascript
// Example using bcrypt on the Node.js backend
const bcrypt = require("bcrypt");

const saltRounds = 12;
const hashPassword = async (plainPassword) => {
  const hashedPassword = await bcrypt.hash(plainPassword, saltRounds);
  return hashedPassword;
};
```

#### 3. Leverage Node.js `crypto` for Tokens and Randomness

- **The Rule:** Avoid insecure random number generators like `Math.random()` when generating session tokens, reset tokens, or
  cryptographic nonces.
- **The Practice:** Use Node's built-in `crypto.randomBytes()` (a Cryptographically Secure Pseudo-Random Number Generator, or
  CSPRNG):

```javascript
const crypto = require("crypto");

// Generate a secure, unpredictable token for password resets
const resetToken = crypto.randomBytes(32).toString("hex");
```

#### 4. Encrypt Data at Rest and in Transit

- **Data in Transit:** Enforce strict **HTTPS** across both your React deployment and Node.js API endpoints. Ensure cookies
  containing session IDs or tokens are marked with `HttpOnly`, `Secure`, and `SameSite` flags to prevent cross-site scripting
  (XSS) theft.
- **Data at Rest:** If storing sensitive user data (like PII or payment details) in a database, use symmetric encryption
  algorithms like **AES-256-GCM** via the Node.js `crypto` module. Ensure encryption keys are stored securely using
  environment variables or dedicated secret managers (e.g., AWS Secrets Manager, HashiCorp Vault)—never hardcoded into your
  code repository.
