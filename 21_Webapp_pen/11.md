Proper error handling in a **React and Node.js** stack ensures that backend crashes are prevented, sensitive system details
are hidden from users, and frontend users receive clear, actionable feedback when something goes wrong.

---

### 1. Backend Error Handling (Node.js / Express)

In Node.js, asynchronous route handlers should catch errors and pass them to a centralized error-handling middleware rather
than crashing the server or leaking stack traces.

#### A. Centralized Error-Handling Middleware

Instead of handling errors inside every single route, define a global error handler at the end of your Express middleware
stack:

```javascript
// errorHandler.js
const errorHandler = (err, req, res, next) => {
  // Log the detailed error internally for debugging
  console.error(err.stack);

  // Determine status code (default to 500 Internal Server Error)
  const statusCode = err.statusCode || 500;

  // Send a safe, generic message to the client in production
  res.status(statusCode).json({
    success: false,
    message: statusCode === 500 ? "Internal Server Error" : err.message,
  });
};

module.exports = errorHandler;
```

#### B. Using `try...catch` in Async Routes

Wrap asynchronous database queries or operations in `try...catch` blocks and pass errors using `next(err)`:

```javascript
const express = require("express");
const router = express.Router();

router.get("/api/user/:id", async (req, res, next) => {
  try {
    const user = await database.findUserById(req.params.id);
    if (!user) {
      const error = new Error("User not found");
      error.statusCode = 404;
      throw error;
    }
    res.json({ success: true, data: user });
  } catch (err) {
    // Pass the error to the Express error-handling middleware
    next(err);
  }
});
```

### 2. Frontend Error Handling (React)

React applications need to handle two types of errors: **API request failures** and **UI rendering crashes**.

#### A. Handling API Errors Gracefully (`try...catch` with `axios` or `fetch`)

When making requests to the Node.js backend, catch network or server errors and store them in state to display user-friendly
messages:

```jsx
import React, { useState } from "react";
import axios from "axios";

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [errorMessage, setErrorMessage] = useState("");
  const [loading, setLoading] = useState(false);

  const fetchUser = async () => {
    setLoading(true);
    setErrorMessage("");
    try {
      const response = await axios.get(`/api/user/${userId}`);
      setUser(response.data.data);
    } catch (err) {
      // Use the message provided by the backend or a fallback
      const message = err.response?.data?.message || "Failed to load user profile. Please try again later.";
      setErrorMessage(message);
    } finally {
      setLoading(false);
    }
  };

  return (
    <div>
      <button onClick={fetchUser}>Load User</button>
      {loading && <p>Loading...</p>}
      {errorMessage && <p className="error-banner">{errorMessage}</p>}
      {user && <div>Welcome, {user.name}</div>}
    </div>
  );
}
```

#### B. Catching Component Rendering Crashes (Error Boundaries)

If a React component throws a JavaScript error during rendering, it can crash the entire application. Use an **Error
Boundary** component to catch rendering failures and show a fallback UI:

```jsx
import React, { Component } from "react";

class ErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false };
  }

  static getDerivedStateFromError(error) {
    // Update state so the next render shows the fallback UI
    return { hasError: true };
  }

  componentDidCatch(error, errorInfo) {
    // Log the error to an external monitoring service (e.g., Sentry)
    console.error("Uncaught error:", error, errorInfo);
  }

  render() {
    if (this.state.hasError) {
      return (
        <div className="fallback-container">
          <h2>Something went wrong.</h2>
          <p>We're having trouble loading this section. Please refresh the page.</p>
        </div>
      );
    }

    return this.props.children;
  }
}

export default ErrorBoundary;
```
