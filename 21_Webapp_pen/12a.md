In JavaScript and Node.js, insecure deserialization or object merging vulnerabilities often intersect with **Prototype
Pollution**, specifically when manipulating the `__proto__` property.

---

### What is `__proto__` and Prototypal Inheritance?

In JavaScript, objects inherit properties and methods from a prototype. Every standard object has a hidden reference called
`__proto__` that points to its prototype object (ultimately leading back to the global `Object.prototype`).

When you access a property on an object, JavaScript first looks at the object itself. If it isn't found, JavaScript looks up
the prototype chain (`__proto__`).

---

### How Prototype Pollution Works

Prototype pollution occurs when an application recursively merges or assigns user-supplied data into an existing JavaScript
object without validating or sanitizing the keys.

#### 1. The Vulnerable Code Pattern

Consider a recursive merge function used to combine user settings with default settings:

```javascript
function merge(target, source) {
  for (let key in source) {
    if (typeof target[key] === "object" && typeof source[key] === "object") {
      merge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
  return target;
}
```

#### 2. The Attack Payload

If an attacker sends a malicious JSON payload structured like this:

```json
{
  "__proto__": {
    "isAdmin": true
  }
}
```

When the `merge` function processes this input, instead of assigning `__proto__` as a regular property, it targets the global
prototype of _all_ objects in the Node.js runtime.

#### 3. The Impact

Once the prototype is polluted:

- **Authorization Bypasses:** Any newly created or existing object that checks `user.isAdmin` will now evaluate to `true`
  (even if the user is unauthenticated), because the property now exists globally on `Object.prototype`.
- **Application Crashes / Denial of Service (DoS):** Overriding built-in prototype methods (like `toString` or `valueOf`) can
  cause core application functions to break unexpectedly.
- **Remote Code Execution (RCE):** In vulnerable applications where polluted properties are later passed into dangerous sinks
  (like templating engines or child process spawners), it can escalate to full system compromise.

---

### Best Practices for Prevention

- **Sanitize Keys:** Explicitly filter or reject incoming keys named `__proto__`, `constructor`, or `prototype` before
  merging or deserializing data.
- **Use Safe Merging Libraries:** Avoid writing custom recursive merge functions. Use well-maintained, security-vetted
  libraries (or modern built-in utility functions) that guard against prototype pollution.
- **Freeze Prototypes:** Prevent modifications to global prototypes by freezing them early in your application lifecycle
  using `Object.freeze(Object.prototype)`.
- **Use `Map` for Key-Value Pairs:** When dealing with dynamic user keys, store them in a `Map` instead of standard
  JavaScript objects, as `Map` instances do not share a prototype chain with standard object properties.
