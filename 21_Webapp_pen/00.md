When building full-stack applications with **React** (frontend) and **Node.js** (backend), security concerns are split
between client-side risks and server-side logic.

Here are the most common vulnerabilities associated with each part of the stack, along with how they typically arise:

---

### 1. React (Frontend) Vulnerabilities

While React natively escapes values embedded in JSX to help prevent basic injection attacks, applications can still face
significant front-end security risks:

- **Cross-Site Scripting (XSS) via Unsafe HTML:**
- _The Issue:_ Using features like `dangerouslySetInnerHTML` or parsing untrusted Markdown/HTML strings directly into the DOM
  can allow attackers to inject malicious JavaScript scripts.
- _Impact:_ Stolen session tokens, modified page content, or hijacked user sessions.

- **Insecure Token Storage:**
- _The Issue:_ Storing sensitive authentication tokens (like JWTs) in vulnerable client-side storage options like
  `localStorage` or `sessionStorage`.
- _Impact:_ If an attacker successfully executes an XSS attack, they can easily read these tokens and impersonate the user.

- **Exposing Secrets in Frontend Code:**
- _The Issue:_ Hardcoding private API keys, database credentials, or secret tokens directly into React code (often mistaken
  as secure because environment variables like `REACT_APP_` are bundled into the public client-side code).
- _Impact:_ Anyone using "Inspect Element" or viewing the bundled source code can extract these secrets.

---

### 2. Node.js (Backend) Vulnerabilities

Node.js servers handle business logic, databases, and authentication, making them prime targets for architectural and
data-handling flaws:

- **Injection Attacks (SQL/NoSQL/Command):**
- _The Issue:_ Directly concatenating or interpolating user-supplied input into database queries or system commands without
  proper sanitization or parameterization.
- _Impact:_ Unauthorized data access, data leaks, data deletion, or complete server compromise.

- **Broken Authentication and Session Management:**
- _The Issue:_ Weak password hashing (e.g., using outdated algorithms instead of `bcrypt`), predictable session IDs, or
  failing to properly invalidate tokens upon logout.
- _Impact:_ Unauthorized account access and privilege escalation.

- **Prototype Pollution:**
- _The Issue:_ A unique JavaScript vulnerability where an attacker manipulates the prototype of base objects
  (`Object.prototype`) through poorly written recursive merge, clone, or property-assignment functions.
- _Impact:_ Can lead to Denial of Service (DoS) or unexpected behavior and remote code execution across the application.

- **Denial of Service (DoS):**
- _The Issue:_ Failing to handle large payloads, unhandled promise rejections crashing the Node process, or expensive regex
  operations (ReDoS) tied to user inputs.
- _Impact:_ Server crashes or unresponsiveness for legitimate users.

---

### 3. Shared Ecosystem & Supply Chain Risks

- **Vulnerable Third-Party Dependencies (NPM Packages):**
- _The Issue:_ Both React and Node.js ecosystems rely heavily on third-party packages. Using outdated or unmaintained
  packages with known Common Vulnerabilities and Exposures (CVEs) introduces risk.
- _Impact:_ Supply chain attacks where malicious code is quietly slipped into widely used utility libraries.

- **Insecure Direct Object References (IDOR) & Broken Access Control:**
- _The Issue:_ Trusting the frontend to handle security. If a Node.js API endpoint accepts a resource ID (e.g.,
  `/api/user/105`) but fails to verify if the currently logged-in user actually owns or has permission to view ID `105`,
  anyone can change the number in the URL to view other data.

---

### Core Prevention Strategies

1. **Never trust client input:** Always validate and sanitize data on the Node.js backend, regardless of whether the React
   frontend already checked it.
2. **Use parameterized queries:** Prevent injection attacks by using ORMs or parameterized query statements for databases.
3. **Secure your tokens:** Store sensitive session tokens in `HttpOnly`, `Secure`, and `SameSite` cookies rather than local
   storage when possible.
4. **Audit dependencies regularly:** Run automated tools like `npm audit` or software composition analysis tools to catch
   vulnerable packages early.
