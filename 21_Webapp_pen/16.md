**X-Frame-Options** is an HTTP response header used in web security to tell a browser whether it is allowed to render a
webpage inside a `<frame>`, `<iframe>`, `<embed>`, or `<object>`.

Its primary purpose is to protect websites against a type of attack known as **clickjacking** (or UI redress attacks).

---

### What Problem Does It Solve?

In a **clickjacking** attack, a malicious website hides a legitimate target website inside a transparent or invisible
`<iframe>` layered on top of the malicious site. When an unsuspecting user clicks on what they think is a harmless button
(like a "Play Video" or "Claim Prize" button), they are actually clicking the hidden button underneath on the secure website
(like a "Transfer Money" or "Delete Account" button).

By setting the correct `X-Frame-Options` header, a website owner can stop other sites from framing their content,
neutralizing this type of trickery.

---

### Main Configuration Values

The `X-Frame-Options` header typically accepts two main directives:

- **`DENY`**: This setting ensures that the webpage **cannot** be displayed in a frame under any circumstances, no matter
  what site is trying to load it.
- **`SAMEORIGIN`**: This allows the webpage to be framed **only** by another page that shares the exact same origin (same
  domain, protocol, and port). This means your own site can frame its own pages, but external sites cannot.

_(Note: While `X-Frame-Options` is still widely used, modern web development often uses a more flexible, comprehensive
security header called **Content Security Policy (CSP)** via the `frame-ancestors` directive to achieve the same goal.)_
