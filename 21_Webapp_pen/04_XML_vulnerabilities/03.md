To protect a React and Node.js application against XML attacks—such as XML External Entity (XXE) injection, XML entity
expansion (XML bombs), and XPath injection—you must secure both your API middleware and file processing logic.

---

### Node.js Backend Protections

#### 1. Enforce Strict Body Parsing (Disable XML Parsers)

Ensure Express only parses JSON and standard URL-encoded forms. Do not use generic body parsers that automatically convert
XML payloads.

```javascript
const express = require("express");
const app = express();

// Strictly accept JSON payloads
app.use(express.json({ limit: "10kb" }));
app.use(express.urlencoded({ extended: true, limit: "10kb" }));

// Reject requests attempting to send XML payloads
app.use((req, res, next) => {
  const contentType = req.headers["content-type"];
  if (contentType && (contentType.includes("xml") || contentType.includes("text/xml"))) {
    return res.status(415).json({ error: "Unsupported Media Type: XML is strictly disabled." });
  }
  next();
});
```

#### 2. Safely Configure XML Parsers (If XML is Mandatory)

If your Node.js application **must** parse XML (for SAML, RSS, or legacy integrations), explicitly disable Document Type
Definitions (DTDs) and external entities in your parsing library.

**Using `xml2js` / `sax`:**

```javascript
const xml2js = require("xml2js");

const safeParser = new xml2js.Parser({
  explicitArray: false,
  // Disable DTD handling to prevent XXE and XML Bombs
  saxOptions: {
    xmlns: true,
    noscript: true,
  },
});

// Avoid using outdated libraries like 'libxmljs' unless manually configured with NOENT: false
```

**Using `fast-xml-parser`:**

```javascript
const { XMLParser } = require("fast-xml-parser");

const parser = new XMLParser({
  allowBooleanAttributes: true,
  processEntities: false, // Prevents entity expansion attacks
});
```

#### 3. Sanitize and Validate Uploaded XML-Based Files (SVGs & Office Docs)

Files like SVGs and Office documents (`.docx`, `.xlsx`) are XML archives. Malicious payloads embedded in vector images can
execute XXE when read by image processors.

- **Sanitize SVGs using `DOMPurify` (with `jsdom`) or `DOMPurify` on upload:**

```javascript
const createDOMPurify = require("dompurify");
const { JSDOM } = require("jsdom");

const window = new JSDOM("").window;
const DOMPurify = createDOMPurify(window);

// Sanitize SVG string before saving or processing
const cleanSvg = DOMPurify.sanitize(rawSvgContent, { USE_PROFILES: { svg: true } });
```

- **Convert SVGs to raster images:** Convert SVGs to PNG or JPEG using tools like `sharp` before storing them on disk or in
  the cloud.

### React Frontend Protections

#### 1. Avoid `dangerouslySetInnerHTML` with SVGs

Rendering untrusted SVG content directly into React components can lead to Cross-Site Scripting (XSS) if the SVG contains
inline JavaScript or embedded entity payloads.

```jsx
// ❌ Dangerous: Renders raw XML/SVG strings directly
<div dangerouslySetInnerHTML={{ __html: userUploadedSvg }} />

// ✅ Secure: Render SVGs safely as standard image tags
<img src={sanitizedSvgUrl} alt="User Upload" />

```

#### 2. Client-Side Sanitization

If users upload or preview SVGs directly in React before hitting the server, sanitize the file content in browser memory
using DOMPurify:

```javascript
import DOMPurify from "dompurify";

const handleFileUpload = (file) => {
  const reader = new FileReader();
  reader.onload = (e) => {
    const rawContent = e.target.result;
    // Strip XML headers, DTDs, and scripts before previewing
    const cleanContent = DOMPurify.sanitize(rawContent, { USE_PROFILES: { svg: true } });
  };
  reader.readAsText(file);
};
```

### Summary Checklist

| Security Area       | Action Item                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------- |
| **API Endpoints**   | Express configured with `express.json()` and strict `Content-Type` validation.              |
| **Parsing Config**  | DTDs and External Entities disabled (`processEntities: false`) on all XML parser instances. |
| **SVG Storage**     | SVGs sanitized with `DOMPurify` or converted to PNG/JPEG via `sharp`.                       |
| **React Rendering** | SVGs served via `<img>` tags rather than `dangerouslySetInnerHTML`.                         |
| **Dependencies**    | Regular `npm audit` scans to catch vulnerable third-party XML modules in `node_modules`.    |
