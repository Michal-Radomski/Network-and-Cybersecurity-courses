**Not necessarily.** While using JSON as your primary API payload drastically reduces your attack surface, **your app can
still be vulnerable to XML attacks.**

You aren't automatically immune just because you didn't write `xml.parse()` in your own code.

---

### Hidden Ways XML Vulnerabilities Enter a JSON App

#### 1. File Uploads (SVG, Office Docs, PDFs)

If your React app lets users upload images or documents, your Node.js backend might process XML behind the scenes:

- **SVG Images:** Scalable Vector Graphics are text files formatted as **pure XML**. If your backend processes or resizes
  SVGs using vulnerable libraries, an attacker can upload a crafted `.svg` containing an XXE payload to read system files or
  execute an SSRF attack.
- **DOCX / XLSX files:** Modern Office files are zipped archives filled with XML files. Processing these with weak parsers
  can expose your server to XXE.

#### 2. Transitive Dependencies (Your `node_modules`)

Your direct code might only use JSON, but third-party npm packages you rely on (SAML authentication modules, legacy payment
gateways, RSS feed readers, or document converters) might bring in XML parsers like `libxmljs` or `xml2js`. If these
dependencies do not explicitly disable external entity processing, XXE vulnerabilities are inherited.

#### 3. Automatic Body Parsers & Content-Type Spoofing

If your Express/Node API uses generic body-parsing middleware configured to handle multiple data types automatically, an
attacker might send an HTTP request with `Content-Type: application/xml` instead of `application/json`. If your middleware
tries to automatically parse XML payloads, the app becomes vulnerable even if you expected JSON.

---

### Security Checklist to Guarantee XML Safety

| Area                          | Security Measure                                                                                                                                                         |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Body Parsers**              | Restrict API body parsers explicitly to JSON (e.g., `express.json()`). Do **not** load general-purpose XML body parsers unless explicitly required.                      |
| **File Uploads**              | If handling SVGs, sanitize them or strip XML `<!DOCTYPE>` declarations before processing/saving. Consider converting SVGs to raster formats (PNG/JPEG) using safe tools. |
| **Dependencies**              | Run `npm audit` or use tools like Snyk to audit `node_modules` for vulnerable XML parsing libraries.                                                                     |
| **XML Parsers (If Required)** | If a dependency _must_ process XML, ensure options like `noent: false` (disabling external entity expansion) or DTD loading are explicitly disabled.                     |
