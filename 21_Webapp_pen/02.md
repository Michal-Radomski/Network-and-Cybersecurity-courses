Same-Origin Policy (SOP) is a fundamental web browser security mechanism that prevents scripts on one website from accessing
or interacting with sensitive data on an entirely different website. [1, 2, 3] It isolates web applications from each other,
ensuring that a malicious website you open in one browser tab cannot steal your personal data, read your messages, or hijack
your session from a legitimate website (like your bank or email) opened in another tab. [4, 5, 6, 7]

---

## What Defines an "Origin"?

A browser considers two URLs to have the same origin if and only if three specific components match exactly: [8]

1.  Protocol (e.g., http vs https)
2.  Host / Domain (e.g., example.com vs ://example.com)
3.  Port (e.g., :80 vs :443 vs :8080) [9, 10, 11, 12]

## Origin Comparison Examples

If a script running on https://example.com tries to access data from other URLs, here is how the browser handles it:

| Target URL          | Same Origin? | Reason for Outcome                            |
| ------------------- | ------------ | --------------------------------------------- |
| https://example.com | YES          | Protocol, host, and port match exactly.       |
| https://example.com | NO           | Port is different (8080 vs default 443).      |
| http://example.com  | NO           | Protocol is different (http vs https).        |
| https://example.com | NO           | Host is different (subdomain does not match). |

---

## How SOP Protects Users

When you log into a website, your browser stores cookies or session tokens to keep you logged in. If you visit a malicious
site in another tab, that site might try to execute a JavaScript fetch request to your bank's API. [13]

- Without SOP: The malicious script could read your bank profile, download your statements, and send them to an attacker.
- With SOP: The browser checks the origin of the request. Since the malicious site's origin does not match the bank's origin,
  the browser blocks the script from reading the database response. [14, 15, 16, 17, 18]

---

## Bypassing SOP Safely: CORS

Sometimes, developers need two different origins to share data safely (for example, your React frontend on https://myapp.com
talking to your Node.js API on https://myapp.com). [31] To allow this without completely disabling security, browsers use
Cross-Origin Resource Sharing (CORS). CORS allows a server to use specific HTTP headers (like Access-Control-Allow-Origin) to
tell the browser: "I trust this specific external origin; please let it read my data." [32, 33, 34, 35]
