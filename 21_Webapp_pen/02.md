The **Same-Origin Policy (SOP)** is a fundamental web browser security mechanism that restricts how a document or script
loaded from one origin can interact with resources from another origin. It prevents malicious websites from reading sensitive
data out of authenticated sessions on other sites.

---

**What Constitutes an "Origin"?**

An origin is defined by the exact combination of three components: **Protocol (Scheme)**, **Hostname (Domain)**, and
**Port**. If any of these three elements differ, the browser considers the origins distinct.

Comparing targets against the base URL `[http://example.com/app/index.html](http://example.com/app/index.html)` (HTTP,
default Port 80):

| Target URL                                                                         | Same Origin? | Reason                                 |
| ---------------------------------------------------------------------------------- | ------------ | -------------------------------------- |
| `[http://example.com/app/profile.html](http://example.com/app/profile.html)`       | **Yes**      | Protocol, host, and port match exactly |
| `[http://example.com/api/data](http://example.com/api/data)`                       | **Yes**      | Path differences do not change origin  |
| `[https://example.com/app/index.html](https://example.com/app/index.html)`         | **No**       | Protocol mismatch (`https` vs `http`)  |
| `[http://api.example.com/app/index.html](http://api.example.com/app/index.html)`   | **No**       | Hostname mismatch (subdomain differs)  |
| `[http://example.com:8080/app/index.html](http://example.com:8080/app/index.html)` | **No**       | Port mismatch (`8080` vs `80`)         |

---

**What SOP Enforces vs. Allows**

SOP primarily governs **read access** via client-side scripts (`fetch`, `XMLHttpRequest`, DOM access):

- **Blocked:** Reading response data or DOM contents across origins (e.g., JavaScript on `malicious.com` making a `fetch()`
  request to `bank.com` cannot read the response data).
- **Allowed:** Cross-origin **embedding** and **writes** by default (e.g., loading images via `<img>`, embedding scripts via
  `<script>`, rendering frames via `<iframe>`, or submitting HTML `<form>` POST requests).

**Exceptions and Relaxations**

1. **CORS (Cross-Origin Resource Sharing):** Servers can use HTTP response headers (such as `Access-Control-Allow-Origin`) to
   explicitly grant specific external origins permission to read their API responses.
2. **WebSockets:** WebSocket connections bypass standard SOP restrictions; servers validate the incoming `Origin` HTTP header
   manually during the initial handshake.
3. **`postMessage()` API:** Pages from different origins can safely send string or JSON messages back and forth if both
   frames explicitly listen for and validate the sender's origin.
