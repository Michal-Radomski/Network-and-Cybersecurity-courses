**Cross-Site Scripting (XSS)** occurs when a web application includes untrusted user input in its web pages without proper
validation or encoding. This allows attackers to inject malicious scripts (typically JavaScript) into pages viewed by other
users, executing code directly within the victim's browser session.

---

**Primary Types of XSS**

- **Stored (Persistent) XSS:** The malicious payload is permanently stored on the target server (e.g., in a database, comment
  section, or user profile field). Whenever a victim visits the affected page, the stored script automatically executes in
  their browser.
- **Reflected (Non-Persistent) XSS:** The payload is included as part of an HTTP request (e.g., in URL parameters or search
  forms) and reflected back in the immediate response. Attackers trick victims into clicking a crafted link containing the
  malicious script.
- **DOM-based XSS:** The attack occurs entirely in the client-side JavaScript code. The application reads data from an
  untrusted source (like `location.search` or `document.referrer`) and insecurely passes it to an execution sink (such as
  `innerHTML` or `eval()`) without server intervention.

---

**Security Impact & Attack Consequences**

- **Session Hijacking:** Stealing sensitive session tokens or cookies (if not marked with `HttpOnly`) to impersonate
  legitimate users.
- **Credential Theft:** Injecting fake login forms directly over valid page UI elements to phish for user passwords.
- **Keylogging & Actions:** Tracking victim keystrokes or performing actions on behalf of the user (e.g., transferring funds
  or modifying account settings).
- **Malware Delivery:** Redirecting users to external malicious sites hosting browser exploits.

---

**Prevention and Defense Strategies**

1. **Context-Aware Output Encoding:** Encode user input before rendering it in the DOM (converting characters like `<` to
   `&lt;` and `>` to `&gt;`).
2. **Content Security Policy (CSP):** Implement strict HTTP headers (`Content-Security-Policy`) to restrict where scripts can
   be loaded from and block inline script execution (`'unsafe-inline'`).
3. **Use Safe APIs & Frameworks:** Modern frameworks (React, Angular) automatically escape HTML by default. Avoid unsafe
   sinks such as `innerHTML`, `document.write()`, or `dangerouslySetInnerHTML`.
4. **Secure Cookies:** Store session identifiers in cookies with `HttpOnly` flags set, preventing JavaScript from reading
   them via `document.cookie`.
