Securing a React and Node.js application against Cross-Site Scripting (XSS) requires a defense-in-depth approach. While React
automatically escapes values rendered in JSX by default, vulnerabilities can still enter through unsafe props, unvalidated
links, SSR state hydration, or missing backend security headers.

---

### 1. Secure React Frontend Components

#### A. Sanitize HTML When Rendering Raw Content

Avoid using `dangerouslySetInnerHTML`. If you must render user-generated HTML (e.g., from a rich-text editor), sanitize it
using `dompurify` before passing it to the component.

```jsx
import DOMPurify from "dompurify";

// SECURE: Strips executable tags (<script>, onerror, onload)
function UserBio({ rawBio }) {
  const cleanBio = DOMPurify.sanitize(rawBio);
  return <div dangerouslySetInnerHTML={{ __html: cleanBio }} />;
}
```

#### B. Validate Links (`javascript:` URI Defense)

React does not automatically sanitize `href` attributes. Malicious users can pass `javascript:...` payloads into dynamic
links to execute arbitrary code when clicked.

```jsx
// SECURE: Enforce safe URL schemes (http / https)
function UserWebsite({ url }) {
  const isSafe = url && (url.startsWith("http://") || url.startsWith("https://"));

  return (
    <a href={isSafe ? url : "#"} target="_blank" rel="noopener noreferrer">
      Visit Profile
    </a>
  );
}
```

### 2. Secure Node.js / Express Backend

#### A. Configure HTTP Security Headers with `helmet`

Use the `helmet` middleware in your Express app to set a strict **Content Security Policy (CSP)**. A CSP tells the browser
which script sources are allowed and blocks unauthorized inline JavaScript.

```javascript
const express = require("express");
const helmet = require("helmet");

const app = express();

// SECURE: Sets CSP, anti-clickjacking, and header restrictions
app.use(
  helmet.contentSecurityPolicy({
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'"], // Blocks inline scripts and external untrusted scripts
      styleSrc: ["'self'", "'unsafe-inline'"],
      imgSrc: ["'self'", "data:", "https:"],
      connectSrc: ["'self'", "https://api.yourdomain.com"],
    },
  })
);
```

#### B. Protect Cookies with `HttpOnly` Flags

Store session tokens or JWTs inside `HttpOnly` cookies rather than `localStorage` or `sessionStorage`. Even if an XSS attack
occurs, scripts running in the DOM cannot access `HttpOnly` cookies via `document.cookie`.

```javascript
// SECURE: Express cookie configuration for authentication tokens
res.cookie("token", jwtToken, {
  httpOnly: true, // Prevents access via client-side JavaScript
  secure: process.env.NODE_ENV === "production", // Requires HTTPS
  sameSite: "strict", // Protects against CSRF
  maxAge: 3600000,
});
```

#### C. Escape Initial State in Server-Side Rendering (SSR)

If using Next.js or custom Node.js SSR, passing global state to the window object using `JSON.stringify()` creates an XSS
vector if state values contain `</script>` tags. Use `serialize-javascript` instead.

```javascript
const serialize = require("serialize-javascript");

// SECURE: Safely serializes objects and escapes HTML/script characters
const html = `
  <script>
    window.__INITIAL_STATE__ = ${serialize(initialState, { isJSON: true })};
  </script>
`;
```

### 3. Input Validation & Defense Matrix

| Vulnerability Location  | Risk Point                      | Primary Remediation                         |
| ----------------------- | ------------------------------- | ------------------------------------------- |
| **React JSX Rendering** | Standard strings                | React automatically escapes HTML entities   |
| **Rich Text / HTML**    | `dangerouslySetInnerHTML`       | Sanitize with `dompurify`                   |
| **Dynamic Links**       | `<a href={userUrl}>`            | Validate for `http:` / `https:` prefixes    |
| **Node.js Responses**   | Missing security headers        | Enforce CSP using `helmet` middleware       |
| **Auth Credentials**    | Client storage (`localStorage`) | Store tokens in `HttpOnly` cookies          |
| **SSR Hydration**       | `JSON.stringify(state)`         | Serialize state with `serialize-javascript` |
