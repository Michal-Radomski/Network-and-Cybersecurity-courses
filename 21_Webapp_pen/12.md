Insecure deserialization occurs when an application converts untrusted or tampered data back into complex objects or runtime
structures without proper validation or filtering. While serialization turns objects into strings or byte streams for storage
or transmission, insecure deserialization can allow attackers to manipulate the resulting data structure or execute arbitrary
code.

---

### Insecure Deserialization in JavaScript & Node.js

#### 1. Why Native JSON is Safe (and Where the Risks Lie)

- **Native JSON (`JSON.parse()`):** In JavaScript and Node.js, standard JSON parsing is generally safe against code execution
  because `JSON.parse()` only processes data types (strings, numbers, booleans, arrays, objects). It does not evaluate
  executable code or functions.
- **The Risk in Third-Party Libraries:** Vulnerabilities usually arise when developers use non-standard serialization formats
  or insecure third-party libraries (such as older versions of packages like `node-serialize`) that attempt to serialize and
  deserialize full JavaScript functions or objects containing closures.

#### 2. How the Vulnerability Works (Code Execution via IIFE)

Historically, insecure deserialization libraries in Node.js allowed objects to include Immediately Invoked Function
Expressions (IIFEs).

- **The Issue:** When the untrusted payload was passed to an unsafe deserialization function, the library would evaluate the
  embedded function string using mechanisms like `eval()`.
- **The Impact:** If an attacker sends a crafted payload containing malicious code disguised as a serialized object, the
  Node.js server executes that code directly in the application's context, leading to **Remote Code Execution (RCE)**.

---

### Best Practices for Prevention

- **Stick to Safe Parsers:** Always use built-in, native methods like `JSON.parse()` and `JSON.stringify()` for data
  exchange. Avoid legacy or unmaintained libraries that handle complex object deserialization or function serialization.
- **Never Use `eval()` on Untrusted Input:** Ensure that user-supplied data is never passed directly into `eval()`,
  `Function()`, or insecure deserialization functions.
- **Validate and Sanitize Inputs:** Treat all incoming data from APIs, cookies, and user requests as untrusted. Validate the
  schema and types of incoming data before processing it in your application logic.
