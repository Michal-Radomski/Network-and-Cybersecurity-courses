While both **buffer overflow** and **stack overflow** involve computer memory limits being breached, they are fundamentally
different problems—one is typically a severe security vulnerability, while the other is usually a programming bug.

---

### Buffer Overflow vs. Stack Overflow: The Difference

- **Buffer Overflow:**
- **What it is:** Writing _more_ data into a memory buffer than it was designed to hold, causing the excess data to spill
  over into adjacent memory spaces.
- **Nature:** Primarily a **security vulnerability** (as discussed earlier) that attackers can exploit to manipulate program
  behavior or execute unauthorized code.

- **Stack Overflow:**
- **What it is:** A specific type of error where the "call stack"—the memory area that tracks active function calls and local
  variables—grows larger than the space allocated for it.
- **Nature:** Usually a **software bug** caused by logic errors (like infinite recursion), which immediately crashes the
  program rather than posing a direct security exploit.

---

### What a Stack Overflow Looks Like in React / Node.js

Because JavaScript manages memory automatically, you won't encounter C-style security buffer overflows. However, **stack
overflows are very common** in JavaScript when writing recursive functions incorrectly.

When a function calls itself infinitely without a proper base case (an exit condition), the V8 engine adds a new frame to the
call stack for every single call until it runs out of allowed space.

#### 1. The Error Message

When this happens in Node.js or a React app, the application crashes or throws a distinct error in the console:

```text
RangeError: Maximum call stack size exceeded

```

#### 2. Example in Code

Here is a simple example of code that triggers a stack overflow in a React component or Node.js script:

```javascript
// Infinite recursion example
function causeOverflow() {
  causeOverflow(); // Calls itself endlessly without an exit condition
}

causeOverflow();
```

In a React application, this often happens by accident if a component triggers a state update inside the render phase or
inside a `useEffect` hook without proper dependency arrays, causing the component to endlessly re-render itself:

```jsx
function BadComponent() {
  const [count, setCount] = React.useState(0);

  // This triggers a re-render, which runs the function again infinitely
  setCount(count + 1);

  return <div>Count: {count}</div>;
}
```
