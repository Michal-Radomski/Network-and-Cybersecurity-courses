In cybersecurity, **black-box**, **white-box**, and **gray-box** refer to the different approaches or methodologies used
during security assessments, vulnerability testing, and penetration testing.

The primary difference between them is **how much knowledge or access the tester has** about the target system before testing
begins.

---

### 1. Black-Box Testing (External / Zero Knowledge)

- **What it is:** The tester has **no prior knowledge** of the system, source code, network architecture, or internal
  documentation. They act just like an external hacker attacking the organization from the outside.
- **How it works:** The tester must first perform reconnaissance and information gathering (such as scanning open ports,
  finding public-facing endpoints, or identifying login pages) before attempting to find vulnerabilities.
- **Pros:** Mimics a real-world cyberattack by an outsider with no internal advantage; uncovers flaws in external perimeters.
- **Cons:** Takes more time because a lot of effort is spent on initial discovery; may miss deep internal logic flaws if the
  external surface area is small.

---

### 2. White-Box Testing (Internal / Full Knowledge)

- **What it is:** The tester has **complete access** to the system's inner workings, including source code, architecture
  diagrams, database schemas, API documentation, and network credentials.
- **How it works:** Security analysts and automated tools analyze the codebase (often called Static Application Security
  Testing or SAST) and system configurations to pinpoint flaws directly in the logic or setup.
- **Pros:** Highly thorough; can uncover deep-seated vulnerabilities, logic errors, and hidden flaws that external black-box
  testing might never reach.
- **Cons:** Time-consuming to review massive codebases; does not simulate how an actual external attacker with zero initial
  knowledge would approach the system.

---

### 3. Gray-Box Testing (Partial Knowledge)

- **What it is:** A hybrid approach where the tester has **partial knowledge** or limited access to the system. For example,
  they might be given a standard user account, low-level network diagrams, or partial documentation, but no access to the
  source code or administrator credentials.
- **How it works:** The tester simulates an insider threat (such as an employee with limited rights) or a hacker who has
  managed to bypass the outer perimeter and gain a low-level foothold.
- **Pros:** Provides a realistic simulation of targeted attacks; more efficient than black-box testing because time isn't
  wasted on basic reconnaissance.
- **Cons:** May still miss certain deep-code vulnerabilities if critical parts of the architecture remain completely hidden.

---

### Quick Comparison Summary

| Testing Type  | Prior Knowledge          | Role Simulated               | Example Focus                                  |
| ------------- | ------------------------ | ---------------------------- | ---------------------------------------------- |
| **Black-Box** | None (Zero Knowledge)    | External Hacker              | Public web apps, firewalls, open ports         |
| **Gray-Box**  | Partial (Limited Access) | Authenticated User / Insider | User privilege escalation, API security        |
| **White-Box** | Complete (Full Access)   | Internal Auditor / Developer | Source code review, architectural design flaws |
