Automated vulnerability scanning refers to the use of specialized software tools to automatically inspect web applications,
APIs, and infrastructure for known security flaws, misconfigurations, and outdated components.

Instead of manually testing every single page or endpoint, security teams and developers use automated scanners to quickly
assess application security postures at scale.

---

### Types of Automated Scanners

#### 1. SAST (Static Application Security Testing)

- **What it does:** Analyzes the application's **source code**, bytecode, or binary files without running the program. It
  acts like a spell-checker or linter for security flaws.
- **When it's used:** Typically integrated early into the development pipeline (CI/CD) so developers can catch insecure
  coding practices before code is merged or deployed.

#### 2. DAST (Dynamic Application Security Testing)

- **What it does:** Tests the **running application** from the outside by sending simulated requests (such as malformed
  inputs or common attack payloads) and analyzing the responses.
- **When it's used:** Typically run against staging or pre-production environments to find runtime vulnerabilities like
  injection flaws, missing security headers, or authentication bypasses.

#### 3. SCA (Software Composition Analysis)

- **What it does:** Scans third-party libraries, packages, and dependencies (such as `node_modules` in a Node.js project)
  against databases of known vulnerabilities (like CVE databases).
- **When it's used:** Continuously monitored during development to alert teams when an installed package has a newly
  discovered security patch available.

---

### Benefits of Automated Scanners

- **Speed and Efficiency:** Scans can cover thousands of URLs, endpoints, and files in a fraction of the time a human tester
  would need.
- **Continuous Integration:** Automated tools can run automatically with every code commit or nightly build, ensuring new
  vulnerabilities are caught early.
- **Baseline Security:** Helps teams quickly identify low-hanging fruit and common misconfigurations before a formal security
  audit or penetration test.

---

### Limitations

- **False Positives and Negatives:** Automated scanners can sometimes flag secure code as vulnerable (false positives) or
  miss complex business logic flaws and authorization issues (false negatives).
- **Cannot Replace Human Context:** Scanners lack the human intuition needed to understand complex multi-step workflows or
  custom business logic, which is why they are best paired with manual code reviews and penetration testing.
