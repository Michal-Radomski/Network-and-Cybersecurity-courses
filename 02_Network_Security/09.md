# How to Build a Custom NAS Using OpenMediaVault

You can turn an old PC, mini PC, or custom-built computer into a NAS (Network Attached Storage) using OpenMediaVault (OMV).

A custom NAS can store files, back up computers and phones, stream media, host a private cloud, and share storage across your
home network.

The advantage is that you control the hardware, storage capacity, software, security, and upgrade path.

**My recommendation:** Build an x86 mini PC or small desktop with OpenMediaVault, a dedicated SSD for the operating system,
and one or more separate HDDs for your data.

The official [OpenMediaVault documentation](https://docs.openmediavault.org/en/8.x/) describes its web interface, storage
management, shared folders, and network file-sharing services. docs.openmediavault.org

## 1\. Choose your NAS architecture

There are three practical ways to build your own NAS.

### Option A: Repurpose an old PC

Best for a budget-friendly home NAS.

- CPU: An existing Intel or AMD processor.
- RAM: 4–8 GB.
- Operating system: Small SSD, preferably 64–128 GB or larger.
- Storage: One or more HDDs.
- Network: Gigabit Ethernet or faster.
- Software: OpenMediaVault.

Advantages:

- You can reuse existing hardware.
- Standard SATA drives are easy to install.
- You can add more storage if the motherboard and case support it.
- You can run file sharing, backups, and media services.

### Option B: Build a compact NAS using a mini PC

Best for a small, quiet, low-power NAS.

- Mini PC with an efficient processor.
- 8–16 GB RAM.
- SSD for OpenMediaVault.
- External storage enclosure or a separate multi-bay drive enclosure.
- Gigabit or 2.5 Gigabit Ethernet.

The main limitation is the number of internal drives. Many mini PCs have only one or two internal storage connections, so
plan the expansion path before buying.

### Option C: Build a custom multi-drive NAS

Best if you want something closer to a commercial NAS appliance.

- Small motherboard or mini-ITX motherboard.
- Intel or AMD processor.
- 8–32 GB RAM, depending on the workload.
- Dedicated SSD for the operating system.
- Two to six HDDs or more.
- A case with adequate drive bays and cooling.
- SATA ports or a compatible storage controller.
- 2.5 GbE or 10 GbE networking if needed.

This option gives you the most control over capacity, cooling, performance, and future expansion.

## 2\. Recommended hardware for your custom NAS

For a first build, I would use the following configuration.

| Component              | Recommended specification                               |
| ---------------------- | ------------------------------------------------------- |
| Processor              | Intel N100-class CPU or a suitable existing desktop CPU |
| RAM                    | 8 GB; 16 GB if running additional services              |
| Operating system drive | 120–256 GB SSD                                          |
| Data storage           | 2 × 4 TB or 2 × 8 TB HDDs                               |
| Network                | 1 GbE minimum; 2.5 GbE recommended for a new build      |
| Motherboard            | At least two SATA ports for a two-drive system          |
| Case                   | Small NAS case with adequate airflow                    |
| Power supply           | Reliable PSU sized for the system and drive spin-up     |
| Backup                 | External HDD or another backup destination              |

These are recommendations, not mandatory specifications. OpenMediaVault can run on less powerful hardware, and the right
setup depends on how many services you intend to run. Its official prerequisites recommend 8 GiB of RAM for a comfortable
basic setup. docs.openmediavault.org

### How much storage will you get?

Suppose you install two 4 TB hard drives.

| Storage configuration       | Approximate usable capacity                   | Drive-failure protection       |
| --------------------------- | --------------------------------------------- | ------------------------------ |
| Two independent disks       | 8 TB total                                    | No redundancy                  |
| RAID 1 mirror               | 4 TB                                          | Can tolerate one drive failure |
| Two-disk parity arrangement | Not applicable to a standard two-drive RAID 5 | —                              |

A mirrored pair keeps a copy of the data on each drive, so you can generally continue operating if either drive fails.

**Important:** RAID is not a backup. It does not protect you from accidental deletion, malware, theft, fire, or damage
affecting both drives.

For valuable files, maintain a separate backup.

# 3\. Install OpenMediaVault

OpenMediaVault is built on Debian Linux and provides a web interface for managing storage, users, and network shares. It
supports common file-sharing protocols such as SMB/CIFS and NFS. docs.openmediavault.org

## Step 1: Download the installer

Visit the official [OpenMediaVault installation page](https://www.openmediavault.org/install).

The current installation instructions describe OpenMediaVault 8 and provide a downloadable installer for compatible x86-64
hardware. openmediavault.org

You will need:

- A USB flash drive for the installer.
- A monitor and keyboard for the initial installation, if needed.
- An Ethernet cable.
- A dedicated SSD for the operating system.

**Warning:** Installing the operating system can erase the selected disk. Disconnect drives containing important data before
installation if you are unsure which disk is which.

## Step 2: Create the installation USB

1. Download the appropriate OpenMediaVault ISO.
2. Use a bootable USB creation tool.
3. Select the USB drive as the destination.
4. Write the ISO image to it.
5. Safely eject the USB drive.

## Step 3: Install the operating system

1. Connect the USB drive to your NAS.
2. Enter the computer's boot menu.
3. Boot from the USB drive.
4. Follow the installer instructions.
5. Select the dedicated SSD as the system disk.
6. Configure the network interface.
7. Complete the installation and reboot.

Keep the data drives disconnected during this step if possible, so you don't accidentally install the operating system on a
drive containing files you want to preserve.

The official installation guide explains the available installation methods. openmediavault.org

## Step 4: Find the NAS's IP address

After the NAS boots, determine its assigned IP address from the console or your router's DHCP client list.

For example:

text

```
NAS IP address: 192.168.1.50
```

This is only an example. Your actual address depends on your network.

Open a browser on another computer and visit:

text

```
http://192.168.1.50
```

Replace the example address with your NAS's actual IP address.

You should see the OpenMediaVault administration interface.

Sign in using the credentials configured during installation, then change any default or temporary passwords as appropriate.

### Give your NAS a stable IP address

You don't want the NAS's IP address changing unexpectedly.

You can either:

- Create a DHCP reservation on your router, or
- Configure a static IP through OpenMediaVault's network settings.

A DHCP reservation is often the simplest option for a home network.

For example:

text

```
NAS IP:       192.168.1.50
Router:       192.168.1.1
Subnet:       255.255.255.0
```

Make sure the chosen address matches your network and doesn't conflict with another device.

# 4\. Configure your storage drives

This is one of the most important parts of building a reliable NAS.

## Step 1: Install the HDDs

Connect your data drives to the motherboard using SATA cables and suitable power connectors.

For a two-drive NAS:

text

```
+----------------------------------+
|             NAS PC               |
|                                  |
|  SSD: OpenMediaVault             |
|                                  |
|  HDD 1: Main data storage        |
|                                  |
|  HDD 2: Additional storage       |
|         or mirror                |
|                                  |
+----------------------------------+
                  |
             Ethernet
                  |
               Router
                  |
          Computers / Phones
```

Once the system is running, check that both HDDs appear in OpenMediaVault's storage management interface.

## Step 2: Check drive health

Before using the disks:

- Check their model numbers and capacities.
- Inspect SMART health information where supported.
- Run the available drive self-tests.
- Check for concerning errors or bad sectors.
- Make sure the drives are suitable for your intended workload.

OpenMediaVault provides storage and disk-management features, although SMART visibility can depend on the drive connection
and controller. docs.openmediavault.org

## Step 3: Create a filesystem

In the OpenMediaVault interface:

1. Open **Storage → File Systems**.
2. Select the appropriate data drive or partition.
3. Create a filesystem if the disk is new and unformatted.
4. Choose a suitable filesystem, such as ext4, for a straightforward Linux NAS.
5. Apply the changes.
6. Mount the filesystem.

**Be careful:** Creating a filesystem generally destroys existing data on the selected partition. Do not format a disk that
contains files you want to preserve.

Repeat the process for other disks if you intend to use them independently.

## Step 4: Decide whether to use RAID

You have several options.

### Option A: Independent disks

Each drive stores its own files.

Advantages:

- Simple to configure.
- Easy to understand.
- A failed disk doesn't necessarily affect files on another independent disk.

Disadvantages:

- No automatic redundancy.
- You need a separate backup strategy.

### Option B: RAID 1 mirror

Two disks store mirrored data.

Advantages:

- Can keep the NAS running if one member drive fails.
- Straightforward capacity calculation.
- Useful for important files that need availability.

Disadvantages:

- Two 4 TB drives provide approximately 4 TB of usable capacity before filesystem overhead.
- A mirror doesn't protect against deletion or malware.
- Replacing a failed drive and rebuilding the mirror requires care.

### Option C: MergerFS and SnapRAID

For a NAS with several large HDDs, you can consider combining storage using MergerFS and protecting selected data using
SnapRAID.

This is useful for media libraries and other files that don't change constantly.

However, parity is not equivalent to real-time RAID redundancy. SnapRAID generally needs synchronization to incorporate
changes, so files changed since the last successful sync may not be recoverable from parity.

For a beginner, I recommend starting with independent disks or a supported RAID 1 configuration rather than introducing
several storage technologies at once.

# 5\. Create folders and share files over your network

Now you can turn the storage into a usable NAS.

For example, you might want these folders:

text

```
CustomNAS/
├── Documents/
├── Photos/
├── Videos/
├── Backups/
└── Shared/
```

Each folder can have its own permissions.

## Step 1: Create a shared folder

In the OpenMediaVault web interface:

1. Open **Storage → Shared Folders**.
2. Click **Create** or **Add**.
3. Enter a folder name, such as `Documents`.
4. Select the filesystem containing your data.
5. Enter the relative folder path.
6. Configure the initial permissions.
7. Save and apply the changes.

Repeat for `Photos`, `Videos`, and any other folders you need.

OpenMediaVault uses shared-folder definitions throughout its services, so the same folder can be made available through SMB,
NFS, and other supported services.
([Official shared-folder documentation](https://docs.openmediavault.org/en/8.x/administration/storage/sharedfolders.html))

## Step 2: Create a NAS user

Don't use administrator credentials for everyday file access.

Instead:

1. Open the user management section.
2. Create a user, such as `nasuser`.
3. Set a strong password.
4. Grant the user access to the appropriate shared folders.

You can create separate accounts for family members or different devices.

For example:

| User          | Documents   | Photos      | Backups     |
| ------------- | ----------- | ----------- | ----------- |
| Administrator | Full access | Full access | Full access |
| nasuser       | Read/write  | Read/write  | No access   |
| backupuser    | No access   | No access   | Read/write  |

These are example permissions. Configure the appropriate filesystem and share-level permissions for each user.

**Important:** OpenMediaVault applies access controls at multiple levels. A user needs sufficient permissions on both the
shared folder and the relevant file-sharing service.
([Shared-folder permissions](https://docs.openmediavault.org/en/8.x/administration/storage/sharedfolders.html))

## Step 3: Enable SMB/CIFS

SMB is the easiest way to access your NAS from Windows, macOS, and many Linux computers.

In OpenMediaVault:

1. Open **Services → SMB/CIFS**.
2. Enable the service.
3. Save and apply the configuration.
4. Open the Shares section.
5. Add the shared folders you want to expose.
6. Configure access and read-only settings.

See the official
[OpenMediaVault services documentation](https://docs.openmediavault.org/en/8.x/administration/services/index.html).

## Step 4: Connect from Windows

On a Windows computer connected to the same network:

1. Open File Explorer.
2. Enter your NAS address in the address bar.

For example:

text

```
\\192.168.1.50
```

3. Press Enter.
4. Sign in using the NAS username and password.
5. Open your shared folders.

To make the NAS easier to access, map a shared folder as a network drive.

For example:

text

```
\\192.168.1.50\Documents
```

You can assign it a drive letter such as `Z:`.

## Step 5: Connect from Linux or macOS

On macOS, open Finder and choose **Go → Connect to Server**.

Enter:

text

```
smb://192.168.1.50/Documents
```

On Linux, use your file manager's network location feature or mount the SMB share using your preferred method.

Replace the example IP address and share name with your actual settings.

# 6\. Add advanced NAS features

Once file sharing works, you can expand your NAS into a more complete home server.

## A. Private cloud storage

You can run a service such as Nextcloud to synchronize files between your computers and phones.

Features can include:

- File synchronization.
- Photo uploads from phones.
- Browser-based file access.
- Sharing links.
- Calendars and contacts.
- Multiple user accounts.

Nextcloud can run alongside OpenMediaVault, commonly through a supported container-based setup.

Keep in mind that self-hosting a cloud service requires additional configuration, maintenance, and security precautions.

## B. Media server

Install Jellyfin if you want to stream your own movies, music, and other media to compatible devices.

A typical setup looks like this:

text

```
       OpenMediaVault NAS
               |
         Media folders
               |
          Jellyfin
               |
       +-------+-------+
       |       |       |
      TV     Phone    PC
```

Jellyfin can scan your media folders and present them through its interface.

If you want real-time video transcoding, check whether your CPU or GPU supports the formats you need.

## C. Docker applications

You can host additional applications, including:

- Jellyfin.
- Nextcloud.
- Home Assistant.
- Download management tools.
- Monitoring dashboards.
- Other self-hosted applications.

OpenMediaVault recommends containerized applications as a way to reduce software conflicts with the operating system.
([OpenMediaVault plugin documentation](https://docs.openmediavault.org/en/8.x/))

Don't install a random collection of system packages directly into the NAS operating system. Keep the core system as close to
a supported configuration as possible.

## D. Automatic computer backups

You can configure your computers to back up files to your NAS.

Examples include:

- Windows File History or other backup software.
- macOS Time Machine, with appropriate SMB configuration.
- Linux backups using `rsync` or other backup software.
- Scheduled backups from a second NAS or external storage device.

OpenMediaVault also supports scheduled remote and local synchronization tasks through its Rsync functionality.
([Official Rsync documentation](https://docs.openmediavault.org/en/8.x/administration/services/rsync.html))

For important data, use versioned backups rather than relying solely on a simple mirror of the source files.

# 7\. Make the NAS secure and reliable

A NAS often contains your most important files, so security and recoverability matter as much as storage capacity.

I recommend the following checklist.

### Security

- Change default or temporary passwords.
- Use separate accounts for different users.
- Give each account only the permissions it needs.
- Keep OpenMediaVault and its applications updated.
- Use Ethernet instead of Wi-Fi where possible.
- Avoid exposing the administration interface directly to the internet.
- Don't forward SMB ports from your router to the internet.
- If you need remote access, use a properly configured VPN rather than exposing file-sharing services directly.

### Reliability

- Enable SMART monitoring where supported.
- Schedule disk health tests.
- Monitor available storage space.
- Keep the NAS well ventilated.
- Consider a UPS to handle power interruptions.
- Test your backups by restoring some files.
- Keep a copy of important data on a separate physical device or remote system.

A UPS can give the NAS time to shut down cleanly during a power failure, but it does not replace backups.

# 8\. My recommended custom NAS build

If I were building a practical home NAS from scratch, I would start with this design:

text

```
                 HOME NETWORK
                      |
                 Wi-Fi Router
                      |
                  2.5 GbE
                      |
          +------------------------+
          |      CUSTOM NAS        |
          |                        |
          |  OpenMediaVault        |
          |                        |
          |  Intel N100-class CPU  |
          |  16 GB RAM              |
          |  256 GB system SSD     |
          |                        |
          |  HDD 1: 8 TB            |
          |  HDD 2: 8 TB            |
          |                        |
          |  SMB / Backups         |
          |  Jellyfin (optional)   |
          |  Nextcloud (optional)  |
          +------------------------+
```

### How I would configure it

| Component       | My choice                                      |
| --------------- | ---------------------------------------------- |
| OS              | OpenMediaVault                                 |
| Processor       | Low-power Intel or AMD                         |
| RAM             | 16 GB                                          |
| OS drive        | Dedicated SSD                                  |
| Data drives     | Two NAS-suitable HDDs                          |
| Filesystem      | ext4 for a straightforward initial setup       |
| Storage layout  | RAID 1 if availability is important            |
| Network         | 2.5 GbE if the rest of the network supports it |
| File sharing    | SMB/CIFS                                       |
| Media streaming | Jellyfin, if needed                            |
| Private cloud   | Nextcloud, if needed                           |
| Backups         | Separate external drive or another NAS         |

The exact hardware should depend on the number of drives, desired capacity, power consumption, and whether you need media
transcoding or other applications.

One final distinction: if your main goal is to store files, you don't need a powerful processor. If you also want video
transcoding, virtual machines, or many self-hosted applications, spend more on the CPU and RAM.
