You can build a **custom router and NAS using a single computer**. This is a great home-lab project because one machine can
manage your internet connection, Wi-Fi, firewall, file storage, backups, and even media streaming.

The main decision is how to run the router and NAS software together without compromising network security or storage
reliability.

**My recommendation:** Use a computer with two or more Ethernet ports, run a dedicated router such as OpenWrt or pfSense, and
run OpenMediaVault for storage. For the cleanest separation, use virtualization.

# 1\. What your combined router and NAS would look like

Here is the overall architecture:

```
                    INTERNET
                       |
                   ISP MODEM
                       |
                       | Ethernet
                       |
             +---------------------+
             |                     |
             |  YOUR CUSTOM PC     |
             |                     |
             |  Router Software    |
             |  OpenWrt / pfSense  |
             |                     |
             |  NAS Software       |
             |  OpenMediaVault     |
             |                     |
             |  HDDs / SSDs        |

                       |
                 Ethernet Switch
                   /         \
                  /           \
             Wi-Fi AP       Desktop PC
                  )))

```

One computer handles routing and storage, while a separate wireless access point provides Wi-Fi.

You can also use a Wi-Fi access point that connects to your router via Ethernet. This generally makes Wi-Fi configuration and
upgrades easier.

# 2\. Three ways to combine a router and NAS

There are three approaches, and the right choice depends on how much complexity you want.

## Option A: OpenWrt + OpenMediaVault on the same Linux installation

**Best for:** Experimentation and lightweight setups, if you're comfortable managing Linux services.

OpenWrt is primarily designed as a router operating system, while OpenMediaVault is built on Debian Linux.

You could theoretically configure Linux networking, routing, firewalling, and NAS services on one system. However, installing
OpenMediaVault directly into an OpenWrt installation is not a supported standard configuration.

Similarly, installing OpenWrt and OpenMediaVault side by side on one conventional installation isn't a straightforward
process.

I wouldn't recommend this approach for a beginner.

## Option B: Virtualize both systems on one computer ⭐

**Best for:** A flexible, powerful home lab.

Install a hypervisor on your computer, then run the router and NAS as separate virtual machines.

For example, you could use **Proxmox VE** as the virtualization platform.

- VM 1: OpenWrt or pfSense for routing and firewalling.
- VM 2: OpenMediaVault for storage and file sharing.
- Optional VM 3: Other applications, such as Jellyfin or Home Assistant.

Official project websites:

- [Proxmox VE](https://www.proxmox.com/en/products/proxmox-virtual-environment/overview?utm_source=chatgpt.com)
- [OpenWrt](https://openwrt.org/?utm_source=chatgpt.com)
- [pfSense](https://www.pfsense.org/?utm_source=chatgpt.com)
- [OpenMediaVault](https://www.openmediavault.org/?utm_source=chatgpt.com)

### Architecture

```
                 INTERNET
                     |
                  ISP MODEM
                     |
                  WAN NIC
                     |
       +----------------------------+
       |       PROXMOX VE            |
       |                             |
       |  +----------------------+   |
       |  | VM 1: OpenWrt        |   |
       |  | Router + Firewall    |   |
       |  +----------------------+   |
       |              |              |
       |           LAN NIC           |
       |              |              |
       |  +----------------------+   |
       |  | VM 2: OpenMediaVault  |   |
       |  | NAS + SMB + Backups   |   |

       |              |              |
       |          HDD Storage        |
       +-----------------------------+
                      |
                 LAN / Switch
                      |
                 Wi-Fi Access
                     Point
```

This is a conceptual diagram; the physical interfaces and virtual network bridges need to be configured carefully.

### Why I recommend this approach

- Router and NAS software stay separate.
- You can restart the NAS without deliberately restarting the router VM.
- You can allocate CPU and RAM independently.
- You can add more virtual machines later.
- You can snapshot supported virtual-machine configurations before making changes.
- You can pass physical storage devices or a dedicated storage controller through to the NAS VM.

However, **the router and NAS still depend on the same physical computer**. If the host crashes or needs to reboot, both
services may become unavailable.

Also, if the router VM fails, internet access stops until it recovers.

### Hardware requirements

For this setup, I'd recommend:

| Component      | Recommendation                                                        |
| -------------- | --------------------------------------------------------------------- |
| CPU            | Intel N100 for a light workload, or a more powerful Intel/AMD CPU     |
| RAM            | 16 GB minimum for a modest combined setup; 32 GB for more flexibility |
| System drive   | 256 GB SSD                                                            |
| NAS storage    | Two or more HDDs, depending on capacity requirements                  |
| Ethernet       | At least two physical interfaces; three can simplify the design       |
| Wi-Fi          | Separate access point                                                 |
| Virtualization | Proxmox VE                                                            |

An Intel N100 system can be suitable for a lightweight setup, but it may be restrictive if you add several applications or
require intensive media transcoding.

For a NAS with multiple drives, ensure the computer has enough SATA ports or a compatible storage controller.

# 3\. Option C: Use pfSense or OpenWrt as the main OS and run the NAS separately

You could also make the router the primary operating system and try to run NAS services alongside it.

However, pfSense is designed as a firewall and routing platform, not as a general-purpose NAS host. OpenWrt is similarly
focused on networking.

You would have to work around their intended system designs to run a full NAS stack.

For that reason, I would choose virtualization instead.

---

# 4\. How to connect the network interfaces

This is the most important part of a combined router/NAS build.

Ideally, your computer should have two dedicated physical Ethernet ports.

| Port       | Purpose                                |
| ---------- | -------------------------------------- |
| Ethernet 1 | WAN connection to the ISP modem or ONT |
| Ethernet 2 | LAN connection to your home network    |

A third port can be useful for dedicated management or a separate LAN segment, but it isn't always necessary.

### Example physical layout

text

```
ISP MODEM
    |
    | Ethernet
    |
[ NIC 1: WAN ]
    |
+--------------------------------+
|        ONE PHYSICAL PC         |
|                                |
|       Proxmox VE               |
|                                |
|   OpenWrt VM                   |
|   OpenMediaVault VM            |
|                                |
|   Dedicated NAS HDDs           |
+--------------------------------+
    |
[ NIC 2: LAN ]
    |
 Ethernet Switch
    |
 +--+-------------+
 |                |
Wi-Fi AP       Desktop PC
```

The router VM should control the WAN and LAN interfaces, with the LAN interface connected to the internal network bridge.

The NAS VM should connect to the LAN side, not directly to the WAN network.

**Security rule:** Never bridge the WAN interface into your ordinary home LAN or expose the NAS management interface directly
to the internet.

You should also keep a way to access the hypervisor's management interface if the router VM fails. A dedicated management
interface or carefully planned local console access can help.

# 5\. Can the same computer provide Wi-Fi?

Yes, but I recommend a separate access point.

There are three possible approaches:

- **Separate Wi-Fi access point:** The easiest and most reliable choice.
- **Compatible Wi-Fi adapter passed through to a router VM:** Possible with suitable hardware and drivers, but more
  complicated.
- **Wi-Fi hardware integrated into the motherboard:** May work, but compatibility with virtualization and router software
  varies.

A dedicated access point also lets you upgrade Wi-Fi without replacing your NAS hardware.

For example:

text

```
                 INTERNET
                     |
                CUSTOM PC
             +---------------+
             | OpenWrt       |
             | OpenMediaVault|
             | Proxmox       |
             +---------------+
                     |
                 2.5 GbE LAN
                     |
              Wi-Fi 6 Access
                   Point
                 )))   )))
               Phones  Laptops
```

If you want Wi-Fi 6 or Wi-Fi 7, choose the access point based on your coverage and speed requirements.

# 6\. How much storage and performance can you expect?

Your network speed, storage configuration, and hardware determine the results.

| Network | Theoretical maximum link speed | Practical considerations                                        |
| ------- | ------------------------------ | --------------------------------------------------------------- |
| 1 GbE   | 125 MB/s                       | Suitable for basic file storage and backups                     |
| 2.5 GbE | 312.5 MB/s                     | Better for large file transfers                                 |
| 10 GbE  | 1,250 MB/s                     | Useful for fast SSD storage or multiple high-throughput clients |

These are theoretical link-speed conversions before protocol overhead; actual file-transfer speeds will be lower.

A typical hard drive may not saturate a 2.5 GbE connection on its own, but multiple drives, caching, and faster storage can
make the additional bandwidth useful.

If you have a 1 Gbps internet connection, a capable modern CPU should generally handle ordinary routing and NAS duties
without difficulty, provided the configuration is appropriate.

# 7\. Important risks of combining everything into one PC

The combined design saves money and space, but it introduces a few trade-offs.

### A single point of failure

If the physical PC fails, both the router and NAS can stop working.

**Mitigation:** Keep external backups and maintain a recovery plan for the router configuration.

### Power consumption

The computer must remain on to provide routing and storage.

Choose efficient hardware, and consider the additional power consumed by multiple HDDs.

### Storage reliability

A mirrored pair of disks can help with availability, but it doesn't protect against every kind of data loss.

Keep separate backups.

### Maintenance and reboots

Updating or rebooting the hypervisor can temporarily interrupt internet access and NAS availability.

Schedule maintenance when interruptions are acceptable.

### Security

The router is exposed to the WAN, while the NAS holds your data.

Keep the services isolated through virtual networking, restrict administrative access, and avoid exposing NAS services
directly to the internet.

# 8\. My recommended build

For your project, I'd choose the following design:

**Hardware**

- One efficient mini PC or small desktop.
- 16–32 GB RAM.
- A 256 GB SSD for Proxmox and virtual-machine storage.
- Two NAS HDDs.
- At least two Ethernet ports, preferably 2.5 GbE.
- A separate Wi-Fi access point.

**Software**

- Proxmox VE as the host.
- OpenWrt as the router VM.
- OpenMediaVault as the NAS VM.
- Optional Jellyfin or other applications in separate containers or VMs.

**Network**

- WAN interface connected to the ISP modem.
- LAN interface connected to a switch.
- NAS connected only to the trusted LAN.
- Separate guest Wi-Fi if desired.

This provides a good balance of performance, flexibility, and manageability.
