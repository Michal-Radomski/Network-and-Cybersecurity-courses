# How to Build a Custom Wi-Fi Router Using pfSense or OpenWrt

You can build your own router with custom hardware and software, giving you much more control over your network than a
typical ISP router. You can configure your own firewall, Wi-Fi, VPN, VLANs, ad blocking, traffic monitoring, parental
controls, and more.

There are two main approaches:

- **Option 1: OpenWrt** — best if you want an all-in-one router with Wi-Fi, a web interface, and extensive customization.
- **Option 2: pfSense** — best if you want a powerful firewall and router, particularly for a home lab or advanced network.
  For Wi-Fi, you will usually want a separate wireless access point.
- **Option 3: pfSense or OpenWrt on custom hardware** — best if you want to build a router from scratch using a mini PC,
  Ethernet network cards, and Wi-Fi hardware.

**My recommendation:** If you want one custom device that handles routing and Wi-Fi, start with OpenWrt. If you want a more
powerful firewall with advanced network segmentation and VPN capabilities, consider pfSense with a dedicated Wi-Fi access
point.

Let's go through the hardware, setup, and configuration.

## 1\. Choose your router architecture

First, decide what kind of hardware you want to use.

### Option A: All-in-one OpenWrt router

**Architecture:**

text

```
            INTERNET
                |
          ISP Modem / ONT
                |
             WAN Port
                |
       +-------------------+
       |                   |
       |   OpenWrt Router  |
       |                   |
       |  Routing + NAT    |
       |  Firewall         |
       |  DHCP + DNS       |
       |  Wi-Fi 2.4 GHz    |
       |  Wi-Fi 5/6 GHz    |
       +-------------------+
           |          )))
        LAN Ports     Wi-Fi
           |            |
       PC / NAS      Phones /
       Switch        Laptops
```

OpenWrt runs routing, firewall, DHCP, and Wi-Fi on one device.

**Advantages:**

- Everything is controlled from one web interface.
- You can install additional software packages.
- It can support multiple Wi-Fi networks, VLANs, VPNs, and traffic-management features.
- You can use compatible commercial routers or purpose-built hardware.

**Best for:** A home router, a custom Wi-Fi access point, or a compact networking project.

See the official [OpenWrt documentation](https://openwrt.org/docs/start?utm_source=chatgpt.com) for installation and
configuration guides.

### Option B: pfSense firewall with a separate Wi-Fi access point

             |              |
             |   pfSense    |

In this setup, pfSense handles routing, firewall rules, VPNs, and network segmentation. A separate access point provides

# 2\. Hardware needed to build your own router

You have three main hardware choices.

## Choice 1: Repurpose an old router

This is the easiest and cheapest way to get started with OpenWrt.

You need:

- An existing router supported by OpenWrt.
- Its power adapter.
- An Ethernet cable.
- A computer for the initial installation.

Before installing OpenWrt, check the exact router model and hardware revision.

Use the official [OpenWrt Table of Hardware](https://openwrt.org/supported_devices?utm_source=chatgpt.com) to verify
compatibility.

**Important:** Don't buy an old router simply because it supports OpenWrt. Devices with only 8 MB of flash and 64 MB of RAM
are unsuitable for a modern, secure installation. Prefer hardware with more storage and memory. OpenWrt

## Choice 2: Build a router using a mini PC

This is my preferred option if you want to experiment with custom networking hardware.

### Recommended components

| Component | Recommendation                                              |
| --------- | ----------------------------------------------------------- |
| CPU       | Modern, low-power Intel or AMD processor                    |
| RAM       | 4–8 GB for a basic router; more for additional services     |
| Storage   | 32–128 GB SSD                                               |
| Ethernet  | At least two Ethernet ports                                 |
| Wi-Fi     | Separate access point, or supported internal Wi-Fi hardware |
| Power     | Reliable power adapter                                      |
| Cooling   | Passive or low-noise active cooling                         |

These are practical starting specifications rather than minimum requirements.

For example, you could use a small x86 mini PC with two Ethernet ports, install OpenWrt or pfSense, and connect a Wi-Fi
access point to its LAN port.

For pfSense, verify that the hardware and network adapters are supported. Netgate recommends Intel network adapters for many
home-built installations and advises against relying on USB Ethernet adapters. Netgate Documentation

You can even use a dedicated managed Ethernet switch to support multiple LAN ports and VLANs.

## Choice 3: Build an OpenWrt device from scratch

If your goal is to create a compact, integrated router rather than repurpose a PC, use a supported embedded networking
platform.

You will need:

- A supported system-on-chip (SoC) or development board.
- Ethernet interfaces.
- Compatible Wi-Fi hardware.
- Flash storage and RAM.
- Power regulation.
- Antennas and appropriate radio-frequency hardware.
- An enclosure.

For this route, check the supported hardware list before purchasing components.

The [OpenWrt hardware documentation](https://openwrt.org/supported_devices?utm_source=chatgpt.com) is the best starting
point.

Building a router board from scratch is more difficult because Wi-Fi driver support, antenna design, heat dissipation, and
regulatory requirements all matter.

# 3\. Method A: Install OpenWrt and configure Wi-Fi

Let's start with the easiest software approach.

## Step 1: Check hardware compatibility

If you already own a router:

1. Find its exact model number.
2. Check the hardware revision printed on the label.
3. Look it up in the OpenWrt hardware database.
4. Confirm that a suitable firmware image exists.
5. Read the installation instructions for that exact model.

Start here: [OpenWrt Supported Devices](https://openwrt.org/supported_devices?utm_source=chatgpt.com).

**Warning:** Installing an image for the wrong device or hardware revision can render a router unusable.

## Step 2: Download OpenWrt

Go to the official [OpenWrt downloads page](https://downloads.openwrt.org/?utm_source=chatgpt.com).

Select the correct image for your hardware.

There are different image types depending on whether you're installing OpenWrt for the first time or upgrading an existing
installation.

Follow the device-specific instructions rather than choosing an image based on its filename alone.

## Step 3: Install the firmware

For a supported commercial router, the process commonly looks like this:

1. Connect your computer to a LAN port.
2. Open the existing router's administration interface.
3. Upload the appropriate OpenWrt installation image if the device supports this method.
4. Wait for the firmware installation and reboot to complete.
5. Connect to the new router interface.

Some devices require a recovery mode, a bootloader interface, or another installation method.

Do not disconnect the power while firmware is being written.

## Step 4: Access the OpenWrt interface

Once OpenWrt starts, connect your computer to the router's LAN port.

The default management address on a standard OpenWrt installation is commonly:

text

```
192.168.1.1
```

Open the address in your browser:

[OpenWrt documentation](https://openwrt.org/docs/start?utm_source=chatgpt.com)

Depending on the device and installation, you may need to set a password or configure your computer's network connection
first.

If your existing router also uses `192.168.1.1`, disconnect it from the new router during initial setup to avoid address
conflicts.

## Step 5: Configure the WAN connection

Your WAN interface connects to the ISP modem or optical network terminal (ONT).

The connection method depends on your ISP.

Common options include:

- **DHCP:** The ISP automatically assigns an IP address.
- **PPPoE:** You enter the ISP-provided username and password.
- **Static IP:** You enter the assigned address, gateway, and other required settings.
- **VLAN tagging:** Some ISPs require a particular VLAN ID on the internet connection.

In OpenWrt's web interface, locate the WAN interface and configure the connection type required by your ISP.

If your ISP uses PPPoE or VLAN tagging, obtain the necessary settings before replacing your existing router.

## Step 6: Configure your LAN

For a simple home network, use the following example:

| Setting       | Value                             |
| ------------- | --------------------------------- |
| Router LAN IP | `192.168.10.1`                    |
| Subnet mask   | `255.255.255.0`                   |
| DHCP server   | Enabled                           |
| DHCP pool     | `192.168.10.100`–`192.168.10.250` |
| DNS           | Router or your preferred resolver |

These values are examples; you can use a different private subnet.

In OpenWrt, the LAN interface handles communication between wired clients and the router. The DHCP server automatically
assigns IP addresses to clients.

Make sure your LAN subnet doesn't overlap with the network used by an upstream router.

## Step 7: Configure Wi-Fi

Open the wireless settings in OpenWrt.

Create your primary wireless network with settings like these:

| Setting  | Example                                           |
| -------- | ------------------------------------------------- |
| SSID     | `MyCustomWiFi`                                    |
| Security | WPA2-AES or WPA3, depending on compatibility      |
| Password | A long, unique passphrase                         |
| Band     | 2.4 GHz and/or 5 GHz                              |
| Channel  | Automatic or a suitable manually selected channel |
| Country  | Poland, if that is your operating country         |

Use the correct regulatory country setting, and obey local frequency and transmit-power restrictions.

If your router supports both 2.4 GHz and 5 GHz, you can configure both bands. Whether 6 GHz is available depends on the
hardware, drivers, and regulatory requirements.

For a detailed guide, use the official [OpenWrt Wi-Fi documentation](https://openwrt.org/docs/start?utm_source=chatgpt.com).

## Step 8: Add advanced features

Once the basic router works, you can extend it.

| Feature            | What it does                                          |
| ------------------ | ----------------------------------------------------- |
| VLANs              | Separates devices into logical networks               |
| Guest Wi-Fi        | Gives visitors restricted access                      |
| VPN client         | Routes selected traffic through a VPN                 |
| VPN server         | Provides secure remote access to your home network    |
| Ad blocking        | Blocks many advertising and tracking domains          |
| SQM                | Helps reduce latency caused by network congestion     |
| DNS filtering      | Blocks selected domains or categories                 |
| Traffic monitoring | Helps identify bandwidth usage                        |
| IPv6               | Provides IPv6 connectivity when supported by your ISP |

OpenWrt supports an extensive package system, so you can add capabilities without replacing the entire operating system.
OpenWrt+1

For a first project, I would start with a stable internet connection, secure Wi-Fi, automatic updates where appropriate, and
a backup of the configuration before adding more packages.

# 4\. Method B: Install pfSense on a mini PC

If you choose pfSense, the general setup is slightly different.

## Step 1: Prepare the hardware

You need a computer with compatible x86-64 hardware, sufficient RAM and storage, and at least two usable network interfaces.

One interface connects to the internet, and the other connects to your internal network.

Check the official
[pfSense hardware requirements and selection guide](https://docs.netgate.com/pfsense/en/latest/hardware/?utm_source=chatgpt.com)
before buying hardware.

## Step 2: Download and install pfSense

1. Obtain the installer from the official [pfSense website](https://www.pfsense.org/getting-started/?utm_source=chatgpt.com).
2. Create the installation media following the official instructions.
3. Boot the mini PC from that media.
4. Install pfSense on the target drive.
5. Reboot into the installed system.
6. Assign the physical network interfaces.

You will need to identify which interface is WAN and which is LAN.

## Step 3: Configure the interfaces

A typical arrangement is:

| Interface | Connection       | Example configuration         |
| --------- | ---------------- | ----------------------------- |
| WAN       | ISP modem or ONT | DHCP or ISP-specific settings |
| LAN       | Internal switch  | `192.168.10.1/24`             |

Configure the WAN connection according to your ISP's requirements.

On LAN, enable the DHCP server if you want pfSense to assign IP addresses automatically.

## Step 4: Access the web interface

Connect a computer to the LAN interface.

Open the configured LAN address in a browser and sign in to the web interface.

The initial setup wizard will guide you through the basic network settings.

For a detailed walkthrough, use the official
[pfSense documentation](https://docs.netgate.com/pfsense/en/latest/?utm_source=chatgpt.com).

## Step 5: Add a Wi-Fi access point

This is the important difference between pfSense and OpenWrt.

**For most pfSense builds, use a separate Wi-Fi access point instead of trying to make the mini PC itself broadcast Wi-Fi.**

Connect the access point to the LAN network.

Configure it with:

- A management IP address, such as `192.168.10.2`.
- DHCP disabled on the access point if pfSense is providing DHCP for that network.
- A secure wireless network name and password.
- A connection from its LAN or designated uplink port to the appropriate LAN switch or pfSense LAN interface.

Make sure the access point's management address doesn't conflict with another device.

This configuration lets pfSense manage routing and firewall policies while the access point handles wireless connections.
Netgate documents this approach in its guide to
[using external wireless access points](https://docs.netgate.com/pfsense/en/latest/recipes/external-wireless-router.html?utm_source=chatgpt.com).

### Can pfSense broadcast Wi-Fi directly?

It can work with certain compatible wireless adapters and drivers, but compatibility is more limited than with dedicated
access points or OpenWrt routers.

Netgate discusses the limitations in its official guide,
[Should pfSense act as an access point?](https://docs.netgate.com/pfsense/en/latest/wireless/suitability.html?utm_source=chatgpt.com).

For a new project, I would not choose pfSense specifically to build a single-box Wi-Fi router.

# 5\. Make your custom router more advanced

Once the basic setup is working, you can build a more sophisticated network.

Here is an example of what a customized home network could look like:

text

```
                       INTERNET
                           |
                     Custom Router
                   OpenWrt / pfSense
                           |
                     Managed Switch
                           |
           +---------------+---------------+
           |               |               |
       VLAN 10          VLAN 20          VLAN 30
        Trusted           IoT             Guest
           |               |               |
       Computers         Cameras         Visitors
       Phones            Smart TV        Guest Wi-Fi
       NAS               Smart devices
```

You could configure the networks as follows:

| Network    | Example subnet    | Access policy                                         |
| ---------- | ----------------- | ----------------------------------------------------- |
| Trusted    | `192.168.10.0/24` | Normal internet and LAN access                        |
| IoT        | `192.168.20.0/24` | Internet access; restricted access to trusted devices |
| Guest      | `192.168.30.0/24` | Internet only                                         |
| Management | `192.168.40.0/24` | Restricted administrative access                      |

These are example subnets, not mandatory settings.

To implement this design, you need VLAN-aware networking equipment and matching firewall rules. The access point must also
support the required VLAN configuration if it carries multiple wireless networks.

**Important:** Creating separate subnets does not automatically isolate them. Configure firewall rules to restrict unwanted
traffic between the networks.

For example, guest clients should normally be able to reach the internet but not your NAS, personal computers, or router
administration interface.

You can build these policies in either OpenWrt or pfSense.

# 6\. Which option should you choose?

Here is my practical comparison.

| Feature                         | OpenWrt router                           | pfSense + Wi-Fi AP                              |
| ------------------------------- | ---------------------------------------- | ----------------------------------------------- |
| Wi-Fi built in                  | Yes, on compatible hardware              | Usually handled by a separate AP                |
| Hardware                        | Embedded router or compatible x86 system | Compatible x86-64 system or supported appliance |
| Routing and NAT                 | Yes                                      | Yes                                             |
| Firewall                        | Yes                                      | Yes                                             |
| VLANs                           | Yes                                      | Yes                                             |
| VPN                             | Yes                                      | Yes                                             |
| Package ecosystem               | Linux-based packages                     | Firewall-oriented packages                      |
| Customization                   | Excellent                                | Excellent                                       |
| Low-power embedded hardware     | Excellent                                | Generally less suitable                         |
| Advanced firewall configuration | Good                                     | Excellent                                       |
| Best use case                   | Custom all-in-one router                 | Dedicated firewall and router                   |

OpenWrt is a Linux-based distribution designed for networking devices, whereas pfSense is a firewall and routing platform
based on FreeBSD. Their hardware requirements and wireless capabilities differ. OpenWrt+2

## My recommendation

I would choose one of these two builds:

**Build A — Custom all-in-one Wi-Fi router**

- OpenWrt-compatible router hardware.
- Built-in dual-band Wi-Fi.
- Gigabit or faster Ethernet.
- Guest network and VLAN support.
- VPN and DNS filtering as needed.

**Build B — Powerful home-lab router**

- Mini PC with at least two compatible Ethernet ports.
- pfSense installed on the mini PC.
- Separate Wi-Fi 6 or Wi-Fi 7 access point.
- Managed switch for VLANs.
- Separate trusted, guest, and IoT networks.

Build A is simpler and more compact. Build B is more flexible if you want to learn advanced firewalling and networking.
