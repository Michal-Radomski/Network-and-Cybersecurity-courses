# What Is Plug and Play in Routers, and Why Can It Be Dangerous?

**Plug and Play (PnP)** means a device or service can automatically detect, configure, and connect to other devices with
little or no manual setup.

In networking, however, the term can refer to several different technologies. Some are harmless conveniences, while others
can introduce serious security risks.

For example, you might connect a new device to your home network and have it automatically configure its network settings,
discover other devices, or request that your router open a port to the internet.

The important distinction is that **automatic configuration isn't inherently dangerous; the danger comes from what a device
is allowed to configure or access automatically.**

Let's look at the main types, how attackers can abuse them, and how to secure a custom router running OpenWrt or pfSense.

## 1\. Different types of Plug and Play in routers

The term PnP is sometimes used loosely to describe several different networking technologies.

| Technology                     | Purpose                                                                    | Potential risk                                                         |
| ------------------------------ | -------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| DHCP                           | Automatically assigns IP addresses to devices                              | A malicious DHCP server can provide incorrect network settings         |
| UPnP IGD                       | Allows applications to request router port mappings                        | Can expose internal services to the internet                           |
| NAT-PMP                        | Allows devices to request NAT port mappings                                | Can unintentionally expose services                                    |
| PCP                            | Allows devices to request network address and port mappings                | Misconfigured access controls can expose services                      |
| SSDP                           | Discovers UPnP-compatible devices and services                             | Can reveal information or facilitate attacks on poorly secured devices |
| Universal Plug and Play (UPnP) | A collection of protocols for automatic device discovery and configuration | Excessive trust in local devices can create security vulnerabilities   |

The most important one to understand for home routers is **UPnP Internet Gateway Device (UPnP IGD)**.

## 2\. Why UPnP can be dangerous

Imagine you've built a custom router using OpenWrt, and you've connected your computers, phones, smart TV, and NAS to it.

Normally, your router's firewall blocks unsolicited incoming connections from the internet. UPnP can allow devices inside
your network to request exceptions to those rules.

### Example: A device automatically opens a port

Suppose you have this network:

text

```
                  INTERNET
                      |
                +-----------+
                |  ROUTER   |
                | Firewall  |
                +-----------+
                      |
                HOME NETWORK
                      |
           +----------+----------+
           |          |          |
         Laptop      NAS       Smart TV
```

Without UPnP, if an application on your laptop needs incoming connections from the internet, you generally have to configure
a port-forwarding rule manually.

With UPnP enabled, the application may ask the router to create that rule automatically.

For example:

text

```
Application starts
        |
        v
Requests a port mapping
        |
        v
Router accepts the request
        |
        v
Firewall permits incoming traffic
        |
        v
A service becomes reachable from outside
```

The problem is that UPnP IGD generally doesn't authenticate local applications before allowing them to request port mappings.
If malware runs on a device inside your network, it may be able to use UPnP to expose a service to the internet. OpenWrt+1

### Five important security risks

**1\. Malware can expose internal services**

Suppose your computer gets infected with malware. If UPnP is available, the malware may request a port mapping that makes a
service on your computer reachable from outside your network.

That could give an attacker another way to access the compromised device.

**2\. Your NAS could become exposed**

This is especially important for your custom NAS project.

Imagine that your NAS contains:

- Personal photos.
- Documents.
- Computer backups.
- Private files.
- Media libraries.

If a NAS application is vulnerable and its service becomes accessible from the internet, an attacker might be able to exploit
it.

UPnP does not automatically expose every NAS, but it can create an unwanted path into your network if a service requests a
mapping and the necessary conditions are met.

**3\. A compromised smart device could affect other devices**

An inexpensive smart camera, TV, or other IoT device might have outdated software or weak security.

If an attacker compromises that device, they may be able to abuse its access to local networking services, including UPnP, to
create additional exposure. The extent of the risk depends on the device, network configuration, and router implementation.
Canadian Centre for Cyber Security

**4\. An application can open a port without your knowledge**

You might never visit the router's administration interface or explicitly configure port forwarding.

An application can create a temporary mapping in the background. If you don't monitor the router's mappings, you may not
notice that a port has been opened.

**5\. Vulnerabilities in UPnP implementations can introduce additional risks**

UPnP software itself can contain bugs. Historically, vulnerabilities in UPnP implementations have allowed attackers to cause
crashes, expose information, or potentially execute code.

Keeping router firmware updated is therefore important, whether or not UPnP is enabled. D-Link+1

## 3\. Does UPnP mean someone can immediately hack your router?

**No. UPnP being enabled does not automatically mean your router has been compromised.**

The risk depends on several factors:

- Whether UPnP is accessible from the WAN or restricted to the LAN.
- Whether an attacker can compromise or connect a device inside your network.
- Whether a device is running a vulnerable service.
- Whether the router has vulnerabilities in its UPnP implementation.
- Whether the router enforces suitable access controls.

The most common concern is that a device already inside the network can request port mappings that expose services to the
internet.

Another risk is a router that incorrectly exposes its UPnP control interface on the WAN. A correctly configured router should
not allow arbitrary internet hosts to control its UPnP service.

The Canadian Centre for Cyber Security recommends disabling UPnP, especially on routers that protect home networks, unless
the feature is needed. Canadian Centre for Cyber Security

# 4\. Should you disable UPnP on your custom router?

For your planned custom router and NAS, **I recommend leaving UPnP disabled initially**.

You can enable it later if a specific application genuinely requires it.

Here's how to do that with the two router platforms we've discussed.

## A. Disable UPnP in OpenWrt

OpenWrt supports UPnP through its `miniupnpd` service.

### Using the web interface

1. Log in to the OpenWrt administration interface.
2. Navigate to **Services → UPnP**.
3. Find the option to enable or start the UPnP service.
4. Disable the service.
5. Click **Save & Apply**.
6. Check that no UPnP service is running and that no unwanted dynamic port mappings remain.

The precise menu labels can vary depending on your OpenWrt version and installed packages.

Official instructions:
[OpenWrt UPnP configuration guide](https://openwrt.org/docs/guide-user/firewall/upnp/upnp_setup?utm_source=chatgpt.com)

### Using the command line

If the `miniupnpd` configuration exists, you can disable the service with:

sh

```
uci set upnpd.config.enabled='0'
uci commit upnpd
/etc/init.d/miniupnpd stop
/etc/init.d/miniupnpd disable
```

This disables and stops the UPnP service managed by that configuration.

**Important:** Verify the configuration on your particular installation. Package versions and configuration structures can
differ, and NAT-PMP/PCP settings may need to be checked separately.

Disabling UPnP does not disable normal routing, DHCP, Wi-Fi, or internet access.

## B. Disable UPnP in pfSense

If you're using pfSense:

1. Log in to the pfSense web interface.
2. Navigate to **Services → UPnP IGD & PCP**.
3. Locate the service settings.
4. Disable the UPnP/PCP service.
5. Save and apply the changes.

Check the configuration to ensure that automatic port mapping is no longer enabled.

Official instructions:
[pfSense UPnP IGD and PCP documentation](https://docs.netgate.com/pfsense/en/latest/services/upnp.html?utm_source=chatgpt.com)

## 5\. What if a game or application needs UPnP?

Disabling UPnP can affect some applications, especially online games, peer-to-peer software, and certain communication
applications.

You have three options.

| Approach                               | Security                                 | Convenience                                    |
| -------------------------------------- | ---------------------------------------- | ---------------------------------------------- |
| UPnP disabled                          | Generally safer                          | Some applications may need extra configuration |
| UPnP with restricted devices and ports | Better controlled than unrestricted UPnP | Convenient for approved applications           |
| Manual port forwarding                 | Explicitly configured and predictable    | Requires understanding which ports are needed  |

Manual port forwarding is not automatically safe: opening an unnecessary port can expose a service just as easily as an
automatic mapping.

If an application needs incoming connections, first check whether it works without port forwarding. If it doesn't, configure
only the required ports and restrict access where possible.

pfSense supports access controls that can limit which internal devices are permitted to request mappings and which ports they
can use. Netgate Documentation

# 6\. What about DHCP? Is that dangerous too?

DHCP is another technology that automatically configures devices, but it serves a different purpose.

When your laptop connects to your home Wi-Fi, DHCP typically provides:

- An IP address.
- A subnet mask.
- A default gateway.
- DNS server information.

For example:

text

```
IP address:      192.168.10.100
Subnet mask:     255.255.255.0
Default gateway: 192.168.10.1
DNS server:      192.168.10.1
```

This is normal and necessary for most home networks.

However, a malicious DHCP server can provide incorrect network settings. A compromised device or unauthorized DHCP server
could potentially direct clients to an attacker-controlled gateway or DNS resolver.

**You generally want DHCP enabled on your router, but you should prevent unauthorized devices from acting as DHCP servers on
your network.**

For example, if you use OpenWrt as your router, let OpenWrt provide DHCP to your main LAN. If you add a separate access
point, disable its DHCP server when operating it as a simple access point.

# 7\. My recommended security configuration for your router and NAS

Since you're considering a custom router and NAS on one computer, I'd start with this setup:

text

```
                    INTERNET
                        |
                +----------------+
                | Custom Router  |
                | OpenWrt        |
                |                |
                | Firewall: ON   |
                | UPnP: OFF      |
                | DHCP: ON       |
                +----------------+
                        |
                 Trusted LAN
                        |
              +---------+---------+
              |                   |
        +-----------+       +-----------+
        | Computers |       | NAS       |
        | Phones    |       | OpenMedia |
        | Laptops   |       | Vault     |
        +-----------+       +-----------+
```

Use the following settings as your starting point:

| Feature               | Recommended setting                             |
| --------------------- | ----------------------------------------------- |
| Router firewall       | Enabled                                         |
| UPnP                  | Disabled initially                              |
| DHCP server           | Enabled on the main router                      |
| Router administration | LAN access only                                 |
| NAS administration    | Restricted to trusted devices                   |
| SMB file sharing      | LAN only; never expose directly to the internet |
| Remote NAS access     | VPN, if needed                                  |
| Router firmware       | Keep updated                                    |
| NAS backups           | Separate physical device or remote destination  |
| Guest Wi-Fi           | Isolated from the NAS and trusted LAN           |

As your network grows, consider putting smart-home devices on a separate VLAN and restricting their access to your NAS.

One important point: **if you run the router and NAS as virtual machines on the same computer, make sure the hypervisor's
network bridges and firewall rules preserve the same separation.** Disabling UPnP alone does not protect the NAS from every
threat.

---

## 8\. The bottom line

Plug and Play is a convenience, not inherently a vulnerability. However, **UPnP can be dangerous because it allows local
devices to request changes to the router's port-forwarding configuration, often without authentication**.

For a custom network:

- Keep DHCP enabled on your router.
- Disable UPnP unless you have a specific reason to use it.
- Restrict router and NAS administration to trusted devices.
- Don't expose NAS file-sharing ports directly to the internet.
- Keep the firmware updated.
- Use a VPN for secure remote access.
- Back up your NAS data independently.

**One final distinction:** UPnP is not the same as the router's ordinary Plug and Play behavior, and disabling UPnP will not
make your devices stop connecting automatically to Wi-Fi or receiving IP addresses.
