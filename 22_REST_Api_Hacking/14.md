## What is an Account Lockout Policy?

An **Account Lockout Policy** is a security mechanism where the system temporarily disables a specific _user account_ after a
set number of consecutive failed login attempts (e.g., 5 failed tries).

While **rate limiting** blocks traffic based on the _IP address_ (stopping a hacker from hammering the server), an **account
lockout** protects a specific user profile regardless of where the attacker is attacking from.

---

## How It Works in Practice

Typically, backend developers implement account lockouts by adding fields to the user's database record:

1. **`failedLoginAttempts`**: Tracks how many wrong passwords have been entered consecutively.
2. **`lockUntil`**: A timestamp indicating when the account lock expires.

### Conceptual Logic in Express.js:

```javascript
app.post("/api/login", async (req, res) => {
  const { username, password } = req.body;
  const user = await User.findOne({ username });

  // 1. Check if the account is currently locked
  if (user.lockUntil && user.lockUntil > Date.now()) {
    return res.status(423).json({ error: "Account is temporarily locked. Try again later or reset your password." });
  }

  // 2. Validate password
  const isMatch = await bcrypt.compare(password, user.password);
  if (!isMatch) {
    user.failedLoginAttempts += 1;

    // 3. Lock account if attempts exceed threshold (e.g., 5 failures)
    if (user.failedLoginAttempts >= 5) {
      user.lockUntil = Date.now() + 15 * 60 * 1000; // Lock for 15 minutes
    }
    await user.save();
    return res.status(401).json({ error: "Invalid username or password." });
  }

  // 4. Successful login: reset counters
  user.failedLoginAttempts = 0;
  user.lockUntil = null;
  await user.save();

  res.json({ message: "Login successful!" });
});
```

## The Catch: The Denial-of-Service Risk

While account lockouts protect against brute-force attacks, they introduce a vulnerability known as **Account Enumeration /
Denial of Service (DoS)**:

- If an attacker knows your username, they can intentionally fail 5 login attempts, instantly locking you out of your own
  account. If they repeat this, you might be permanently locked out.

### How to Mitigate This:

- **Time-Based Lockouts:** Instead of locking an account until an administrator unlocks it, automatically unlock it after a
  short period (e.g., 10 to 15 minutes).
- **Use CAPTCHAs:** Trigger a CAPTCHA challenge after 2 or 3 failed attempts rather than locking the account right away,
  ensuring a human is behind the keyboard.
- **Email Verification:** Require the user to click a secure link sent to their email to unlock the account instead of
  locking it automatically.
