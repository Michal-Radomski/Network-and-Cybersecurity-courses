## What is Broken Authentication in APIs?

**Broken Authentication** occurs when an API implements authentication and session management mechanisms incorrectly. This
flaw allows attackers to compromise passwords, API keys, or session tokens, letting them impersonate legitimate users and
gain unauthorized access to accounts or sensitive data.

APIs are particularly vulnerable because they are often automated, making it easy for attackers to script rapid login
attempts or exploit weak token validation across many endpoints at once.

---

## Common Causes of Broken Authentication

- **Lack of Rate Limiting:** Allowing unlimited login or password-reset attempts without throttling or temporary lockouts,
  enabling brute-force and credential-stuffing attacks.
- **Weak Password Policies:** Permitting simple, short, or commonly used passwords that are easily guessed or cracked.
- **Flawed Token Implementation:** Using weak algorithms to sign tokens, failing to check token expiration dates, or exposing
  tokens in public URLs.
- **Improper Logout/Session Invalidation:** Failing to properly invalidate tokens or sessions on the server side when a user
  logs out, leaving the token active for an attacker to reuse if intercepted.
- **Hardcoded or Default Credentials:** Leaving default API keys, admin credentials, or test tokens active in production
  environments.

---

## How to Prevent Broken Authentication

Securing API authentication requires a multi-layered approach:

1. **Implement Rate Limiting and Brute-Force Protection:** Restrict the number of failed login or token-request attempts from
   a single IP address or user account within a given timeframe.
2. **Enforce Multi-Factor Authentication (MFA):** Add an extra layer of security beyond just a username and password.
3. **Use Strong Token Management:** Follow best practices for JSON Web Tokens (JWTs) or OAuth 2.0, ensuring short expiration
   times, secure random signing keys, and proper server-side invalidation on logout.
4. **Enforce Strong Password Standards:** Require complex passwords and check them against lists of known breached passwords.
5. **Never Expose Secrets in URLs:** Always transmit credentials and tokens securely inside request headers (like the
   `Authorization` header) or encrypted request bodies, never via GET query parameters.
