Preventing common REST API vulnerabilities requires implementing defensive coding practices directly on your backend server.
Below are secure code examples using **Node.js and Express** to protect against some of the most frequent API flaws.

---

### 1. Preventing BOLA (Broken Object Level Authorization)

**The Fix:** Always verify on the server side that the currently authenticated user owns or has explicit permission to access
the requested resource ID.

```javascript
const express = require("express");
const router = express.Router();

// Example: Fetching a user profile securely
router.get("/api/users/:id", authenticateToken, async (req, res, next) => {
  try {
    const requestedId = req.params.id;
    const loggedInUser = req.user; // Attached by authentication middleware

    // Check if the logged-in user is requesting their own data (or is an admin)
    if (loggedInUser.id !== requestedId && !loggedInUser.isAdmin) {
      return res.status(403).json({ success: false, message: "Forbidden: Access denied." });
    }

    const user = await database.findUserById(requestedId);
    if (!user) {
      return res.status(404).json({ success: false, message: "User not found." });
    }

    res.json({ success: true, data: user });
  } catch (err) {
    next(err);
  }
});
```

### 2. Preventing Mass Assignment

**The Fix:** Never pass raw request bodies directly into database update queries. Instead, explicitly pick or whitelist
allowed fields.

```javascript
// Vulnerable approach: await User.update(req.params.id, req.body); -> Allows attackers to send {"isAdmin": true}

router.put("/api/users/profile", authenticateToken, async (req, res, next) => {
  try {
    const userId = req.user.id;

    // Explicitly destructure only allowed fields from req.body (Whitelisting)
    const { username, bio, avatarUrl } = req.body;

    const updatedData = { username, bio, avatarUrl };

    const updatedUser = await database.updateUser(userId, updatedData);
    res.json({ success: true, data: updatedUser });
  } catch (err) {
    next(err);
  }
});
```

### 3. Preventing Excessive Data Exposure

**The Fix:** Filter out sensitive properties (such as password hashes, internal roles, or billing details) before sending
database objects back to the client.

```javascript
router.get("/api/posts", async (req, res, next) => {
  try {
    const posts = await database.getAllPosts();

    // Map through posts and explicitly select only safe, necessary fields (DTO pattern)
    const sanitizedPosts = posts.map((post) => ({
      id: post.id,
      title: post.title,
      content: post.content,
      authorName: post.author.name,
      createdAt: post.createdAt,
      // Notice: passwordHash, internalNotes, and ipAddress are intentionally omitted
    }));

    res.json({ success: true, data: sanitizedPosts });
  } catch (err) {
    next(err);
  }
});
```
