API security testing involves evaluating REST (Representational State Transfer) APIs for vulnerabilities, misconfigurations,
and logic flaws. Because APIs serve as the communication backbone for modern web and mobile applications, securing them is
critical to protecting backend systems and user data.

---

### Common REST API Vulnerabilities

#### 1. BOLA (Broken Object Level Authorization)

- **The Issue:** APIs often accept IDs in requests (e.g., `/api/users/123/profile`) to fetch or modify data. If the backend
  fails to verify whether the logged-in user actually owns or has permission to access resource `123`, an attacker can simply
  change the ID number to view other users' data.
- **The Fix:** Always validate user permissions and session ownership on the server side for every request to sensitive
  resources.

#### 2. Broken Authentication

- **The Issue:** Weak implementation of authentication tokens (such as improperly configured JWTs) or missing rate limits on
  login/token endpoints allows attackers to crack credentials or forge valid tokens.
- **The Fix:** Use strong token signing, enforce short expiration times, and implement strict rate limiting to prevent
  brute-force attacks.

#### 3. Mass Assignment

- **The Issue:** Automatically binding incoming HTTP request data directly to internal database objects or models. If an
  attacker appends restricted fields (like `"isAdmin": true`) to a standard user update request, the backend might
  unintentionally save it.
- **The Fix:** Explicitly whitelist or filter which properties can be updated by users rather than accepting raw request
  objects.

#### 4. Excessive Data Exposure

- **The Issue:** The backend API returns full database objects (including sensitive fields like password hashes, internal
  flags, or PII) to the frontend, relying on the client-side UI to hide them.
- **The Fix:** Implement data transfer object (DTO) filtering or explicit serialization on the backend to return only the
  specific fields the client needs.

---

### Best Practices for Secure API Testing

- **Automated & Manual Testing:** Use tools like OWASP ZAP or Postman to test API endpoints, inspect request/response
  payloads, and verify that unauthorized requests are properly blocked with `401 Unauthorized` or `403 Forbidden` status
  codes.
- **Implement Rate Limiting:** Protect APIs from Denial of Service (DoS) and automated credential stuffing by limiting the
  number of requests a single IP or user can make within a given timeframe.
- **Input Validation:** Validate the data type, length, and format of all incoming parameters on every API endpoint before
  processing or querying databases.
