## What is the Lack of Rate Limiting Vulnerability?

The **Lack of Rate Limiting** (often associated with _Unrestricted Resource Consumption_) occurs when an API fails to
restrict how many times a user, IP address, or application can make requests within a specific timeframe.

Because APIs are designed to be automated and machine-readable, they are prime targets for automated scripts. Without proper
traffic controls, servers are left defenseless against floods of requests.

---

## Why It Is a Major Risk

When an API lacks rate limiting, it opens the door to several severe security attacks:

- **Brute-Force Attacks:** Attackers use automated scripts to try thousands of password combinations per second against a
  login endpoint until they guess the correct one.
- **Credential Stuffing:** Hackers take lists of leaked usernames and passwords from other data breaches and test them
  against your API to see if users reuse their credentials.
- **Denial of Service (DoS):** An attacker can flood an API endpoint with heavy requests (like searching a large database or
  uploading files), overwhelming server CPU, memory, and bandwidth, causing the service to crash for legitimate users.
- **Data Scraping:** Automated bots can rapidly pull massive amounts of data from endpoints—such as product pricing,
  inventory, or user profiles—in a short window.

---

## How to Remediate It

Protecting an API from this vulnerability requires a combination of throttling and monitoring:

1. **Implement Rate Limiting:** Use middleware (such as `express-rate-limit` in Node.js) to cap the number of requests a
   single IP address or user account can make within a set window (e.g., 100 requests per 15 minutes).
2. **Enforce Stricter Limits on Sensitive Routes:** Apply tighter restrictions to critical endpoints like login, password
   reset, and payment processing (e.g., allowing only 3 to 5 attempts per window).
3. **Set Payload and Size Limits:** Restrict the maximum size of incoming requests to prevent memory exhaustion attacks.
4. **Monitor and Alert:** Track traffic patterns using logging tools to spot sudden spikes or anomalous request behavior in
   real time.
