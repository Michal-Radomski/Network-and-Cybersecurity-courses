## Web Vulnerabilities in REST APIs

While REST APIs make building modern web and mobile applications seamless, they also inherit many traditional web
vulnerabilities—along with unique challenges specific to APIs. Because APIs expose direct communication channels to backend
data, securing them is critical.

---

## Key Vulnerabilities to Know

- **Broken Object Level Authorization (BOLA / IDOR):** Occurs when an API endpoint fails to verify if the logged-in user has
  permission to access a specific resource. For example, if a user changes the ID in `/api/users/123` to `/api/users/124`,
  they might view another user's private data.
- **Broken Authentication:** Weaknesses in how tokens, passwords, or API keys are handled allow attackers to compromise
  credentials and impersonate legitimate users.
- **Injection Flaws:** Just like traditional web apps, if user input is passed directly to a database or command line without
  sanitization, it can lead to SQL injection or other injection attacks.
- **Mass Assignment:** Happens when an API automatically binds client-supplied request parameters into internal object
  properties. If a user sends an extra field like `is_admin: true` during registration, the backend might blindly accept it
  and grant elevated privileges.
- **Excessive Data Exposure:** The API sends back entire database records to the client, relying entirely on the frontend to
  filter what the user should see, which leaves sensitive data exposed in the network response.

---

## Defensive Best Practices

- **Strict Authorization Checks:** Always validate user permissions on _every_ request, verifying that the user actually owns
  or has rights to the requested resource.
- **Input Validation & Sanitization:** Never trust data coming from the client; always validate types, lengths, and formats
  on the server side.
- **Use Strong Token-Based Auth:** Implement robust authentication standards like OAuth 2.0 and JSON Web Tokens (JWT) with
  proper expiration and signature verification.
