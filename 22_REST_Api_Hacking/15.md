## What is Multi-Factor Authentication (MFA)?

**Multi-Factor Authentication (MFA)** adds an extra layer of security beyond just a username and password. It requires the
user to provide two or more verification factors to gain access. Typically, this is a combination of:

1. **Something you know:** Your password.
2. **Something you have:** A time-based code generated by an app on your phone (like Google Authenticator, Authy, or
   Microsoft Authenticator) via **TOTP (Time-Based One-Time Password)**.

---

## How MFA Works in a REST API Flow

Adding MFA to an API usually splits the login process into **two steps**:

1. **Step 1 (Credential Check):** The user sends their username and password. If correct, instead of returning an access
   token immediately, the server responds with a temporary flag or token indicating: _"Password is correct, now provide your
   MFA code."_
2. **Step 2 (MFA Verification):** The client sends the 6-digit code from their authenticator app along with the temporary
   session identifier. If the code is valid, the server finally issues the full access token (like a JWT).

---

## Implementing TOTP MFA in Node.js / Express

In the JavaScript ecosystem, the most popular libraries for handling TOTP codes are **`speakeasy`** (for generating and
verifying codes) and **`qrcode`** (for generating the setup QR code).

### 1. Setup and Registration (Enabling MFA)

When a user wants to set up MFA, the server generates a unique secret key for them and turns it into a QR code that they can
scan with their phone.

```javascript
const speakeasy = require("speakeasy");
const QRCode = require("qrcode");

// Endpoint to generate MFA secret and QR code for a user
app.post("/api/mfa/setup", async (req, res) => {
  // 1. Generate a secret key for the user
  const secret = speakeasy.generateSecret({ name: "MyAwesomeApp" });

  // 2. Save secret.base32 in the database linked to the user (keep it secret!)
  // await User.updateOne({ username: req.user.username }, { mfaSecret: secret.base32 });

  // 3. Generate a QR code data URL for the user to scan
  QRCode.toDataURL(secret.otpauth_url, (err, dataUrl) => {
    if (err) return res.status(500).json({ error: "Error generating QR code" });

    // Send the QR code image and secret to the client
    res.json({
      secret: secret.base32,
      qrCodeUrl: dataUrl,
    });
  });
});
```

### 2. Verifying the Code (Login Step 2)

When logging in, the user provides the 6-digit code currently showing on their authenticator app. The server verifies it
using the secret stored in the database.

```javascript
app.post("/api/mfa/verify", (req, res) => {
  const { username, token } = req.body;

  // 1. Retrieve the user's saved mfaSecret from the database
  // const user = await User.findOne({ username });

  // 2. Verify the token provided by the user
  const verified = speakeasy.totp.verify({
    secret: userSecret,
    encoding: "base32",
    token: token,
    window: 1, // Allows a small time drift (30 seconds before/after)
  });

  if (verified) {
    // MFA is correct! Issue the actual JWT/Access Token
    // const accessToken = generateJwt(user);

  } else {
    res.status(401).json({ error: "Invalid MFA code. Please try again." });
  }
});
```

## Best Practices for API MFA

- **Provide Backup Recovery Codes:** Generate a set of one-time backup codes when the user first enables MFA. If they lose
  their phone, they can use a backup code to log in and reset their authenticator.
- **Enforce MFA for Sensitive Actions:** Even if MFA isn't required for regular login, mandate it for high-security actions
  like changing a password, updating billing info, or transferring funds.
