**DOM-Based Cross-Site Scripting (DOM XSS)** is an advanced form of XSS where the vulnerability exists entirely within the
client-side JavaScript rather than on the server.

In a traditional XSS attack, the malicious script comes from the backend server (via a database or a reflected HTTP
response). In a DOM XSS attack, the malicious data is processed by client-side scripts and written directly into the
browser's Document Object Model (DOM) in an unsafe way.

---

### How DOM XSS Works

DOM XSS involves three main components:

1. **The Source:** A JavaScript property that an attacker can control, such as `location.search` (URL parameters),
   `location.hash`, or `document.referrer`.
2. **The Sink:** A function or DOM element that allows JavaScript to be executed or HTML to be rendered, such as
   `element.innerHTML`, `document.write()`, or `eval()`.
3. **The Execution:** The client-side script takes data from the **source**, fails to sanitize it, and passes it directly
   into the **sink**, causing the browser to execute the untrusted code.

---

### Example Scenario

Imagine a webpage that reads a username from the URL fragment and displays a greeting:

```javascript
// Vulnerable code
const greetingDiv = document.getElementById("greeting");
const username = location.hash.substring(1); // Source

// SINK: Unsafely writing untrusted data directly into the DOM
greetingDiv.innerHTML = "Hello, " + username;
```

If a user visits a specially crafted URL containing HTML or JavaScript code in the hash fragment, the browser treats it as
part of the page content and executes it locally.

---

### Potential Impact

Because the vulnerability lives in the client-side code, it can lead to the same severe consequences as other forms of XSS:

- **Session Hijacking:** Stealing authentication tokens or cookies stored in the browser.
- **Keylogging:** Recording user keystrokes on the page.
- **Malicious Redirection:** Forcing the browser to navigate to an external site.

---

### How to Prevent DOM XSS

Preventing DOM XSS requires careful handling of data within client-side scripts:

1. **Avoid Unsafe Sinks:** Never use dangerous sinks like `innerHTML` or `document.write()` with untrusted input. Instead,
   use safe alternatives like `textContent` or `innerText`, which treat input strictly as text rather than executable markup.
2. **Sanitize Data:** If you must render HTML dynamically, use a dedicated client-side sanitization library (such as
   DOMPurify) to strip out dangerous tags and attributes before updating the DOM.
3. **Context-Aware Encoding:** Ensure that any data pulled from the browser environment (like the URL or local storage) is
   properly validated and encoded before being processed.
