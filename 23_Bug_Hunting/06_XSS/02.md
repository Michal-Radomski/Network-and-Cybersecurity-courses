**HTML Injection** (sometimes called Virtual Defacement) is a web application vulnerability that occurs when an application
takes untrusted user input and renders it directly into a webpage without proper sanitization or encoding.

Unlike **Cross-Site Scripting (XSS)**—which focuses on injecting executable scripts (like JavaScript)—HTML injection focuses
on injecting raw HTML tags (like `<div>`, `<a>`, or `<img>`) into the page's DOM.

---

### How HTML Injection Works

Imagine a simple comment section on a website. If the backend accepts user input and outputs it directly onto the page
without checking for HTML tags, a user could submit input containing HTML markup.

Instead of displaying the text literally, the browser interprets the injected tags as part of the webpage's structure,
altering how the page looks or behaves for anyone who views it.

---

### HTML Injection vs. XSS

- **HTML Injection:** Injects HTML tags and attributes. The goal is often to alter the visual appearance, create deceptive
  elements, or trick users.
- **Cross-Site Scripting (XSS):** A specific sub-type or evolution of HTML/script injection where the injected content
  includes executable code (like `<script>`) designed to steal cookies, hijack sessions, or run malicious functions. In fact,
  many HTML injection flaws can be upgraded to XSS if script execution is possible.

---

### Potential Impact

While it might sound less dangerous than executing backend commands, HTML injection can still cause significant harm:

- **Phishing & Spoofing:** Attackers can inject fake login forms or misleading notices onto a legitimate website to trick
  users into typing passwords or sensitive data.
- **Website Defacement:** Attackers can alter text, insert broken layouts, or display unauthorized images, damaging the
  credibility of the application.
- **Malicious Redirection:** Attackers can inject hidden or disguised links (`<a>`) that redirect unsuspecting visitors to
  external, malicious websites.

---

### How to Prevent HTML Injection

Preventing HTML injection relies on the same core defense principles used for XSS:

1. **Context-Aware Output Encoding:** Convert special HTML characters into their corresponding entities before rendering
   them. For example, convert `<` to `&lt;` and `>` to `&gt;`. This ensures the browser displays the input as plain text
   rather than processing it as code.
2. **Use Secure Frameworks:** Modern web frameworks (like React, Angular, or Vue) automatically escape HTML content by
   default when rendering data, drastically reducing the risk of injection vulnerabilities.
3. **Input Sanitization Libraries:** If your application legitimately needs to accept rich text (like a blog editor allowing
   bold text or links), use a trusted sanitization library (such as DOMPurify) to strip out dangerous tags and attributes
   while preserving safe ones.
