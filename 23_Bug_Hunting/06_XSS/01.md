**Cross-Site Scripting (XSS)** is a common web application security vulnerability that allows an attacker to inject malicious
scripts (usually written in JavaScript) into web pages viewed by other users.

Unlike command injection—which targets the server—XSS targets the **users** of a web application. When a vulnerable page
renders the malicious script, the script executes inside the victim's browser as if it were a legitimate part of the website.

---

### Main Types of XSS

1. **Stored (Persistent) XSS:** The malicious script is permanently saved ("stored") on the target server, typically in a
   database (e.g., in a comment section, forum post, or user profile). When other users visit that page, the server fetches
   the malicious script from the database and sends it to their browsers, affecting multiple people.
2. **Reflected (Non-Persistent) XSS:** The malicious script comes from the current HTTP request, often embedded in a
   specially crafted URL or form submission. The server "reflects" this input back immediately in the response page without
   properly sanitizing it, affecting the user who clicks the link.
3. **DOM-Based XSS:** The vulnerability exists entirely in the client-side JavaScript rather than the server-side code. The
   browser processes untrusted data from the DOM (Document Object Model) and unsafely updates the page content, causing the
   script to execute locally.

---

### Potential Impact

Because the script executes inside the context of the user's browser session, an attacker can achieve several things:

- **Session Hijacking:** Stealing session cookies or authorization tokens to impersonate the user and take over their
  account.
- **Data Theft:** Accessing sensitive information visible on the page.
- **Malicious Redirection:** Redirecting users to phishing sites or malicious downloads.

---

### How to Prevent XSS

Preventing XSS involves ensuring that user input is never treated as executable code by the browser:

1. **Context-Aware Output Encoding:** Before rendering user-supplied data on a webpage, convert special characters (like `<`,
   `>`, `&`, and quotes) into their corresponding HTML entities (e.g., converting `<` to `&lt;`). This tells the browser to
   display the input as plain text rather than executing it as code.
2. **Use Modern Frameworks:** Modern frontend frameworks like **React** automatically escape values embedded in JSX by
   default, protecting developers from many common XSS vulnerabilities.
3. **Content Security Policy (CSP):** Implement a strong CSP HTTP header. A CSP restricts where scripts can be loaded from
   and blocks unauthorized inline scripts, adding a powerful layer of defense-in-depth.
