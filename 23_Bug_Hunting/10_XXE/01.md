## What is XXE Injection?

XML External Entity (**XXE**) injection is a web security vulnerability that occurs when an application parses poorly
configured XML input. It allows an attacker to interfere with how an application processes XML data, often enabling them to
view files on the application server or interact with backend systems.

---

## How Does It Work?

- **XML Entities:** XML allows the definition of "entities," which are essentially variables used to define shortcuts or
  reference external data within an XML document.
- **External References:** A vulnerable XML parser can be tricked into loading external entities defined by an attacker.
- **The Exploit:** An attacker sends a crafted XML request containing a malicious external entity. When the server processes
  this XML, the parser fetches the specified resource (such as a sensitive system file or an internal network address) and
  includes it in the application's response.

---

## What is the Impact?

- **File Disclosure:** Attackers can read sensitive files stored on the server, such as configuration files, source code, or
  system files (e.g., `/etc/passwd` on Linux).
- **Server-Side Request Forgery (SSRF):** XXE can be used to force the vulnerable server to make requests to internal or
  external systems, potentially bypassing firewalls.
- **Denial of Service (DoS):** An attacker can define recursive entities (often called the "Billion Laughs" attack) that
  consume all server memory, crashing the application.

---

## How is it Prevented?

- **Disable DTDs:** The most effective defense is to completely disable Document Type Definitions (DTDs) and external entity
  resolution in the application's XML parser configuration.
- **Use Safer Formats:** Whenever possible, applications should use simpler data formats like JSON instead of XML to avoid
  parser vulnerabilities entirely.
