To prevent XML External Entity (XXE) vulnerabilities in a Node.js application, your defense strategy centers entirely on
**how you configure your XML parsing libraries**. Because Node.js core modules do not natively parse heavy XML documents
out-of-the-box, developers rely on third-party libraries (such as `libxmljs`, `xml2js`, or `xml2json`). If left on default
settings, some of these libraries can be prone to unsafe external entity handling.

---

## Key Prevention Steps

### 1. Secure Your XML Parser Configuration

Never parse untrusted XML using default parser settings. You must explicitly disable external entities, DTD (Document Type
Definition) loading, and entity expansion.

For example, if you are using libraries built on top of native bindings like `libxmljs` (or packages like `xml2json` that
utilize them), configure your parse options strictly:

```javascript
const xml2json = require("xml2json");

function secureParse(xmlString) {
  return xml2json.toJson(xmlString, {
    parseOptions: {
      noent: false, // Disables entity substitution/expansion
      dtdload: false, // Prevents loading external DTDs
      dtdattr: false, // Prohibits DTD attribute default values
      dtdvalid: false, // Disables validation against a DTD
      nonet: true, // Blocks network access for external entities
    },
  });
}
```

### 2. Validate and Sanitize Input

Before passing raw data to any parser, implement structural checks:

- **Reject DOCTYPE declarations:** If your application logic does not legitimately require DTDs, you can use a quick regex or
  string check to reject any incoming XML payload containing `<!DOCTYPE` or `<!ENTITY` tags.
- **Use Schema Validation (XSD):** Enforce strict schemas so that any unexpected tags, properties, or external references are
  automatically dropped before processing.

### 3. Switch to Safer Data Formats (JSON)

XML has a long history of complex parsing vulnerabilities. If your Node.js APIs or microservices communicate internally or
with modern frontends, transition entirely to **JSON**. JSON does not support document type definitions or external entities,
completely eliminating the risk of XXE.
