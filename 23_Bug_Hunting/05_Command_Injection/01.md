**Command Injection** is a critical software security vulnerability that allows an attacker to execute arbitrary operating
system commands on a server or host machine running an application.

This typically happens when a web application takes user-supplied input (such as form data, URL parameters, or file names)
and passes it directly to the system shell without proper validation or sanitization.

---

### How Command Injection Happens

Imagine a web application that allows users to test network connectivity by entering an IP address, which the backend then
passes to the server's operating system to run a standard tool like `ping`.

If the application is poorly written, it might directly combine the user's input into a system command string like this:

- **Underlying Command:** `ping <user_input>`

If an attacker enters a specially crafted input that includes command separators (such as `;`, `&&`, or `|`), they can trick
the operating system into running multiple commands instead of just the intended one. For example, instead of just pinging an
address, the system might accidentally execute additional commands appended by the attacker.

---

### Potential Impact

When a command injection vulnerability is successfully exploited, the consequences can be severe:

- **Unauthorized Access:** Attackers can read sensitive files, view environment variables, or access database credentials.
- **System Compromise:** Attackers can install malware, create new administrative user accounts, or completely take control
  of the server.
- **Lateral Movement:** Once inside one server, attackers may use it as a stepping stone to attack other systems on the same
  internal network.

---

### How to Prevent Command Injection

Developers can protect their applications by following secure coding practices:

1. **Avoid Using Shell Execution Functions:** Whenever possible, use built-in programming language features or safe libraries
   to accomplish tasks rather than calling out to the operating system shell.
2. **Use Parameterized APIs:** If you must interact with the OS, pass arguments as an array/list rather than a single
   concatenated string so the system treats them strictly as data, not executable code.
3. **Strict Input Validation (Allowlisting):** Use allowlists (e.g., checking if an IP address matches a strict regex
   pattern) to ensure user input only contains expected, safe characters.
