Command injection can allow an attacker to run arbitrary shell commands on the target Linux or Windows server when user input
is unsafely passed to a system shell. Examples include using command separators like ;, |, &, ||, or newlines to chain
unintended commands.

- Linux-specific danger examples:
  - Input that ends a legitimate command and appends another like: echo "user" ; cat /etc/shadow
  - Using backticks or $(...) to execute commands: ping "$(whoami)"
  - Injecting into a path or filename parameter that is then passed to a shell utility (e.g., /bin/mailx -s "subject"
    user@example.com; rm -rf /)

- Windows-specific danger examples:
  - Using & or | to chain commands in a parameter passed to cmd.exe, e.g.: dir C:\Users\Public & del
    C:\Windows\System32\config\sam
  - Injecting via powershell or cmd arguments: powershell -Command "Invoke-WebRequest ..."; Remove-Item "C:\temp\*"
  - Using && to run subsequent commands after a vulnerable executable parameter: someTool.exe "C:\path\to\file.txt" && del
    "C:\path\to\file.txt"

- Consequences: arbitrary command execution, data disclosure, privilege escalation, system compromise, lateral movement.

- Defenses (brief): input validation, least privilege, avoid composing shell commands from user input, use parameterized
  APIs, separate user input from command execution, run with non-privileged accounts, implement input sanitization and
  allowlists, use safe APIs (e.g., subprocess with arguments instead of shell), proper escaping/quoting, and robust logging.
