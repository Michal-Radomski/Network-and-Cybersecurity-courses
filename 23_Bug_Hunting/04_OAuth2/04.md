Implementing token-based stateless authentication using **JSON Web Tokens (JWT)** instead of session cookies means that your
Node.js backend will generate a signed token after a successful OAuth login and pass it to your React frontend. React then
stores this token and includes it in the `Authorization` header for subsequent API requests.

Here is how you can adapt your React and Node.js setup to use JWTs.

---

### Step 1: Update Node.js Backend

1. **Install JWT package:**

```bash
npm install jsonwebtoken

```

2. **Modify the OAuth Callback Route (`server.js`):** Instead of setting a session cookie, the backend will generate a JWT
   and redirect the user back to the React frontend, appending the token in the URL query parameters.

```javascript
const jwt = require("jsonwebtoken");

// Inside your Google Strategy callback or route handler:
app.get(
  "/auth/google/callback",
  passport.authenticate("google", { session: false, failureRedirect: "http://localhost:3000/login" }),
  (req, res) => {
    // 1. Create a JWT containing user info
    const payload = {
      id: req.user.id,
      name: req.user.displayName,
      email: req.user.emails[0].value,
    };

    const token = jwt.sign(payload, "your_jwt_secret", { expiresIn: "1h" });

    // 2. Redirect to React frontend with the token in the URL
    res.redirect(`http://localhost:3000/dashboard?token=${token}`);
  }
);
```

3. **Create a Protected API Middleware:** To protect your backend routes, create a middleware that verifies the JWT sent in
   the `Authorization` header.

```javascript
const verifyJWT = (req, res, next) => {
  const authHeader = req.headers["authorization"];
  const token = authHeader && authHeader.split(" ")[1]; // Bearer <token>

  if (!token) return res.status(401).json({ error: "Access denied" });

  jwt.verify(token, "your_jwt_secret", (err, user) => {
    if (err) return res.status(403).json({ error: "Invalid token" });
    req.user = user;
    next();
  });
};

// Protected Route Example
app.get("/api/protected-data", verifyJWT, (req, res) => {
  res.json({ message: `Welcome ${req.user.name}, this is secret data!` });
});
```

---

### Step 2: Update React Frontend

1. **Capture and Store the Token (`Dashboard.jsx`):** When the user is redirected back from the backend with the token in the
   URL, React should capture it, store it securely (e.g., in `localStorage` or memory), and clean up the URL.

```jsx
import React, { useEffect, useState } from "react";

export default function Dashboard() {
  const [data, setData] = useState(null);
  const [error, setError] = useState(null);

  useEffect(() => {
    // 1. Check for token in URL query parameters on initial load
    const params = new URLSearchParams(window.location.search);
    const tokenFromUrl = params.get("token");

    if (tokenFromUrl) {
      localStorage.setItem("jwt_token", tokenFromUrl);
      // Clean the token from the browser URL for cleanliness/security
      window.history.replaceState({}, document.title, window.location.pathname);
    }

    // 2. Fetch protected data using the stored token
    const token = localStorage.getItem("jwt_token");
    if (!token) {
      setError("No token found. Please log in.");
      return;
    }

    fetch("http://localhost:5000/api/protected-data", {
      headers: {
        Authorization: `Bearer ${token}`,
      },
    })
      .then((res) => {
        if (!res.ok) throw new Error("Unauthorized");
        return res.json();
      })
      .then((data) => setData(data))
      .catch(() => setError("Session expired or invalid. Please log in again."));
  }, []);

  const handleLogout = () => {
    localStorage.removeItem("jwt_token");
    window.location.href = "/login";
  };

  if (error)
    return (
      <div>
        {error} <a href="http://localhost:5000/auth/google">Login</a>
      </div>
    );
  if (!data) return <div>Loading...</div>;

  return (
    <div>
      <h2>Dashboard</h2>
      <p>{data.message}</p>
      <button onClick={handleLogout}>Logout</button>
    </div>
  );
}
```

---

### Comparison Summary

- **Session Cookies (Previous):** The browser automatically handles sending and storing cookies. It's generally more secure
  against XSS attacks if configured with `HttpOnly`, but requires state management on the server side.
- **JWT (This setup):** The backend remains stateless (no sessions stored in server memory). React manages the token storage
  (`localStorage`) and explicitly attaches it to API headers, making it ideal for decoupled architectures (like mobile apps
  or separate frontend/backend domains).
