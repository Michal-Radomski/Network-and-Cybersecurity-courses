## What is CSP?

**Content Security Policy (CSP)** is a computer security standard used to protect websites from attacks like Cross-Site
Scripting (XSS) and data injection. It acts as a set of rules enforced by the user's web browser to control which
resources—such as scripts, images, and stylesheets—are allowed to load and execute on a webpage.

---

## How It Works

CSP is implemented primarily through an **HTTP response header** sent from the web server. When a browser loads a page, it
reads this policy and blocks anything that violates the predefined security rules.

- **Restricts Origins:** Limits where scripts, stylesheets, and media can be loaded from.
- **Blocks Inline Scripts:** Prevents the execution of untrusted inline JavaScript by default.
- **Controls Data Exfiltration:** Restricts where web applications can send data via APIs or forms.

---

## Key Benefits

- **XSS Mitigation:** Makes it significantly harder for attackers to inject and run malicious JavaScript.
- **Defense in Depth:** Works as an extra layer of security alongside input sanitization and secure coding practices.
- **Reporting Mechanisms:** Can be configured in "report-only" mode to log policy violations without breaking the website,
  helping developers spot vulnerabilities.

---

## Example Policy

A typical CSP header looks like this:

`Content-Security-Policy: default-src 'self'; script-src 'self' [https://trustedscripts.com](https://trustedscripts.com);`

- `default-src 'self'`: Restricts most resource types to the website's own origin.
- `script-src`: Allows scripts only from the website's domain and a specific trusted third-party site.
