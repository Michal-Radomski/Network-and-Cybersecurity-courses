When your React application is built, it compiles into static files (HTML, JS, CSS). If your setup uses **Node.js** as an API
backend and **Apache** as the web server delivering those static React files, the best place to configure your Content
Security Policy (CSP) is directly on the **Apache server**.

Here is how to implement and configure it step-by-step:

---

## Step 1: Enable the Apache Headers Module

Apache needs the `headers` module active to inject custom HTTP response headers. Run these commands in your terminal:

```bash
sudo a2enmod headers
sudo systemctl restart apache2

```

---

## Step 2: Add the CSP Header in Apache

You can add the CSP header globally in your main Apache configuration file, inside your Virtual Host block, or locally via a
`.htaccess` file inside your React app's build directory.

### Option A: Using `.htaccess` (Easiest for shared hosting or standard builds)

Create or open the `.htaccess` file in the root folder of your built React project (e.g., inside `build/` or `dist/`) and
add:

```apache
<IfModule mod_headers.c>
    Header set Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self' https://your-node-api-domain.com;"
</IfModule>

```

### Option B: Using the Apache Virtual Host Configuration

If you have root access to the server configuration, add it directly inside your `<VirtualHost>` block:

```apache
<VirtualHost *:443>
    ServerName yourdomain.com
    DocumentRoot /var/www/my-react-app/build

    # Content Security Policy Header
    Header set Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'self' https://your-node-api-domain.com;"

    # (Optional) Ensure other security best practices
    Header set X-Content-Type-Options "nosniff"
    Header set X-Frame-Options "DENY"
</VirtualHost>

```

---

## Step 3: Tailor the CSP Directives for React & Node.js

Because React apps often fetch data from a Node.js backend and handle styles differently than traditional websites, your CSP
needs specific adjustments:

- **`default-src 'self'`**: Tells the browser that by default, all content should come from your own domain.
- **`script-src 'self'`**: Only allows JavaScript files hosted on your domain to execute, blocking injected malicious scripts
  (XSS).
- **`style-src 'self' 'unsafe-inline'`**: React frequently injects styles inline (or UI libraries might do so). Allowing
  `'unsafe-inline'` here prevents your styles from breaking, though a stricter nonces-based approach can be used for maximum
  security later.
- **`connect-src 'self' [https://your-node-api-domain.com](https://your-node-api-domain.com)`**: **Crucial for your Node.js
  backend.** This tells the browser it is safe for your React frontend to send fetch/axios requests to your Node.js API
  server.

---

## Step 4: Restart and Verify

After saving your configuration changes, restart Apache:

```bash
sudo systemctl restart apache2

```

Open your website, open your browser's Developer Tools (F12), and check the **Console** tab. If any scripts, styles, or API
calls violate your rules, Apache/the browser will log a clear CSP warning telling you exactly what was blocked.
