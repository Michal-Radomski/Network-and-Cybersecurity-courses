Configuring a Content Security Policy (CSP) header at the web server level is a great way to protect your entire website.
Here is how you can set it up on the two most popular web servers: **Nginx** and **Apache**.

---

## 1. Configuring CSP in Nginx

To add a CSP header in Nginx, you modify your server block configuration file (usually found in `/etc/nginx/sites-available/`
or `/etc/nginx/nginx.conf`).

- Open your configuration file.
- Add the `add_header` directive inside your `server {}` block:

```nginx
server {
    listen 80;
    server_name yourdomain.com;

    # Add the Content Security Policy header
    add_header Content-Security-Policy "default-src 'self'; script-src 'self' https://trusted.cdn.com;" always;
}

```

- **Test and Restart:** Check your Nginx configuration for syntax errors and reload the service:

```bash
sudo nginx -t
sudo systemctl reload nginx

```

---

## 2. Configuring CSP in Apache

For Apache, you need to ensure the headers module is active, then add the header via your main configuration file or a
`.htaccess` file.

- **Enable the headers module** (if it isn't already):

```bash
sudo a2enmod headers
sudo systemctl restart apache2

```

- **Add the header** inside your Virtual Host configuration or `.htaccess` file:

```apache
<VirtualHost *:80>
    ServerName yourdomain.com

    # Add the Content Security Policy header
    Header set Content-Security-Policy "default-src 'self'; script-src 'self' https://trusted.cdn.com;"
</VirtualHost>

```

- **Restart Apache** to apply the changes:

```bash
sudo systemctl restart apache2

```

---

## Best Practice: Start with "Report-Only" Mode

Because a strict CSP can accidentally break parts of your website (like loading fonts, tracking scripts, or styles), it is
wise to test it first. You can use the **Report-Only** header:

- **Nginx:** `add_header Content-Security-Policy-Report-Only "default-src 'self'; report-uri /csp-report-endpoint;" always;`
- **Apache:** `Header set Content-Security-Policy-Report-Only "default-src 'self'; report-uri /csp-report-endpoint;"`

This logs violations in the browser's developer console (or sends them to your specified endpoint) without actually blocking
anything, allowing you to fine-tune your rules safely.
