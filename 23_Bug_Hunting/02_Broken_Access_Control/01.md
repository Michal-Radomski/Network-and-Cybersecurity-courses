**Broken Access Control** occurs when a website or application fails to properly enforce permissions, allowing users to act
outside of their intended roles or view data they shouldn't have access to. It is consistently ranked as one of the most
common and critical web security risks (holding the #1 spot in the OWASP Top 10).

It typically breaks down into a few main categories:

### 1. Vertical Privilege Escalation (Going Up)

This happens when a standard, low-privileged user (like a regular customer) manages to access high-privileged functions meant
only for administrators.

- **Example:** An application has an admin panel at `/admin`, but it forgets to check if the person visiting that URL is
  actually logged in as an administrator. Anyone who types the URL can access it and delete users.

### 2. Horizontal Privilege Escalation (Moving Sideways / IDOR)

This happens when a user accesses or modifies resources belonging to _another_ user who has the exact same privilege level.
This is often tied to **IDOR (Insecure Direct Object References)**.

- **Example:** You log into your account, and your profile URL looks like
  `[mysite.com/account?id=1001](https://mysite.com/account?id=1001)`. If you change that parameter to `id=1002` and it
  successfully loads another customer's private profile and order history, the app has a horizontal access control flaw.

### 3. Unprotected Functions (Forced Browsing)

Sometimes developers try to "hide" sensitive features by simply not putting links to them on the normal user interface. If an
attacker discovers the hidden path (sometimes using a wordlist like the SecLists `raft-medium-directories.txt` file you
looked at earlier), they can access those features directly.
