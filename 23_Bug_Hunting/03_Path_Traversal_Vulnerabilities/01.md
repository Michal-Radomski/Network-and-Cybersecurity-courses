**Path traversal** (also known as **directory traversal**) is a web security vulnerability that allows an attacker to read
arbitrary files on the server running an application. This might include application source code, configuration files,
sensitive user data, or critical system files.

Here is a breakdown of how path traversal vulnerabilities work, why they happen, and how to prevent them.

---

## How Path Traversal Works

Web applications often need to load files from disk based on user input—such as viewing an image, downloading a document, or
loading a template page.

- **The Flaw:** If the application does not properly sanitize or validate the user-supplied input, an attacker can manipulate
  the file path.
- **The Mechanism:** Attackers typically use special character sequences, most commonly dot-dot-slash (`../`), to move up one
  directory level in the file system. By stringing multiple `../` sequences together, they can "escape" the intended web
  directory and navigate to restricted areas of the server's file system (for example, accessing `/etc/passwd` on a Linux
  server).

---

## Impact of the Vulnerability

The severity of a path traversal vulnerability depends heavily on the permissions of the user account running the web
application:

- **Information Disclosure:** Attackers can read sensitive system files, database credentials, or source code.
- **Remote Code Execution (RCE):** In worst-case scenarios, if the application allows file uploads alongside path traversal,
  an attacker might be able to upload executable scripts to critical system directories and run them.

---

## Prevention and Remediation

Developers can protect applications from path traversal using several secure coding practices:

- **Avoid Using User Input for File Paths:** Whenever possible, avoid letting users specify filenames or paths directly.
  Instead, use an indirect reference map (like an ID or a dropdown selection) that maps to a hardcoded file path on the
  server.
- **Input Validation and Sanitization:** If user input must be used, implement a strict "allowlist" of permitted characters,
  words, or filenames. Reject any input containing directory navigation sequences like `../` or `..\`.
- **Use Built-In Safe APIs:** Many modern programming languages and frameworks provide secure functions or methods designed
  to handle paths safely (e.g., resolving absolute paths and ensuring they remain within a designated base directory).
- **Principle of Least Privilege:** Run the web server and application with the lowest possible system permissions so that,
  even if a vulnerability is exploited, the attacker's access to the rest of the system is severely restricted.
