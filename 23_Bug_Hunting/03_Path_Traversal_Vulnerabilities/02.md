Storing images on servers involves more than just dumping files into a folder. Depending on the size, scale, and architecture
of a website or application, developers use several different methods to store, manage, and serve images efficiently.

Here is a breakdown of how images are typically stored on servers:

## 1. Direct File System Storage

The traditional approach is to save images directly onto the server's hard drive (SSD or HDD) inside a designated folder
structure.

- **How it works:** When a user uploads an image, the backend code saves the raw file into a specific directory (e.g.,
  `/var/www/mywebsite/uploads/2026/06/`).
- **Database link:** The server usually stores only the **file path** or filename in a database (e.g., `images/sunset.jpg`)
  linked to the user or post, rather than the image itself.
- **Pros & Cons:** Simple to set up and works well for small websites. However, it doesn't scale well if a website grows and
  needs multiple servers, because the servers would have to sync their file systems.

---

## 2. Cloud Object Storage

Modern web applications and large-scale platforms heavily rely on cloud object storage services (such as Amazon S3, Google
Cloud Storage, or Microsoft Azure Blob Storage).

- **How it works:** Instead of storing files on the local web server, images are uploaded directly to a cloud storage bucket
  via an API.
- **Accessibility:** Each image gets a unique URL hosted by the cloud provider. The application database simply stores this
  URL.
- **Pros & Cons:** Highly scalable, secure, and reliable. It offloads storage and bandwidth heavy-lifting from your main web
  server.

---

## 3. Databases as BLOBs (Binary Large Objects)

In some specific cases, images can be stored directly inside a relational database (like MySQL, PostgreSQL, or MongoDB).

- **How it works:** The image file is converted into binary data and stored inside a column designated as a **BLOB**.
- **Pros & Cons:** Keeps everything neatly backed up in one place (the database). However, it is generally **discouraged**
  for web applications because storing large binary files bloats the database size, slows down queries, and consumes
  excessive memory.

---

## Delivering Images: CDNs

Once images are stored (usually in cloud storage or a file system), they are rarely served directly from a single origin
server to users worldwide. Instead, developers use a **CDN (Content Delivery Network)** like Cloudflare, AWS CloudFront, or
Fastly.

- **Caching:** CDNs cache copies of your images on edge servers located all over the world.
- **Speed:** When a user in Tokyo requests an image, they get it from a nearby server in Japan rather than the main server in
  the United States, making the website load much faster.
