## What is Shellshock?

Shellshock is a major computer security flaw discovered in 2014 that affected **GNU Bash**, a widely used command-line shell
found in Unix-based operating systems like Linux and macOS. Because Bash is used extensively to run scripts and manage system
operations, this vulnerability had a massive reach across the internet.

---

## How Did It Work?

- **Environment Variables:** Bash allows administrators and programs to store configuration data in "environment variables."
- **The Flaw:** Bash had a bug where it would mistakenly execute code that was accidentally (or maliciously) placed _after_ a
  function definition inside an environment variable.
- **Remote Code Execution:** Attackers could exploit this by sending specially crafted inputs—such as through web servers
  running outdated CGI scripts—that tricked Bash into running unauthorized commands automatically upon startup.

---

## Why Was It So Dangerous?

- **Widespread Impact:** It affected countless servers, routers, and IoT devices running Linux or macOS.
- **High Severity:** It allowed for **Remote Code Execution (RCE)**, meaning an attacker could potentially gain full control
  over a vulnerable server from anywhere across the internet without needing a password.

---

## How Was It Fixed?

As soon as the vulnerability was publicized, security researchers and developers rushed to release patches for GNU Bash. The
fix involved modifying how Bash parses environment variables so it safely ignores any trailing code appended to function
definitions. System administrators quickly updated their software to close the security gap.

In a vulnerable version of the GNU Bash shell, this specific syntax allowed an environment variable to masquerade as a
