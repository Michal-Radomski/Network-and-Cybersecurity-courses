To prevent Server-Side Request Forgery (SSRF) in a Node.js application (often paired with a frontend like React and hosted
behind Apache), you need to ensure that your server-side code never blindly trusts or executes HTTP requests based on
user-supplied URLs.

Here is a practical guide to securing your architecture against SSRF:

---

### 1. Validate and Sanitize User Input (Node.js)

The core vulnerability happens when user input is passed directly to an HTTP client (like `axios` or `fetch`).

- **Allowlist Approach:** Instead of trying to block malicious domains (blocklisting), maintain a strict allowlist of
  permitted domains or APIs that your server is allowed to talk to.
- **URL Parsing:** Use the built-in Node.js `URL` module to parse and validate incoming URLs before making any requests.
  Check that the `protocol` is strictly `https:` and that the `hostname` matches your approved list.

```javascript
const { URL } = require("url");

function isValidUrl(userInput) {
  try {
    const parsed = new URL(userInput);
    // Only allow specific trusted domains
    const allowedDomains = ["api.trustedservice.com", "data.internaldomain.local"];
    return parsed.protocol === "https:" && allowedDomains.includes(parsed.hostname);
  } catch (err) {
    return false; // Invalid URL structure
  }
}
```

### 2. Restrict Network Access (Network-Level Protection)

Even if an attacker tricks your Node.js app into making a request, you can limit the damage by restricting what the server
can reach:

- **Block Internal IP Ranges:** Ensure your Node.js application cannot send requests to local network addresses, loopback
  addresses (`127.0.0.1`, `localhost`), or metadata services (like `169.254.169.254` used in cloud environments).
- **Firewall Rules:** Configure your server's firewall (or cloud security groups) so that the Node.js backend can only make
  outbound requests to the specific external services it actually needs.

### 3. Configure Apache Reverse Proxy Safely

If Apache is acting as a reverse proxy forwarding traffic to your Node.js app:

- **Disable Unnecessary Proxying:** Ensure Apache isn't configured with open proxy settings (e.g., `ProxyRequests On`). It
  should only forward requests to predefined application routes.
- **Header Sanitization:** Strip or sanitize incoming headers that could be manipulated to alter routing behavior.
