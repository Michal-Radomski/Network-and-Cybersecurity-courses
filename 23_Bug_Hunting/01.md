## What is Bug Bounty Hunting?

**Bug bounty hunting** is a practice where companies and organizations invite independent security researchers and ethical
hackers (often called "bug bounty hunters") to find and report security vulnerabilities in their websites, apps, and APIs.

Instead of treating external hackers as threats, organizations partner with them through formal programs (hosted on platforms
like HackerOne or Bugcrowd) to improve their security.

---

### How It Works

1. **The Program Setup:** A company sets up a bug bounty program outlining what systems are safe to test (the "scope") and
   what rewards they offer.
2. **The Hunt:** Ethical hackers use tools (like the ones we've discussed, such as automated scanners or manual testing
   proxies) to look for security flaws like IDOR, broken authentication, or injection bugs.
3. **Responsible Disclosure:** If a hunter finds a vulnerability, they submit a detailed report to the company rather than
   exploiting it maliciously.
4. **The Bounty:** Once the company verifies the bug is real and fixes it, they reward the researcher with public
   recognition, points, or a cash payout (bounty) based on how severe the flaw was.

Bug bounty hunting is a legal, constructive way to leverage crowdsourced security so companies can patch weaknesses before
malicious hackers find them.

---

---

When ethical hackers hunt for bugs in APIs, they look for high-severity flaws that can lead to data leaks or complete system
compromise. According to the **OWASP API Security Top 10**, some of the most sought-after and critical bugs include:

- **BOLA (Broken Object Level Authorization):** As discussed earlier, swapping an ID in a request URL to view or modify
  another user's private data. This is one of the most common and lucrative bugs found in bug bounties.
- **Broken Function Level Authorization (BFLA):** Finding endpoints intended only for administrators (like
  `/api/admin/delete-database`) and discovering that a regular, low-privileged user account can successfully access them just
  by changing the URL or HTTP method.
- **Mass Assignment / Excessive Data Exposure:** Finding endpoints that return too much sensitive user data (like internal
  password hashes or personal identifiable info) or letting attackers inject hidden database fields (like `role: "admin"`)
  during registration.
- **Server-Side Request Forgery (SSRF):** Tricking an API into fetching data from internal servers or external URLs that the
  application shouldn't normally have access to.
