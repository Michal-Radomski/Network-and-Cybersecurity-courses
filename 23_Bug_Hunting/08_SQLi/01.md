## What is SQL Injection (SQLi)?

**SQL Injection (SQLi)** is a common cybersecurity vulnerability that happens when an application improperly handles user
input, allowing an attacker to insert (or "inject") malicious database commands into a query.

To understand it, it helps to know that **SQL** (Structured Query Language) is the programming language used to communicate
with databases (where websites store user data, passwords, and content).

---

### How SQLi Works

Imagine a simple login form on a website that asks for a username. Behind the scenes, the website creates a database command
like this:

```sql
SELECT * FROM users WHERE username = 'userInputHere';

```

- **Normal behavior:** If you type `alex`, the database searches for the user named "alex".
- **SQL Injection behavior:** If an attacker enters a specially crafted string containing SQL commands (like `' OR '1'='1`),
  the database command becomes:

```sql
SELECT * FROM users WHERE username = '' OR '1'='1';

```

Because `'1'='1'` is always true, the database gets tricked into returning _all_ user accounts, potentially letting the
attacker log in without a password.

---

### Why It's Dangerous

- **Data Theft:** Attackers can read sensitive data, like customer records, personal info, or credit card numbers.
- **Data Tampering:** They can modify or delete data inside the database.
- **Admin Access:** In severe cases, attackers can gain complete control over the database server.

---

### How to Prevent It

Developers protect websites from SQL injection using secure coding practices:

- **Parameterized Queries (Prepared Statements):** This is the gold standard. It ensures the database treats user input
  strictly as data, never as executable code.
- **Input Validation:** Checking and filtering user input to make sure it only contains expected characters.
- **Principle of Least Privilege:** Giving the database account used by the website only the permissions it strictly needs,
  limiting damage if an attack occurs.
