## What is Blind SQL Injection?

**Blind SQL Injection** is a variation of regular SQL injection. It happens when a web application is vulnerable to SQLi, but
**does not actually display database results or error messages** on the screen.

Instead of seeing the data directly, the attacker (or security tester) has to "blindly" extract information by asking the
database a series of True/False questions and observing how the website behaves.

---

### How Blind SQLi Works

Since the application doesn't output database data, attackers rely on two main techniques:

- **Boolean-Based (True/False):** The attacker injects a condition (e.g., _"Is the first letter of the administrator's
  password 'a'?"_). If the page loads normally, the answer is True. If it shows an error or a different page, the answer is
  False. By repeating this process letter by letter, they can slowly map out hidden data.
- **Time-Based:** The attacker injects a command that forces the database to pause or sleep for a few seconds (e.g.,
  `WAITFOR DELAY '0:0:5'`). If the website takes 5 seconds longer to load than usual, the attacker knows their injected
  condition was True.

---

### Why It's Tricky

- **Harder to Detect:** Because there are no visible error messages, traditional web scanners or casual glances might miss
  it.
- **Slower to Exploit:** Extracting data bit by bit through True/False or time delays takes a lot of time and automated
  scripting.

### Prevention

Just like standard SQL injection, the defense is identical:

- **Parameterized Queries (Prepared Statements):** This completely blocks the database from executing malicious input as
  code, whether the output is visible or not.
