## What is Time-Based Blind SQL Injection?

**Time-Based Blind SQL Injection (SQLi)** is a type of security vulnerability that occurs when an application takes user
input and uses it in a database query without proper validation or sanitization, but **does not return any data or error
messages** in the application's response.

Because the application is "blind" (it doesn't show whether the query succeeded or failed on the screen), an attacker has to
find another way to ask the database true/false questions. They do this by forcing the database to wait (sleep) for a
specific amount of time.

---

## How It Works Conceptually

1. **The Hidden Query:** The application runs a database query that includes untrusted user input.
2. **Conditional Delay:** An attacker injects a command that tells the database: _"If a certain condition is true, pause for
   5 seconds before responding. If it is false, respond immediately."_
3. **Measuring Time:** The attacker measures how long the server takes to reply.

- If the page takes 5 seconds to load, the condition was **true**.
- If the page loads instantly, the condition was **false** (or the vulnerability isn't there).

4. **Data Extraction:** By repeating this process letter by letter or number by number, sensitive data (like database
   versions or table names) can theoretically be guessed and pieced together based on timing delays.

---

## Why Is It Dangerous?

Even though it is slow and tedious to perform, time-based blind SQLi is dangerous because it can be used against applications
that seem secure on the surface—meaning they don't display database errors or output data directly to the web page. If left
unpatched, it can eventually lead to unauthorized access to sensitive data stored in the database.

---

## How to Prevent It

Protecting applications against SQL injection, including time-based variants, involves secure coding practices:

- **Use Parameterized Queries (Prepared Statements):** This is the most effective defense. It ensures that user input is
  always treated as data, never as executable database code.
- **Use Object-Relational Mapping (ORM):** Modern frameworks (like Entity Framework, Hibernate, or Django ORM) often build
  safe queries automatically by default.
- **Input Validation and Least Privilege:** Restrict database user accounts so they only have the bare minimum permissions
  needed to function, limiting potential damage if a vulnerability is present.
