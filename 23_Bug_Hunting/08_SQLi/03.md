Time-based blind SQL injection is a great one to learn next—watching a server deliberately delay its response based on an
injected boolean condition really makes the concepts click!

When building a full-stack application with **React (frontend)**, **Node.js/Express (backend)**, and **TypeScript**, the most
important thing to remember is that **SQL injection happens entirely on the backend/database layer**. React is just a user
interface; it cannot prevent SQLi on its own because malicious input can bypass the frontend entirely (using tools like Burp
Suite or cURL).

Here are the key TypeScript snippets for a Node.js backend using popular database drivers to prevent SQL injection.

---

### 1. Using `pg` (PostgreSQL)

If you are using native PostgreSQL, **never** use template literals (`${}`) to concatenate user input directly into a query
string. Instead, use parameterized queries by passing values into an array as the second argument to `pool.query`.

```typescript
import { Pool } from "pg";
import { Request, Response } from "express";

const pool = new Pool({
  // connection config...
});

export async function getUser(req: Request, res: Response): Promise<void> {
  const username: string = req.body.username;

  try {
    // ❌ VULNERABLE: Direct string concatenation allows SQLi
    // const query = `SELECT * FROM users WHERE username = '${username}'`;
    // const result = await pool.query(query);

    // ✅ SECURE: Parameterized query (Node/pg handles escaping safely)
    const query = "SELECT id, username, email FROM users WHERE username = $1";
    const result = await pool.query(query, [username]);

    res.json(result.rows);
  } catch (error) {
    console.error(error);
    res.status(500).json({ error: "Internal server error" });
  }
}
```

### 2. Using Knex.js (SQL Query Builder in TypeScript)

If you are using an ORM or query builder like **Knex.js**, it uses parameterized queries by default _as long as_ you use its
built-in method bindings correctly.

```typescript
import knex from "knex";
import { Request, Response } from "express";

const db = knex({
  client: "pg", // or 'mysql2', 'sqlite3', etc.
  connection: {
    /* config */
  },
});

export async function getUserByEmail(req: Request, res: Response): Promise<void> {
  const email: string = req.query.email as string;

  try {
    // ✅ SECURE: Knex automatically parameterizes inputs passed to .where()
    const users = await db("users").select("id", "email").where("email", email);

    res.json(users);
  } catch (error) {
    res.status(500).json({ error: "Internal server error" });
  }
}
```

_Note on Knex:_ Be careful with raw queries like `db.raw('SELECT * FROM users WHERE email = ?', [email])`. They are safe if
you use placeholders (`?`), but if you use template literals (`db.raw(`... ${email}`)`), you open yourself right back up to
SQLi.

---

### 3. Using Prisma ORM (Type-Safe Database Client)

Prisma is extremely popular in modern TypeScript/Node.js stacks. Because it uses a strongly typed query engine under the
hood, it automatically protects against SQL injection for all standard operations.

```typescript
import { PrismaClient } from "@prisma/client";
import { Request, Response } from "express";

const prisma = new PrismaClient();

export async function searchUser(req: Request, res: Response): Promise<void> {
  const searchTerm: string = req.query.q as string;

  try {
    // ✅ SECURE: Prisma's API methods are automatically parameterized
    const users = await prisma.user.findMany({
      where: {
        username: {
          contains: searchTerm,
        },
      },
    });

    res.json(users);
  } catch (error) {
    res.status(500).json({ error: "Internal server error" });
  }
}
```

---

### Summary Checklist for Node/TS:

1. **Never concatenate user input** into SQL strings using template literals or `+`.
2. **Always use placeholders** (`$1`, `?`, etc.) provided by your database driver or query builder.
3. **Be cautious with `.raw()` queries** in ORMs/Query builders, as they give you raw power but remove automatic safety
   guards if misused.
