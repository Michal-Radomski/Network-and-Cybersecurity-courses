## What is PKCE?

**PKCE** (pronounced "pixie"), which stands for **Proof Key for Code Exchange** (RFC 7636), is an extension to the OAuth 2.0
authorization code grant. Originally designed to secure native and mobile apps, it is now the gold standard for **Single Page
Applications (SPAs)** like React, where client secrets cannot be safely stored.

Without PKCE, an attacker could potentially intercept the authorization code during the redirect and exchange it for an
access token. PKCE prevents this by introducing a cryptographically random string called a **code verifier** and its hashed
counterpart, the **code challenge**.

---

## How PKCE Works (Step-by-Step)

1. **Generate Verifier & Challenge:** The React app generates a random string (`code_verifier`) and creates a SHA-256 hash of
   it called the `code_challenge`.
2. **Authorization Request:** The React app redirects the user to the Authorization Server (e.g., Auth0, Keycloak, Google)
   along with the `code_challenge` and the challenge method (`S256`).
3. **Authorization Code:** After successful login, the server redirects back to React with an `authorization_code`.
4. **Token Exchange:** The React app sends the `authorization_code` _plus_ the original `code_verifier` directly to the
   server.
5. **Verification:** The server hashes the received `code_verifier` and compares it to the original `code_challenge`. If they
   match, the server issues the tokens. Even if someone stole the authorization code earlier, they can't use it without the
   `code_verifier` that never left the browser!

## Implementing PKCE in a React + Node.js App

### 1. React Frontend (Initiating Auth & Handling Callback)

In a React app, it is usually easiest to use a trusted library like `oidc-client-ts` or `@auth0/auth0-react` which handles
PKCE out of the box. However, here is the conceptual implementation using standard browser APIs (`crypto`):

```javascript
// 1. Generate Code Verifier and Challenge
function generateRandomString(length) {
  const possible = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-._~";
  let text = "";
  for (let i = 0; i < length; i++) {
    text += possible.charAt(Math.floor(Math.random() * possible.length));
  }
  return text;
}

async function sha256(plain) {
  const encoder = new TextEncoder();
  const data = encoder.encode(plain);
  return window.crypto.subtle.digest("SHA-256", data);
}

function base64urlencode(a) {
  let str = "";
  const bytes = new Uint8Array(a);
  const len = bytes.byteLength;
  for (let i = 0; i < len; i++) {
    str += String.fromCharCode(bytes[i]);
  }
  return btoa(str).replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, "");
}

async function loginWithPKCE() {
  const verifier = generateRandomString(64);
  sessionStorage.setItem("code_verifier", verifier); // Save for later step

  const challengeBytes = await sha256(verifier);
  const challenge = base64urlencode(challengeBytes);

  // Redirect to Authorization Server
  const authUrl =
    `https://your-auth-server.com/oauth/authorize?` +
    `client_id=YOUR_CLIENT_ID&` +
    `redirect_uri=http://localhost:3000/callback&` +
    `response_type=code&` +
    `code_challenge_method=S256&` +
    `code_challenge=${challenge}`;

  window.location.href = authUrl;
}
```

### 2. Node.js Backend (Token Exchange & API Protection)

Your Node.js/Express backend typically acts as a Resource Server that verifies the access tokens issued by the authorization
server, or it can handle the token exchange if you want to keep client secrets off the public client.

Here is how a Node.js backend validates the token using `express-oauth2-jwt-bearer`:

```javascript
const express = require("express");
const { auth } = require("express-oauth2-jwt-bearer");

const app = express();

// Middleware to validate Access Tokens coming from React
const checkJwt = auth({
  audience: "https://your-api-identifier.com",
  issuerBaseURL: "https://your-auth-server.com/",
});

// Protected route
app.get("/api/protected", checkJwt, (req, res) => {
  res.json({ message: "Hello from Node.js! You are authorized.", user: req.auth });
});

app.listen(3001, () => {
  console.log("Server running on port 3001");
});
```

> **Note:** The heavy lifting of PKCE validation happens directly at the OAuth2 Authorization Server (like Auth0, Okta, or
> Keycloak). Your Node backend simply needs to trust and verify the resulting JWT access tokens.
