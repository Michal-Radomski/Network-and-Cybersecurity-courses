An **Information Disclosure Vulnerability** (also known as information leakage) happens when a system, website, or
application unintentionally reveals sensitive data to users or unauthorized parties.

While it might not look like a direct attack right away, it acts like an open window—giving attackers a map or clues they
need to launch bigger, more damaging cyberattacks.

---

### Common Types of Leaked Information

- **Technical Details:** Server types, software or framework versions (e.g., revealing exact version numbers in HTTP
  headers), and internal file paths.
- **Verbose Error Messages:** Detailed stack traces or database errors that reveal internal code logic, table structures, or
  database names.
- **Credentials & Secrets:** Hardcoded API keys, passwords, or tokens left inside client-side code or public configuration
  files (like `.env` files).
- **User Data (PII):** Accidental exposure of personal data, such as email addresses, phone numbers, or financial details.

### Why Do They Happen?

1. **Misconfigurations:** Leaving debug modes or directory listing enabled on production web servers.
2. **Poor Error Handling:** Letting applications spit out raw error logs directly to the user interface instead of logging
   them privately on the backend.
3. **Insecure Code Practices:** Leaving comments or hardcoded secrets in source code repositories that get pushed to public
   platforms.

### How to Prevent and Fix Them

- **Generic Error Messages:** Ensure live applications show friendly, generic errors to users (e.g., _"Something went
  wrong"_), while saving the detailed technical logs securely on the server.
- **Harden Configurations:** Disable unnecessary server headers (like `X-Powered-By`), turn off directory listings, and
  ensure debug tools are strictly disabled in production environments.
- **Secure Secrets Management:** Keep API keys and credentials out of source code by utilizing secure environment variables.
