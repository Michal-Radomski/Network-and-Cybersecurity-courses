**Website OSINT** (Open-Source Intelligence) refers to the practice of collecting, analyzing, and gathering information about
a website, web application, or web domain using **publicly available data**.

In the cybersecurity and tech industry, it is widely used by security professionals, penetration testers, and defenders for
**Attack Surface Management**—identifying what an organization exposes to the public internet so they can secure it before an
attacker finds it.

---

### Key Categories of Website OSINT

When analyzing a website through an open-source lens, investigations typically look at several distinct layers:

#### 1. Domain and Registration Intelligence (WHOIS)

- **What it looks at:** Ownership details, registrar information, creation dates, and expiration dates.
- **Why it matters:** Helps determine how long a domain has existed, whether it's tied to an organization or privacy service,
  and historical ownership changes via archived records (like the Wayback Machine).

#### 2. Infrastructure and Network Mapping

- **What it looks at:** IP addresses, hosting providers, Autonomous System Numbers (ASNs), and DNS records (A, MX, TXT,
  CNAME).
- **Why it matters:** Reveals where the website is hosted, what email servers or security services (like Cloudflare) sit in
  front of it, and whether there are associated server endpoints.

#### 3. Subdomain Enumeration

- **What it looks for:** Hidden or forgotten subdomains (e.g., `test.example.com`, `dev.example.com`, `admin.example.com`).
- **Why it matters:** Development or staging subdomains are frequently left unsecured, poorly configured, or running outdated
  software that lacks production-level security controls.

#### 4. Technology Stack Fingerprinting

- **What it looks for:** Content Management Systems (CMS like WordPress or Drupal), server software (Apache, Nginx),
  frameworks (React, Laravel), and third-party JavaScript libraries or plugins.
- **Why it matters:** Knowing the exact version of a piece of software helps security teams check if it contains known,
  unpatched vulnerabilities.

#### 5. File and Content Discovery ("Google Dorking")

- **What it looks for:** Exposed files, configuration backups, directory listings, or login portals indexed by search engines
  using advanced operators.
- **Common Operators:** \* `site:` (restricts searches to a specific domain)
- `filetype:` (searches for specific file extensions like `.pdf`, `.conf`, or `.sql`)
- `intitle:` (looks for specific terms in the page title)

---

### Common Defensive Tools

Professionals use various automated and manual tools to map a website's public footprint:

- **DNS Lookups & Subdomain Tools:** Tools like `nslookup`, `dig`, Sublist3r, or Amass to map domain structures.
- **Web Archiving:** The Wayback Machine (`archive.org`) to view historical snapshots of a website and look for deleted
  pages, old developers' notes, or exposed configurations.
- **Security Scanners / Search Engines:** Platforms like **Shodan** or **Censys**, which index internet-connected devices and
  servers, helping identify open ports or misconfigured web services.

---

### Ethical Considerations

Website OSINT is strictly focused on **passive or public-facing reconnaissance**. It relies entirely on data that is already
accessible to anyone on the internet without bypassing authentication controls, guessing passwords, or breaking into
restricted systems. Crossing those boundaries moves from intelligence gathering into unauthorized access or hacking.
