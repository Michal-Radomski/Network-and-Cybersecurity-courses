## What is Local File Inclusion (LFI)?

**Local File Inclusion (LFI)** is a web application vulnerability that occurs when an application uses untrusted user input
to load or display files stored on the server.

When input is not properly validated or sanitized, an attacker can manipulate the file path—often using path traversal
sequences like `../`—to trick the application into opening files that should be restricted, such as source code,
configuration files, or sensitive system files (like `/etc/passwd` on Unix-like systems).

---

### How LFI Typically Happens

1. **Unsafe Input Handling:** The application takes a parameter from the URL or a form (e.g., `page=about.php`) and passes it
   directly into a file-loading function.
2. **Lack of Validation:** The application does not check whether the requested file is part of an approved list of allowed
   files.
3. **Path Manipulation:** Instead of loading `about.php`, an input containing path traversal sequences forces the server to
   look outside the intended directory and return a sensitive file instead.

---

### How to Prevent LFI

Securing an application against file inclusion vulnerabilities involves strict control over what paths and files the server
is allowed to access:

- **Use Whitelists (Allow-lists):** Map user input to a predefined, hardcoded list of safe file paths rather than letting
  users specify filenames directly.
- **Avoid Raw User Input:** Never concatenate raw user input directly into file system paths or include statements.
- **Implement Strict Input Validation:** Reject any input containing path traversal characters (like `..` or slash
  variations) if dynamic naming is absolutely necessary.
- **Use Chroot / Sandboxing:** Run the application in a restricted environment or container so that even if an LFI
  vulnerability exists, the attacker cannot access files outside that isolated directory.
