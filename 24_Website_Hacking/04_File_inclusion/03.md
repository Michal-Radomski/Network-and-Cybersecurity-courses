## What is Remote File Inclusion (RFI)?

**Remote File Inclusion (RFI)** is a web application vulnerability that occurs when an application improperly handles user
input to load and execute files from an external, remote server (rather than locally on the same machine).

While Local File Inclusion (LFI) lets an attacker access files _already on_ the server, RFI allows an attacker to host a
malicious script on their own server and trick the target application into downloading and executing it.

---

### How RFI Typically Happens

1. **Unsafe Dynamic Loading:** The application takes a URL or file path from user input (like a query parameter) and passes
   it into a function that fetches and includes external content.
2. **Lack of Validation:** The app does not restrict the input to trusted internal domains or local directories.
3. **Execution:** The application downloads the remote file (which might contain malicious code) and runs it within the
   server's context, potentially leading to Remote Code Execution (RCE).

_Note: RFI is most historically famous in PHP-based applications (where settings like `allow_url_include` could be
exploited), but any application that dynamically fetches and executes untrusted remote URLs or files is vulnerable._

---

### How to Prevent RFI

Securing an application against remote file inclusion requires strict control over external data and file handling:

- **Disable Remote File Inclusion in Frameworks/Runtimes:** If using languages or frameworks that have configuration flags
  for remote inclusions (such as `allow_url_include` in PHP), ensure they are turned **off**.
- **Never Execute Remote Code:** Avoid writing code that downloads and runs raw scripts or templates from user-supplied URLs.
- **Use Whitelists (Allow-lists):** If external resources must be fetched (like fetching data from an API), strictly validate
  the domain against a hardcoded, trusted list of approved URLs using a URL parser rather than raw string concatenation.
- **Use Safe APIs:** Use standard HTTP client libraries (like `axios` or `fetch` in Node.js) to retrieve _data_ safely,
  rather than executing or including files directly into the execution flow.
