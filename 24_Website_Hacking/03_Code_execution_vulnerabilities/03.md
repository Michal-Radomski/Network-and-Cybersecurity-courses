Here is a breakdown of how these four functions work in JavaScript and Node.js, along with their security implications.

---

### 1. `child_process.exec()`

- **What it does:** Spawns a shell (like `bash` or `cmd.exe`) and runs a command string inside that shell. It buffers the
  output and passes the result (stdout and stderr) to a callback function once the process finishes.
- **Security Risk:** Because it passes the command through a shell, it evaluates shell metacharacters (like `;`, `&`, or
  `|`). If user input is concatenated directly into the command string, it can lead to **command injection**.

### 2. `child_process.execFile()`

- **What it does:** Executes a specific file directly as a new process, _without_ spawning a shell by default. You pass the
  arguments as an array rather than a single concatenated string.
- **Security Risk:** Much safer than `exec()` because it avoids shell interpretation. Even if the arguments contain shell
  special characters, they are treated strictly as literal parameter values rather than executable commands.

### 3. `spawn()`

- **What it does:** Launches a new process asynchronously and returns a stream-based interface (using Node.js
  `EventEmitter`). Instead of buffering all output into memory until the process completes, it streams data (`stdout` and
  `stderr`) chunk by chunk as it comes in.
- **Best Use Case:** Ideal for long-running processes or commands that generate large amounts of output (like video
  processing or large data compilation). Like `execFile`, it takes arguments as an array and does not spawn a shell by
  default.

### 4. `eval()`

- **What it does:** A built-in JavaScript function that takes a string of text and evaluates/executes it as actual JavaScript
  code within the current execution context.
- **Security Risk:** Highly dangerous when used with untrusted data. If an attacker can control the string passed to
  `eval()`, they can run arbitrary code on your server or in the user's browser, leading to **Remote Code Execution (RCE)**
  or **XSS**. It should almost always be avoided.
