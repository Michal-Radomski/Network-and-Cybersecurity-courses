### What is a Code Execution Vulnerability?

A **code execution vulnerability** (often referred to as **Remote Code Execution** or **RCE**) occurs when a web application
or software flaw allows an attacker to execute arbitrary programming code or system commands on the underlying server or
device.

Unlike other vulnerabilities that might only affect a specific database or user account, RCE is considered one of the most
severe security risks because it grants direct control over the host system.

---

### How Code Execution Vulnerabilities Happen

These flaws typically occur when an application improperly handles user-supplied input and passes it directly to internal
interpreter functions or operating system shells without adequate validation or sanitization.

- **Unsafe Evaluation Functions:** Using built-in programming functions (like `eval()` in PHP or Python, or `exec()`) that
  dynamically execute text as code, while allowing untrusted user input to influence that text.
- **Command Injection:** When an application takes user input (such as a form field or URL parameter) and passes it directly
  to the operating system command line (e.g., executing system terminal commands).
- **Deserialization Flaws:** When an application unserializes (converts back into objects) untrusted data without
  verification, allowing malicious code to be injected during the object recreation process.

---

### Potential Impact

If a code execution vulnerability is successfully exploited, the consequences are severe:

- **Full System Compromise:** An attacker can gain complete administrative control over the web server.
- **Data Breach:** Sensitive data, including databases, environment variables, and user credentials, can be stolen or
  destroyed.
- **Pivoting to Internal Networks:** The compromised server can be used as a launchpad to attack other internal systems
  behind a corporate firewall.
- **Malware Deployment:** The server can be co-opted to host malware, crypto-miners, or botnet software.

---

### Prevention and Best Practices

Defending against code execution vulnerabilities requires strict secure coding habits:

- **Avoid Dangerous Functions:** Refrain from using dynamic code execution functions like `eval()` or OS command execution
  functions whenever possible. If they must be used, never allow direct user input to reach them.
- **Strict Input Validation:** Use robust allowlists to ensure user input strictly conforms to expected formats (e.g.,
  checking that an age field contains only integers).
- **Use Safe APIs and Libraries:** When executing system-level tasks, use high-level libraries or parameterized APIs that
  safely handle arguments without passing them through a shell interpreter.
- **Principle of Least Privilege:** Run the web server application with minimal user permissions so that even if a flaw is
  exploited, the attacker's access to the wider operating system is heavily restricted.
