Penetration testers (pentesters) gather information about websites during the initial phase of an assessment, commonly known
as **reconnaissance** or **recon**. The goal is to map out the target's digital footprint, identify underlying technologies,
and find potential entry points.

This process is generally divided into two main categories: **passive** and **active** reconnaissance.

---

### 1. Passive Reconnaissance (Information Gathering without Direct Contact)

Passive recon involves collecting publicly available data without interacting directly with the target website's servers.
This keeps the activity completely stealthy.

- **OSINT (Open Source Intelligence):** Pentesters search public records, social media, corporate blogs, and job postings.
  Job postings, for example, often reveal what tech stack, frameworks, or cloud services a company uses.
- **WHOIS Lookups:** Checking domain registration details to find ownership records, registrar data, and administrative
  contact information.
- **Search Engine Dorking:** Using advanced search operators (like `site:`, `filetype:`, or `intitle:`) on search engines to
  unearth hidden files, old admin portals, or sensitive documents (such as exposed PDFs or configuration sheets) left indexed
  online.
- **Certificate Transparency Logs:** Pentesters query public logs where SSL/TLS certificates are recorded. This is a powerful
  way to discover hidden or internal subdomains (`admin.example.com`, `staging.example.com`) associated with a target.

---

### 2. Active Reconnaissance (Directly Interacting with the Target)

Active recon involves direct communication with the website and its servers to gather detailed technical specifications.
While this generates network traffic and logs, it yields granular insights.

- **DNS Enumeration:** Querying domain name servers using tools like `dig`, `nslookup`, or `dnsrecon` to map out IP
  addresses, mail exchangers (MX records), and text records.
- **Port Scanning & Service Fingerprinting:** Using tools like **Nmap** to scan for open ports, running services, and the
  specific operating systems or server software versions powering the infrastructure.
- **Technology Detection:** Utilizing tools like **WhatWeb** or browser extensions to identify the Content Management System
  (CMS) (e.g., WordPress, Drupal), JavaScript frameworks, or web servers (e.g., Nginx, Apache). Knowing the exact software
  version helps testers check for known vulnerabilities.
- **Directory and File Brute-Forcing:** Using tools like **Gobuster** or **Dirsearch** to systematically guess and discover
  hidden directories, backup files, or administrative panels (like `/robots.txt`, `/sitemap.xml`, or hidden login pages) that
  aren't directly linked from the main menu.

---

### Why is this phase important?

The data collected during information gathering acts as the blueprint for the rest of the penetration test. By understanding
how a website is built and what assets are exposed, pentesters can prioritize which vulnerabilities to look for and simulate
realistic cyberattacks efficiently.
