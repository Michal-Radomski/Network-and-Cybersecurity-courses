Performing a penetration test on a website requires strict adherence to legal boundaries. **You must never test a website
without explicit, written permission** from the owner, as unauthorized testing is illegal.

Professional security testers (ethical hackers) follow standardized frameworks, such as the Penetration Testing Execution
Standard (PTES) or the OWASP Testing Guide. Here is how a professional, authorized web penetration test is structured:

### 1. Scoping and Agreement (Rules of Engagement)

Before any testing begins, the tester and the website owner establish clear boundaries:

- **Target Definition:** Exactly which URLs, domains, or IP addresses are included in the test.
- **Timeframes:** When testing can occur (often outside business hours to avoid disrupting service).
- **Permissions:** Written authorization protecting the tester from legal liability.

### 2. Reconnaissance (Information Gathering)

The tester collects as much information about the target as possible using publicly available sources and non-intrusive
methods:

- **OSINT (Open Source Intelligence):** Searching for publicly exposed configuration files, employee details, or outdated
  software versions.
- **Mapping the Application:** Discovering hidden directories, admin panels, forms, and API endpoints using automated
  crawlers or manual browsing.

### 3. Vulnerability Analysis

The tester looks for known weaknesses in the application's design, code, or configuration:

- Using automated tools (like OWASP ZAP or vulnerability scanners) to flag common issues.
- Manually checking for logic flaws, weak access controls, and input validation errors.

### 4. Exploitation (Verification)

To prove whether a vulnerability is a real risk, testers attempt to safely exploit it. This phase focuses on verification
rather than causing damage:

- Testing if inputs properly sanitize data (to check for injection vulnerabilities).
- Verifying whether users can access data they shouldn't see (Broken Object Level Authorization).

### 5. Reporting and Remediation

The final and most important step of a penetration test is documentation:

- Writing a comprehensive report detailing each discovered vulnerability, its severity level, and how it was identified.
- Providing clear, actionable recommendations to the development team on how to patch and secure the code.
