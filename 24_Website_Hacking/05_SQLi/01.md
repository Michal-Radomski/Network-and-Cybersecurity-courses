## What is SQL Injection (SQLi)?

**SQL Injection (SQLi)** is a web application vulnerability that occurs when user-supplied input is directly concatenated
into a database query instead of being handled separately as data.

When an application fails to properly sanitize or parameterize input, an attacker can input specially crafted SQL syntax
(like quotes, operators, or additional query commands) to manipulate the underlying database query. This can allow attackers
to bypass login screens, view unauthorized data, modify or delete records, or in some cases, execute administrative
operations on the database server.

---

### How SQLi Typically Happens

1. **Unsafe Query Construction:** The application builds a SQL statement by pasting user input directly into the query string
   using string concatenation or template literals.
2. **Special Character Interpretation:** The database interprets parts of the user input not as plain text data, but as
   actual SQL commands.
3. **Unexpected Execution:** The database executes the modified query, returning sensitive information or performing
   unintended actions.

---

### How to Prevent SQLi in Node.js / TypeScript

The gold standard for preventing SQL injection is using **Parameterized Queries** (also known as Prepared Statements).
Parameterization ensures that the database driver treats user input strictly as literal values, never as executable code or
SQL structure.

Here is how you secure a database query using a popular Node.js PostgreSQL client (`pg`) in TypeScript:

```typescript
import { Pool } from "pg";

const pool = new Pool({
  connectionString: "postgresql://user:password@localhost:5432/mydb",
});

// SECURE: Using parameterized queries ($1, $2)
export async function getUserByUsername(username: string): Promise<any> {
  // Even if 'username' contains SQL syntax (like ' OR '1'='1),
  // the database treats it purely as a literal string search value.
  const query = "SELECT id, username, email FROM users WHERE username = $1";

  try {
    const result = await pool.query(query, [username]);
    return result.rows[0];
  } catch (error) {
    console.error("Database error:", error);
    throw error;
  }
}
```

_Note: If you are using an Object-Relational Mapper (ORM) like Prisma, TypeORM, or Sequelize, they typically use
parameterized queries out-of-the-box, protecting you from SQLi as long as you use their built-in query builders rather than
raw unescaped SQL strings._
