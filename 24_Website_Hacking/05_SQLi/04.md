### What is a Blind SQL Injection?

A **Blind SQL Injection (SQLi)** is a type of security vulnerability that occurs when a web application is vulnerable to SQL
injection, but the application does not display the results of the database query directly on the page.

In a standard SQL injection, an attacker enters malicious input and sees the direct database output or error message on the
screen. In a _blind_ attack, the application typically behaves normally, returning a generic success or failure page, making
it harder to see what is happening behind the scenes.

---

### How It Works

Even though the application doesn't show direct data, attackers can still extract information by asking the database a series
of **True/False questions** and observing how the application responds.

There are two primary types of blind SQL injection:

- **Boolean-Based (True/False) Injection:** The attacker sends a query that forces the application to return a different
  response (or page content) depending on whether a specific condition is true or false. By repeating this process character
  by character, they can deduce data like passwords or usernames.
- **Time-Based Injection:** The attacker sends a query that instructs the database to pause or wait for a specific number of
  seconds (e.g., `WAITFOR DELAY '0:0:5'`) only if a certain condition is true. If the webpage takes longer to load, the
  attacker knows their condition was correct.

---

### Why It Matters and How to Prevent It

Blind SQL injections can allow unauthorized users to access sensitive data, bypass login controls, or compromise the entire
database system over time.

Developers protect applications against blind SQL injection—and all SQL injections—by using secure coding practices:

- **Parameterized Queries (Prepared Statements):** Ensuring user input is always treated as data, never as executable code.
- **Object-Relational Mapping (ORM):** Using frameworks that naturally handle database queries safely.
- **Input Validation and Least Privilege:** Restricting database accounts to only the permissions they absolutely need.
