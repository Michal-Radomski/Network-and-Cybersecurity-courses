## What is a Content Security Policy (CSP)?

A **Content Security Policy (CSP)** is an HTTP response header that allows site administrators to declare approved sources of
content that browsers are allowed to load and execute on that page.

Think of CSP as a security guard for your browser. Even if an attacker manages to inject a malicious script into your
database (Stored XSS) or craft a malicious URL (Reflected XSS), a strict CSP prevents the browser from executing it.

---

### How CSP Defends Against XSS

1. **Blocks Inline Scripts:** By default, a strong CSP blocks inline scripts (`<script>...</script>` or `onclick="..."` event
   handlers). Attackers frequently rely on inline execution for XSS payloads.
2. **Restricts External Sources:** It specifies exact domains from which scripts, stylesheets, and images can be downloaded.
   If a script tries to load from an unauthorized external server, the browser blocks it.

---

### Configuring CSP in Node.js (Express + Helmet)

The easiest and most reliable way to implement CSP in a Node.js and Express application is by using the **Helmet**
middleware.

**Secure Code Example:**

```typescript
import express from "express";
import helmet from "helmet";

const app = express();

// Configure Helmet to set a strict Content Security Policy
app.use(
  helmet.contentSecurityPolicy({
    directives: {
      // Default fallback for all resource types
      defaultSrc: ["'self'"],

      // Only allow scripts from your own domain and trusted sources
      scriptSrc: ["'self'", "https://apis.google.com"],

      // Restrict stylesheets to your domain
      styleSrc: ["'self'", "'unsafe-inline'"], // 'unsafe-inline' should be avoided if possible

      // Prevent loading dangerous plugins like Flash
      objectSrc: ["'none'"],

      // Automatically upgrade HTTP requests to HTTPS
      upgradeInsecureRequests: [],
    },
  })
);

app.get("/", (req, res) => {
  res.send("Secure application running with CSP enabled.");
});

app.listen(3000, () => {
  console.log("Server running on port 3000");
});
```

---

### Key CSP Directives to Remember

- `defaultSrc`: The fallback policy for fetching resources if a specific directive isn't defined. Setting this to
  `[''self'']` locks down your app significantly.
- `scriptSrc`: Controls which scripts are allowed to execute. Omitting `'unsafe-inline'` completely blocks injected script
  tags.
- `objectSrc`: Usually set to `[''none'']` to disable legacy elements like `<object>`, `<embed>`, or `<applet>` which can be
  exploited.
