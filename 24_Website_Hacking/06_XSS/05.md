Preventing **Stored XSS** requires a defense-in-depth strategy. Because the malicious payload lives in your database, you
must protect your app at **two critical points**: when data is _received and saved_ on the backend, and when it is _rendered_
on the frontend.

Here is how to prevent Stored XSS in a Node.js and React application using TypeScript.

---

### 1. Sanitize and Validate on the Backend (Node.js)

Never trust user input. Even if your frontend has validation, attackers can bypass it and send requests directly to your API
(using tools like Postman).

- **Validation:** Ensure the input matches expected types and formats using a library like `express-validator`.
- **Sanitization:** Clean user-submitted text _before_ saving it to the database. For rich text, use a robust backend HTML
  sanitizer like `sanitize-html`.

**Secure Code Example (Express + TypeScript):**

```typescript
import express, { Request, Response } from "express";
import { body, validationResult } from "express-validator";
import sanitizeHtml from "sanitize-html";

const app = express();
app.use(express.json());

app.post(
  "/api/posts",
  [
    // Validate that the input is a non-empty string
    body("content").isString().trim().notEmpty(),
  ],
  async (req: Request, res: Response) => {
    const errors = validationResult(req);
    if (!errors.isEmpty()) {
      return res.status(400).json({ errors: errors.array() });
    }

    // Sanitize HTML: Strip out <script>, onclick handlers, and dangerous tags
    const cleanContent = sanitizeHtml(req.body.content, {
      allowedTags: ["b", "i", "em", "strong", "p", "br"],
      allowedAttributes: {},
    });

    // TODO: Save `cleanContent` safely to your database

    return res.status(201).json({
      success: true,
      message: "Post created safely",
      content: cleanContent,
    });
  }
);
```

---

### 2. Rely on React’s Default Escaping (Frontend)

When fetching stored data from your API to display in React, standard text content should always be rendered inside JSX
variables (`{data}`). React automatically escapes strings, converting dangerous symbols into safe text.

**Secure Code Example:**

```tsx
import React from "react";

interface PostViewProps {
  content: string;
}

export const PostView: React.FC<PostViewProps> = ({ content }) => {
  // React treats `content` as plain text, neutralizing any stored scripts
  return (
    <div className="post-card">
      <p>{content}</p>
    </div>
  );
};
```

---

### 3. Safely Render Stored Rich-Text in React

If your application allows users to store formatted content (like Markdown or HTML comments) and you _must_ render it as
HTML, sanitize it on the client side using **DOMPurify** right before rendering.

**Secure Code Example:**

```tsx
import React from "react";
import DOMPurify from "dompurify";

interface RichPostProps {
  storedHtmlContent: string;
}

export const RichPostView: React.FC<RichPostProps> = ({ storedHtmlContent }) => {
  // Double-sanitize stored content as an extra layer of defense
  const safeHtml = DOMPurify.sanitize(storedHtmlContent);

  return <div className="rich-content" dangerouslySetInnerHTML={{ __html: safeHtml }} />;
};
```

---

### Summary Checklist for Stored XSS

- **Validate** all incoming request bodies in Node.js.
- **Sanitize** HTML input using libraries like `sanitize-html` before database insertion.
- **Escape** output automatically by rendering data via React JSX (`{variable}`).
- **Sanitize again** using `DOMPurify` if rendering stored rich HTML.
