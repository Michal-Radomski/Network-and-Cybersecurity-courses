## What is DOM-Based XSS?

**DOM-Based XSS (Document Object Model XSS)** is an attack where the vulnerability exists entirely in client-side code rather
than on the server. It happens when JavaScript in the web page reads data from an untrusted source (known as the **source**,
such as `window.location.search`, `window.location.hash`, or `document.referrer`) and passes that data into an unsafe sink
(such as `element.innerHTML`, `document.write()`, or executing it via `eval()`).

Unlike Reflected or Stored XSS, the server might not even see the malicious payload because it is processed entirely within
the victim's browser via the DOM.

---

### How DOM-Based XSS Works

1. **The Source:** An attacker crafts a malicious URL containing JavaScript in a query parameter or hash fragment (e.g.,
   `[https://example.com/search?q=](https://example.com/search?q=)<script>alert('XSS')</script>`).
2. **The Execution Flow:** The victim clicks the link. The client-side JavaScript script extracts the value from
   `window.location.search`.
3. **The Unsafe Sink:** Instead of treating the value as plain text, the frontend code takes that raw value and inserts it
   directly into the DOM using an unsafe method (like setting `innerHTML`).
4. **The Attack:** The browser executes the injected script within the context of the user's active session.

---

### How to Prevent DOM-Based XSS in React & Node.js

Because DOM-based XSS relies on unsafe client-side handling, the primary defenses happen in your frontend React code, backed
by strong HTTP headers from your Node.js server.

#### 1. Avoid Unsafe DOM Sinks in React

Never use native DOM manipulation methods (like `document.getElementById('id').innerHTML = ...`) or raw script evaluation
based on URL parameters. Rely on React's declarative state and JSX, which safely escapes variables.

**Secure Code Example (React + TypeScript):**

```tsx
import React from "react";
import { useSearchParams } from "react-router-dom";

export const SafeSearchComponent: React.FC = () => {
  // Use a router hook to safely extract search parameters
  const [searchParams] = useSearchParams();
  const query = searchParams.get("q") || "";

  // React automatically escapes the `query` variable, preventing DOM XSS
  return (
    <div>
      <h1>Search Results</h1>
      <p>You searched for: {query}</p>
    </div>
  );
};
```

#### 2. Sanitize if Raw HTML is Unavoidable

If your application must read user-controlled data from URL fragments or local storage and render it as HTML, sanitize it
client-side using **DOMPurify** before passing it to a sink like `dangerouslySetInnerHTML`.

**Secure Code Example (DOMPurify in React):**

```tsx
import React from "react";
import DOMPurify from "dompurify";

export const HashContentRenderer: React.FC = () => {
  // Reading from window.location.hash (an untrusted source)
  const rawHash = window.location.hash.substring(1);

  // Sanitize immediately before rendering
  const cleanHtml = DOMPurify.sanitize(rawHash);

  return <div dangerouslySetInnerHTML={{ __html: cleanHtml }} />;
};
```

#### 3. Enforce a Content Security Policy (CSP) in Node.js

A strong **Content Security Policy (CSP)** configured on your Node.js backend acts as a crucial safety net. It restricts
inline script execution and ensures that scripts can only be loaded from trusted domains, mitigating the impact if
client-side code accidentally processes a dangerous sink.

**Secure Code Example (Express + Helmet):**

```typescript
import express from "express";
import helmet from "helmet";

const app = express();

// Set up a strict CSP header
app.use(
  helmet.contentSecurityPolicy({
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'"], // Blocks inline scripts and malicious injected payloads
      objectSrc: ["'none'"],
    },
  })
);
```
