Preventing **Reflected Cross-Site Scripting (XSS)** in a React and Node.js application requires a combination of React’s
built-in rendering protections, secure Node.js handling, and robust HTTP headers. Reflected XSS occurs when malicious input
(often via URL query parameters) is immediately echoed back by the server or client without proper sanitization or escaping.

Here is a practical guide with secure TypeScript code snippets to protect your application.

---

### 1. Leverage React’s Built-In JSX Escaping (Frontend)

By default, React escapes any values embedded in JSX (`{variable}`) before rendering them. This turns dangerous characters
like `<` or `>` into safe strings, neutralizing most XSS attacks automatically.

**Secure Code Example:**

```tsx
import React from "react";

interface SearchResultProps {
  query: string;
}

export const SearchResult: React.FC<SearchResultProps> = ({ query }) => {
  // React automatically escapes 'query', preventing injected scripts from executing
  return (
    <div className="search-results">
      <h2>Search results for: {query}</h2>
    </div>
  );
};
```

---

### 2. Safely Handle `dangerouslySetInnerHTML`

If your application _must_ render raw HTML from user input or an API, never insert it directly. Always sanitize the content
using a trusted library like **DOMPurify** before passing it to `dangerouslySetInnerHTML`.

**Secure Code Example:**

```tsx
import React from "react";
import DOMPurify from "dompurify";

interface RichTextProps {
  rawHtmlContent: string;
}

export const SafeHtmlRenderer: React.FC<RichTextProps> = ({ rawHtmlContent }) => {
  // Sanitize input to strip out malicious scripts and event handlers
  const cleanHtml = DOMPurify.sanitize(rawHtmlContent);

  return <div dangerouslySetInnerHTML={{ __html: cleanHtml }} />;
};
```

---

### 3. Secure Node.js & Express Responses

If your Node.js backend performs Server-Side Rendering (SSR) or returns user-controlled query parameters directly in HTML
templates, it is vulnerable to reflected XSS.

- **Best Practice:** Separate your API from your frontend. Return **JSON** data (`res.json()`) rather than rendering raw HTML
  strings on the server. The browser will treat JSON as data, not executable code.

**Secure Code Example (Express + TypeScript):**

```typescript
import express, { Request, Response } from "express";

const app = express();

app.get("/api/search", (req: Request, res: Response) => {
  const searchQuery = (req.query.q as string) || "";

  // Returning JSON prevents the browser from interpreting the string as HTML/JS
  res.json({
    success: true,
    query: searchQuery,
    results: [],
  });
});
```

---

### 4. Implement a Content Security Policy (CSP)

A strong Content Security Policy acts as a defense-in-depth layer. It restricts where scripts can be loaded from and blocks
inline script execution. You can easily configure this in Node.js using **Helmet**.

**Secure Code Example (Express + Helmet):**

```typescript
import express from "express";
import helmet from "helmet";

const app = express();

// Configure Helmet with a strict Content Security Policy
app.use(
  helmet.contentSecurityPolicy({
    directives: {
      defaultSrc: ["'self'"],
      scriptSrc: ["'self'"], // Only allow scripts from your own domain
      objectSrc: ["'none'"],
      upgradeInsecureRequests: [],
    },
  })
);
```
