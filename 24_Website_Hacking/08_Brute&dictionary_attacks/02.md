Protecting a Node.js and React application against brute force and dictionary attacks involves implementing security controls
on both the server and client sides.

---

### 1. Backend: Rate Limiting (Express)

Rate limiting restricts the number of times a user (identified by their IP address) can hit a specific endpoint (like
`/api/login`) within a given time window. You can easily implement this using the `express-rate-limit` package.

```typescript
import express, { Request, Response } from "express";
import rateLimit from "express-rate-limit";

const app = express();

// Create a rate limiter for login routes
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 minutes
  max: 5, // Limit each IP to 5 login requests per windowMs
  message: { error: "Too many login attempts from this IP, please try again after 15 minutes." },
  standardHeaders: true, // Return rate limit info in the `RateLimit-*` headers
  legacyHeaders: false, // Disable the `X-RateLimit-*` headers
});

// Apply the rate limiter specifically to the login route
app.post("/api/login", loginLimiter, (req: Request, res: Response) => {
  // Handle login logic here
  res.json({ message: "Login attempt received" });
});
```

---

### 2. Account Lockout Policies

In addition to IP-based rate limiting, track failed login attempts per **user account** in your database:

- If a specific user account accumulates 5 consecutive failed login attempts, temporarily lock the account (e.g., for 30
  minutes) or require an email verification link to unlock it.
- This prevents attackers from bypassing IP rate limiters by using distributed botnets (multiple IPs).

### 3. Frontend: CAPTCHA Integration (React)

When an attacker automates a script, they cannot easily solve visual puzzles. You can integrate a service like **Google
reCAPTCHA**, **hCaptcha**, or **Turnstile** into your React login form.

- **Adaptive CAPTCHA:** Trigger the CAPTCHA only after 2 or 3 failed login attempts to keep the user experience smooth for
  legitimate users.

```tsx
import React, { useState } from "react";
import HCaptcha from "@hcaptcha/react-hcaptcha";

export const LoginForm: React.FC = () => {
  const [captchaToken, setCaptchaToken] = useState<string | null>(null);
  const [failedAttempts, setFailedAttempts] = useState(0);

  const handleLogin = async (e: React.FormEvent) => {
    e.preventDefault();
    // Send email, password, and captchaToken to the backend
  };

  return (
    <form onSubmit={handleLogin}>
      <input type="email" placeholder="Email" required />
      <input type="password" placeholder="Password" required />

      {/* Show CAPTCHA after multiple failed attempts */}
      {failedAttempts >= 2 && <HCaptcha sitekey="your-hcaptcha-site-key" onVerify={(token) => setCaptchaToken(token)} />}

      <button type="submit">Log In</button>
    </form>
  );
};
```

### 4. Enforce Multi-Factor Authentication (MFA)

Even if an automated script guesses a user's password through a dictionary attack, **Multi-Factor Authentication (MFA)**
stops them cold. Requiring a time-based one-time password (TOTP) from an app like Google Authenticator ensures that a stolen
password alone is not enough to gain entry.
