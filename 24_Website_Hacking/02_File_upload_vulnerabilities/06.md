In Node.js, the industry standard and most secure library for image processing is **Sharp**. Like the PHP GD library example,
re-encoding an image with Sharp automatically strips out EXIF metadata and drops any non-image data (such as appended
scripts) because it parses the raw pixel data and generates a brand-new file.

Here is how you can do it using TypeScript and **Sharp**:

---

### Prerequisites

First, install the `sharp` library in your Node.js project:

```bash
npm install sharp
npm install --save-dev @types/node

```

---

### TypeScript Implementation

```typescript
import sharp from "sharp";
import path from "path";

/**
 * Sanitizes and re-encodes an uploaded image to strip metadata and malicious payloads.
 *
 * @param inputPath Path to the temporary uploaded file
 * @param outputPath Path where the clean image should be saved
 * @param mimeType The MIME type of the uploaded file
 */
export async function sanitizeAndProcessImage(inputPath: string, outputPath: string, mimeType: string): Promise<void> {
  try {
    const imageProcessor = sharp(inputPath);

    // Check format and re-encode to strip metadata and non-image data
    if (mimeType === "image/jpeg") {
      await imageProcessor
        .jpeg({ quality: 90 }) // Re-encodes as JPEG
        .toFile(outputPath);
    } else if (mimeType === "image/png") {
      await imageProcessor
        .png({ compressionLevel: 9 }) // Re-encodes as PNG
        .toFile(outputPath);
    } else if (mimeType === "image/webp") {
      await imageProcessor
        .webp({ quality: 90 }) // Re-encodes as WebP
        .toFile(outputPath);
    } else {
      throw new Error("Unsupported image format.");
    }

    console.log("Image successfully sanitized and re-encoded.");
  } catch (error) {
    // If Sharp fails to parse the file, it throws an error (e.g., fake image / corrupted payload)
    throw new Error("Invalid image file. Processing failed.");
  }
}
```

---

### Why Sharp is Recommended

- **Automatic Metadata Stripping:** By default, Sharp strips all EXIF, IPTC, and XMP metadata during the re-encoding process.
- **Security Against Exploits:** If someone uploads a text file or a script renamed to `.jpg`, Sharp will fail to decode it
  as an image and throw an exception, preventing the file from being saved as a valid asset.
- **Performance:** Sharp is built on top of the high-performance `libvips` C library, making it significantly faster than
  pure JavaScript alternatives.
