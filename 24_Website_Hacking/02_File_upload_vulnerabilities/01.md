### What is a File Upload Vulnerability?

A **file upload vulnerability** occurs when a web application allows users to upload files to its server without properly
validating or restricting them. If an application fails to check properties like file type, size, or content, it can allow
malicious files to be stored on the server.

---

### Potential Risks and Impacts

When file upload mechanisms are poorly secured, the consequences can range from minor disruptions to a complete compromise of
the system:

- **Remote Code Execution (RCE):** If an attacker uploads executable code (such as a script file) and the server is
  configured to run it, they may gain unauthorized control over the server.
- **Denial of Service (DoS):** Without file size or storage limits, users or attackers could flood the server with massive or
  numerous files, exhausting storage space and crashing the application.
- **Stored Cross-Site Scripting (XSS):** Uploading files that contain scripts (like certain image or document formats) can
  cause malicious code to execute in other users' browsers when they view the file.
- **Path Overwriting:** Poorly handled filenames can sometimes allow files to be written to unintended directories,
  overwriting critical application configuration files.

---

### Why Do They Happen?

- **Relying Solely on Client-Side Checks:** Validating file extensions using only browser-side code (like JavaScript) can be
  easily bypassed.
- **Trusting User-Controlled Headers:** Relying entirely on HTTP headers (like the `Content-Type` sent by the browser)
  without verifying the actual file contents can lead to spoofing.
- **Insecure File Storage:** Storing uploaded files directly inside the web root directory where the server can directly
  execute scripts.

---

### Prevention and Best Practices

Securing file upload features involves implementing strict, server-side defenses:

- **Whitelist Allowed Extensions:** Explicitly define which file extensions are permitted (e.g., `.jpg`, `.png`) rather than
  trying to blacklist dangerous ones.
- **Rename Uploaded Files:** Automatically assign a unique, randomly generated name (such as a UUID or cryptographic hash) to
  uploaded files to prevent predictable paths and direct script execution.
- **Enforce Size Limits:** Restrict the maximum file size and total upload volume to prevent storage exhaustion.
- **Isolate Storage:** Store uploaded files outside of the main web root directory or on a separate dedicated storage domain.
- **Verify File Content:** Check internal file signatures (magic bytes) rather than just looking at the file extension or
  headers.
