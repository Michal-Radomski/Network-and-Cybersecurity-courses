## How SameSite Cookies Eliminate Manual CSRF Tokens

The `SameSite` cookie attribute is a powerful browser-level defense that can completely eliminate the need for manual CSRF
tokens in many modern web applications.

---

### How `SameSite` Works

When you set a cookie, you can configure its `SameSite` attribute to one of two security levels:

- **`SameSite=Strict`:** The browser will **never** send the cookie on cross-site requests. For example, if a user is on a
  malicious website (`evil.com`) and clicks a link or triggers a background form pointing to your app, the session cookie is
  withheld. It is only sent when the request originates directly from your own domain.
- **`SameSite=Lax`:** The browser withholds cookies on cross-site subrequests (like images, iframes, or JavaScript `fetch`
  calls), but **allows** the cookie to be sent when a user navigates to your site via a standard top-level link (e.g.,
  clicking a link on a blog). This provides a good balance of security and usability.

---

### Why It Eliminates CSRF Tokens

1. **The Core CSRF Problem:** CSRF attacks succeed because browsers automatically attach user session cookies to _every_
   request directed at the target domain, regardless of where the request originated.
2. **The `SameSite` Solution:** By setting `SameSite=Strict` or `SameSite=Lax`, you tell the browser: _"Do not attach this
   cookie if the request is coming from an external website."_
3. **Result:** Because the malicious site cannot trick the browser into sending the session cookie, the server receives an
   unauthenticated request and rejects it. The attack fails natively, removing the need to generate, store, and validate
   separate CSRF tokens.

---

> **Note:** While `SameSite` provides robust protection, it is often best used as a defense-in-depth strategy alongside
> proper CORS configuration and secure session management.
