## Understanding CSRF Vulnerabilities

Cross-Site Request Forgery (CSRF) is an attack that forces an authenticated user to execute unwanted actions on a web
application where they are currently logged in. Because browsers automatically attach user credentials (such as session
cookies) to cross-origin requests, the target server processes the command, falsely assuming the legitimate user authorized
it.

---

## How CSRF Attacks Happen

- **Authentication State:** The victim is logged into a trusted web application (e.g., an online store or banking portal).
- **Malicious Trigger:** The user visits an untrusted or compromised website containing a hidden form or script.
- **Automatic Cookie Inclusion:** The malicious site sends a request to your app, and the browser automatically includes the
  victim's valid session cookie.
- **Unauthorized Execution:** The server receives the request with valid credentials and performs the state-changing action
  (like changing an email or transferring funds).

---

## Preventing CSRF in Node.js & Express

- **Configure SameSite Cookies:** Set session cookies with `sameSite: 'strict'` or `sameSite: 'lax'` to prevent browsers from
  sending cookies along with cross-site requests.
- **Use CSRF Tokens:** Implement the Synchronizer Token Pattern by generating a unique, cryptographically secure token on the
  server for each session.
- **Validate Request Headers:** Require state-changing requests (POST, PUT, DELETE) to include the CSRF token, verifying it
  against the token stored in the user's server session.

---

## Integrating CSRF Protection in React

- **Retrieve the Token:** Fetch the CSRF token from the server upon initial app load or store it securely in application
  state.
- **Attach Custom Headers:** Configure your HTTP client (like Axios) to send the token back in a custom header (such as
  `X-CSRF-Token`) on every mutation request.
