**802.1X** is an IEEE standard for **port-based Network Access Control (NAC)**. It provides an authentication mechanism for
devices wishing to connect to a Local Area Network (LAN) or Wireless LAN (WLAN), ensuring that only authorized users and
devices gain access to the network infrastructure.

---

### Key Components of 802.1X

The 802.1X architecture relies on a strict tripartite framework, commonly referred to as the **authenticator, supplicant, and
authentication server model**:

- **Supplicant:** The client device (e.g., laptop, IP phone, smartphone) attempting to connect to the network. It runs client
  software that responds to requests from the authenticator.
- **Authenticator:** The network device managing the physical or logical port connection—typically a managed switch, wireless
  access point (WAP), or router. It acts as an intermediary, passing information between the supplicant and the
  authentication server.
- **Authentication Server:** Usually a RADIUS (Remote Authentication Dial-In User Service) server (such as FreeRADIUS,
  Microsoft NPS, or Cisco ISE). It maintains the database of user credentials and makes the final decision on whether to
  grant or deny network access.

---

### How 802.1X Works (The Authentication Flow)

1. **Unauthenticated State:** When a device plugs into a switch port or associates with a Wi-Fi network, the port is placed
   in an "uncontrolled" or unauthorized state. Only 802.1X traffic (Extensible Authentication Protocol over LAN, or
   **EAPOL**) is allowed through.
2. **Initiation:** The authenticator or the supplicant initiates the authentication process by sending an
   EAP-Request/Identity frame.
3. **Credential Exchange:** The supplicant responds with its identity, which the authenticator packages and forwards to the
   RADIUS authentication server.
4. **Backend Authentication:** The authenticator and RADIUS server negotiate an **EAP (Extensible Authentication Protocol)**
   method (e.g., EAP-TLS, PEAP, EAP-TTLS). The server challenges the supplicant for credentials (passwords, certificates, or
   tokens).
5. **Authorization & Port State Change:** \* If the credentials are valid, the RADIUS server sends an **Access-Accept**
   message to the authenticator.

- The authenticator shifts the switch port or wireless connection to an **authorized state**, allowing normal network traffic
  (IP traffic, DHCP, internet access) to flow.
- If authentication fails, an **Access-Reject** message is sent, and the port remains blocked.

---

### Common EAP Methods Used with 802.1X

Because 802.1X relies on EAP to transport authentication data securely, several underlying methods are commonly deployed:

- **EAP-TLS (Transport Layer Security):** The most secure method. It requires both the client and the authentication server
  to have digital certificates for mutual authentication.
- **PEAP (Protected EAP):** Uses a TLS tunnel established by the server to protect a secondary inner authentication method
  (such as MSCHAPv2, which uses username/passwords).
- **EAP-TTLS (Tunneled Transport Layer Security):** Similar to PEAP, creating a secure tunnel to validate user credentials
  against legacy databases.

---

### Benefits of 802.1X

- **Enhanced Security:** Prevents rogue devices and unauthorized users from plugging into office network jacks or connecting
  to corporate Wi-Fi.
- **Dynamic Access Control:** Integrates with VLAN assignment policies. Once authenticated, a user or device can
  automatically be placed into a specific VLAN (e.g., Guest, IoT, Finance, or Engineering) based on their credentials.
- **Centralized Management:** Credentials and access policies are managed centrally on the RADIUS server rather than
  configured individually on every switch or access point.
