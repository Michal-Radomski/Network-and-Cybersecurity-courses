## Overview of 802.11 Security and Privacy

Because wireless networks transmit data via radio waves through the air, anyone within range can theoretically intercept the
traffic. To address these inherent vulnerabilities, the IEEE 802.11 wireless standard has undergone decades of evolution to
protect user privacy, authenticate network devices, and encrypt data payloads.

---

## 1. The Evolution of Wi-Fi Security Protocols

The security architecture of Wi-Fi has progressed through several generations to fix foundational flaws present in earlier
standards:

| Protocol                             | Era / Status                | Encryption Cipher                                 | Authentication Method                         | Major Vulnerabilities / Issues                                                                                           |
| ------------------------------------ | --------------------------- | ------------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **WEP** _(Wired Equivalent Privacy)_ | 1997 / **Deprecated**       | RC4 (40-bit or 104-bit)                           | Open System / Shared Key                      | Short Initialization Vectors (IVs) caused rapid key reuse; trivial to crack in minutes.                                  |
| **WPA** _(Wi-Fi Protected Access)_   | 2003 / **Deprecated**       | RC4 with TKIP _(Temporal Key Integrity Protocol)_ | Pre-Shared Key (PSK) or 802.1X                | Served as a temporary patch; still relied on the flawed RC4 cipher.                                                      |
| **WPA2**                             | 2004 / **Widely Used**      | AES with CCMP                                     | Pre-Shared Key (PSK) or 802.1X                | Vulnerable to offline dictionary attacks on weak passwords; optional PMF left networks open to deauthentication attacks. |
| **WPA3**                             | 2018 / **Current Standard** | AES (128-bit or 192-bit CNSA suite)               | SAE _(Simultaneous Authentication of Equals)_ | Most robust standard to date, designed to mitigate brute-force and dictionary attacks.                                   |

## 2. Key Privacy and Security Mechanisms

### A. Authentication and Handshake Security

- **WPA2-Personal (PSK):** Utilized a 4-way handshake to establish session keys from a shared password. If an attacker
  captured this handshake over the air, they could attempt to guess the password offline using brute-force dictionary
  attacks.
- **WPA3-Personal (SAE):** Replaces the standard PSK model with **Simultaneous Authentication of Equals (SAE)**, derived from
  the Dragonfly key exchange. SAE ensures that a password cannot be guessed via offline attacks because an attacker cannot
  passively record a single handshake and crack it later—they must actively interact with the network for each guess.
- **Forward Secrecy:** WPA3 introduces forward secrecy, ensuring that even if an attacker discovers a network's long-term
  password later, they cannot decrypt previously captured session traffic.

### B. Data Encryption

- **CCMP (Counter Mode with Cipher Block Chaining Message Authentication Code Protocol):** Standardized under WPA2 using the
  Advanced Encryption Standard (AES), providing strong data confidentiality and integrity.
- **Individualized Data Encryption:** On open or public Wi-Fi networks (using features like WPA3 Enhanced Open /
  Opportunistic Wireless Encryption), WPA3 encrypts the traffic link between each individual client and the access point,
  preventing casual snooping on public hotspots even without a password.

### C. Management Frame Protection (802.11w / PMF)

Older 802.11 networks transmitted management frames (like disassociation and deauthentication commands) in plain text. This
allowed attackers to spoof frames and forcefully kick users off a network. WPA3 **mandates Protected Management Frames
(PMF)**, cryptographically signing these management packets to prevent denial-of-service deauthentication attacks.

---

## 3. Enterprise Security: 802.1X

For large corporate and campus environments, personal pre-shared keys are insufficient.

- **802.1X Framework:** Leverages an external Authentication, Authorization, and Accounting (AAA) server—typically using
  **RADIUS**—to authenticate individual users or devices.
- **Extensible Authentication Protocol (EAP):** Provides various methods for credential verification (such as smart cards,
  certificates via EAP-TLS, or credentials via PEAP).
- **WPA3-Enterprise 192-bit Mode:** Meets high-security standards (such as government and defense guidelines) by enforcing
  strict cryptographic rules, mandatory server certificate validation to prevent "evil twin" rogue access points, and AES-256
  encryption.
