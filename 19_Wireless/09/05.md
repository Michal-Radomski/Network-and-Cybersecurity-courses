## Promiscuous Mode vs. Monitor Mode

While both **Promiscuous Mode** and **Monitor Mode** are settings used by network cards to capture traffic that isn’t
specifically addressed to your device, they operate at different layers of the network and serve entirely different purposes.

---

## 1. Promiscuous Mode (Wired & Wireless Layer 2)

Promiscuous mode is a configuration typically used on **wired Ethernet networks** (though it can apply to virtual or wireless
interfaces under certain setups). Normally, a network interface card (NIC) only processes frames addressed directly to its
own MAC address, dropping everything else.

- **How it works:** When a NIC is put into promiscuous mode, the operating system instructs the card to pass **all** traffic
  it sees on the network segment up to the CPU for analysis, regardless of the destination MAC address.
- **Scope:** In a traditional wired hub environment (or a switched environment utilizing port mirroring/SPAN ports), it
  captures all unicast, multicast, and broadcast frames flowing through that specific network segment.
- **Primary Use Cases:** Network troubleshooting, intrusion detection systems (IDS), and analyzing traffic patterns on
  switched networks.

---

## 2. Monitor Mode (Wireless Layer 1 & 2)

Monitor mode (sometimes called **RF monitor mode**) is exclusive to **wireless network cards**. It goes a step further than
promiscuous mode by shifting how the hardware interacts with the physical radio waves.

- **How it works:** In normal operation, a Wi-Fi card is "associated" with a specific Access Point (AP) on a single channel,
  and it only listens to frames intended for its network. In monitor mode, the card detaches from any network, stops
  transmitting, and listens passively to **all radio frequency traffic** on a chosen channel.
- **Scope:** It captures raw 802.11 wireless frames—including Management frames (beacons, probes, de-authentication), Control
  frames (RTS/CTS), and Data frames—from _any_ network broadcasting on that channel within range, regardless of the SSID or
  encryption used.
- **Primary Use Cases:** Wireless site surveys, passive sniffing (via tools like Kismet), and capturing 4-way handshakes for
  security audits (via tools like Aircrack-ng).

---

## Quick Comparison

| Feature                     | Promiscuous Mode                                                | Monitor Mode                                                                                              |
| --------------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| **Primary Medium**          | Wired (Ethernet) & Virtual interfaces                           | Wireless (Wi-Fi Radio Frequencies)                                                                        |
| **OSI Layer**               | Layer 2 (Data Link Layer)                                       | Layer 1 & 2 (Physical & Data Link Layers)                                                                 |
| **Association Requirement** | Often needs to be connected/bridged to a network switch or hub. | Must **disassociate** from any network; acts strictly as a passive listener.                              |
| **Frame Types Captured**    | Standard Ethernet frames (unicast, multicast, broadcast).       | Raw 802.11 wireless frames (Management, Control, and Data frames).                                        |
| **Hardware Support**        | Supported by almost all standard Ethernet NICs.                 | Requires specialized wireless NICs and drivers that explicitly support monitor mode and packet injection. |
