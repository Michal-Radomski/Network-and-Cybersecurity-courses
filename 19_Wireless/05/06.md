The **4-Way Handshake** is a critical security process used in Wi-Fi networks (specifically WPA2 and WPA3) to securely
establish a connection between a wireless client (like your phone or laptop) and an access point (your router).

Its main purpose is twofold: **prove that both parties possess the correct master key** (without ever revealing the actual
password over the air) and **generate fresh, unique session keys** to encrypt all your future data.

---

### The Prerequisites

Before the handshake even starts, two things must happen:

1. **Authentication:** The device connects to the network (either via a shared password in Personal mode or a RADIUS server
   in Enterprise mode).
2. **PMK Generation:** Both the router and the client derive a foundational secret called the **PMK (Pairwise Master Key)**
   from that initial login. The PMK is never used directly to encrypt data.

---

### The 4 Steps of the Handshake

During the handshake, the router and client exchange four sequential messages, using random numbers called **nonces**
(Non-cees) to ensure each session is entirely unique.

- **Message 1: Access Point $\rightarrow$ Client (Anonce)**
- The router sends a random number it generated (called **ANonce**) to the client.
- _What happens:_ The client now has its own password derivation (PMK), the router's random number (ANonce), and its own
  random number (SNonce). It combines these to generate the **PTK (Pairwise Transient Key)**, which is the actual session key
  used to encrypt data.

- **Message 2: Client $\rightarrow$ Access Point (SNonce + MIC)**
- The client sends its own random number (**SNonce**) back to the router, along with a **MIC (Message Integrity Code)** to
  prove it holds the correct PMK.
- _What happens:_ The router now has all the ingredients to generate the exact same **PTK**. It verifies the MIC to ensure
  the client’s password is correct. If the MIC fails, the connection is dropped.

- **Message 3: Access Point $\rightarrow$ Client (GTK + MIC)**
- The router sends confirmation back to the client, along with the **GTK (Group Temporal Key)**, which is used for broadcast
  and multicast traffic (like network discovery). It also includes a MIC to prove the router is legitimate.
- _What happens:_ The client verifies the router's message and installs the PTK for unicast traffic and the GTK for group
  traffic.

- **Message 4: Client $\rightarrow$ Access Point (Acknowledgment)**
- The client sends a final confirmation message back to the router.
- _What happens:_ Once the router receives this, the handshake is complete, and encrypted data transmission can safely begin.
