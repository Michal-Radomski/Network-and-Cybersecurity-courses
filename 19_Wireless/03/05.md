When discussing **TKIP** (Temporal Key Integrity Protocol) in the context of an **MPDU** (MAC Protocol Data Unit), it refers
to how the protocol modifies, encapsulates, and secures a standard wireless data frame.

TKIP adds a total of **20 bytes of overhead** to every standard IEEE 802.11 MPDU to enforce per-packet encryption, message
integrity, and anti-replay protection.

---

### Structure of a TKIP-Encapsulated MPDU

When a data packet travels through a TKIP-enabled Wi-Fi link, the payload and header are expanded with specialized security
fields before transmission:

```
+-------------------+-------------------+-------------------+-------------------+--------------------+
| 802.11 MAC Header |    TKIP Header    |    Payload (MSDU) |      MIC          |      ICV           |
|    (30 Bytes)     |     (8 Bytes)     |   (Variable)      |    (8 Bytes)      |    (4 Bytes)       |
+-------------------+-------------------+-------------------+-------------------+--------------------+

```

#### 1. 802.11 MAC Header (Standard)

- Contains standard layer-2 addressing details, including the Frame Control, Duration/ID, Receiver Address (RA), Transmitter
  Address (TA), and Sequence Control.

#### 2. TKIP Header (8 Bytes Added)

TKIP splits this section into two distinct 4-byte parts to handle sequence counting and initialization vector (IV)
requirements without breaking legacy architecture:

- **Extended Initialization Vector (Extended IV - 4 bytes):** Contains the upper bits of the 48-bit TKIP Sequence Counter
  (TSC). This counter prevents **replay attacks** by ensuring that old packets cannot be captured and resent to the network.
- **WEP Initialization Vector (IV - 4 bytes):** Contains the lower sequence counter values and flags required to seed the
  legacy RC4 stream cipher engine.

#### 3. Payload / MSDU (MAC Service Data Unit)

- The actual data frame or user payload being transmitted across the wireless medium.

#### 4. Message Integrity Check / "Michael" (8 Bytes Added)

- Known widely as **Michael**, this cryptographic checksum calculates a hash over the destination address, source address,
  priority, and payload data.
- **Purpose:** It protects the packet against tampering, bit-flipping, and forgery. If an attacker tries to alter the packet
  in transit, the MIC check will fail.

#### 5. Integrity Check Value / ICV (4 Bytes Added)

- Inherited from the original WEP design, this is a standard 32-bit Cyclic Redundancy Check (CRC-32) placed at the very end
  of the frame body to catch transmission errors alongside the primary Frame Check Sequence (FCS).

---

### How the TKIP MPDU Processing Works

1. **Key Mixing:** Before encryption, TKIP takes the base 128-bit Temporal Key (TK), mixes it with the Transmitter Address
   (TA), and combines it with the 48-bit **TKIP Sequence Counter (TSC)** using a rigorous two-phase mixing function. This
   generates a unique, dynamic per-packet key.
2. **Integrity Check:** The **Michael MIC** is appended to the MSDU data.
3. **Encryption:** The combined payload, MIC, and ICV are encrypted using the RC4 stream cipher driven by the per-packet key.
4. **Header Attachment:** The TKIP Header (IV and Extended IV) is prepended, and the standard 802.11 MAC header wraps the
   front of the frame before it is converted into a physical layer transmission.
