### What are Stream and Block Ciphers?

In cryptography, encryption algorithms are divided into two main categories based on how they process input data (plaintext):
**Stream Ciphers** and **Block Ciphers**. Both are fundamental building blocks used to secure data, but they handle
information differently.

---

### Stream Ciphers

A **stream cipher** encrypts data one digital data unit (usually a single byte or bit) at a time.

- **How it works:** The cipher takes a secret key and combines it with an **Initialization Vector (IV)** or counter using a
  pseudo-random number generator (PRNG) to create a keystream. This keystream is then combined with the plaintext (usually
  using a bitwise XOR operation) to produce the ciphertext.
- **Key Characteristic:** The encryption key changes or shifts with every bit or byte processed. The stream of bits generated
  depends on the state of the cipher at that exact moment.
- **Common Examples:** **RC4** (used in legacy WEP), **ChaCha20** (widely used in modern secure protocols like TLS and
  WireGuard).
- **Pros & Cons:** \* _Pros:_ Very fast, highly efficient for continuous or real-time data streams (like audio/video
  streaming or VoIP), and requires minimal processing power.
- _Cons:_ If a key and IV are ever reused, an attacker can easily decrypt the messages (as seen historically with WEP).

---

### Block Ciphers

A **block cipher** encrypts data in fixed-size blocks (groups of bits) rather than processing individual bits continuously.

- **How it works:** The algorithm takes a fixed-length block of plaintext (for example, 128 bits) and a secret key, then
  applies a complex series of mathematical operations (substitutions and permutations) across multiple rounds to transform it
  into a ciphertext block of the exact same size.
- **Key Characteristic:** If the final block of data is shorter than the required block size, it must undergo **padding**
  (adding extra dummy data to fill the block) before encryption.
- **Common Examples:** **AES** (Advanced Encryption Standard, using 128-bit blocks), **3DES** (Triple Data Encryption
  Standard).
- **Pros & Cons:** \* _Pros:_ Extremely secure when implemented correctly; handles large files, databases, and stored data
  very effectively.
- _Cons:_ Slower than stream ciphers for real-time data streams because it has to wait for an entire block of data to
  accumulate before encrypting.

---

### Key Differences at a Glance

| Feature               | Stream Cipher                                        | Block Cipher                                 |
| --------------------- | ---------------------------------------------------- | -------------------------------------------- |
| **Processing Unit**   | Bit by bit (or byte by byte)                         | Fixed-size blocks (e.g., 64 or 128 bits)     |
| **Speed**             | Generally faster                                     | Slower (requires waiting for full blocks)    |
| **Memory Usage**      | Low memory footprint                                 | Higher memory usage (buffers blocks)         |
| **Error Propagation** | An error usually corrupts only the affected bit/byte | An error can corrupt an entire block of data |
| **Best Used For**     | Real-time communication, secure sockets (TLS/SSL)    | Stored data, file encryption, databases      |

---

### Modes of Operation for Block Ciphers

Because block ciphers only encrypt fixed-size chunks, using them on large files requires a **mode of operation** to determine
how multiple blocks are linked together. Common modes include:

- **ECB (Electronic Codebook):** Encrypts each block independently. _Insecure_ because identical plaintext blocks produce
  identical ciphertext blocks, revealing patterns in data.
- **CBC (Cipher Block Chaining):** XORs each plaintext block with the previous ciphertext block before encrypting, making
  identical blocks encrypt differently.
- **GCM (Galois/Counter Mode):** A widely used modern mode that turns a block cipher into a stream cipher, providing both
  high-speed encryption and built-in data authentication.
