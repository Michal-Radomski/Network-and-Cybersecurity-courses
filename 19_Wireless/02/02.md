### Wired Equivalent Privacy (WEP)

**Wired Equivalent Privacy (WEP)** is a legacy security protocol introduced in the original 1997 IEEE 802.11 wireless
standard. Its primary goal was to provide wireless local area networks (WLANs) with the same level of confidentiality and
privacy security expected on a physical, wired Ethernet cable.

- **Encryption Algorithm:** WEP relies on the **RC4 stream cipher** to encrypt packet payloads.
- **Key Configuration:** It uses a static, pre-shared secret key (commonly 40-bit or 104-bit length, expressed as hexadecimal
  digits) that must be manually configured on both the client device and the Access Point (AP).
- **Critical Flaws:** WEP proved to be notoriously insecure. Its implementation of RC4 reused short Initialization Vectors
  (IVs), meaning that attackers using readily available software could capture enough network traffic packets and quickly
  derive the static WEP key—often in just a few minutes. Because of these fatal cryptographic flaws, WEP was officially
  deprecated and superseded by WPA and WPA2.

### Shared Key Authentication

**Shared Key Authentication** is an 802.11 authentication algorithm that _requires_ the use of WEP to prove that a client
device possesses the correct pre-shared secret key before granting it network access.

Unlike Open System Authentication (which accepts all connection requests regardless of identity), Shared Key Authentication
actively attempts to verify the client using a multi-step challenge-response mechanism.

#### How the 4-Step Process Works:

1. **Authentication Request:** The client station sends an initial 802.11 management frame to the AP requesting connection
   via Shared Key Authentication.
2. **Challenge Text:** The Access Point responds by sending a piece of random, cleartext data called **challenge text** back
   to the client.
3. **Encrypted Response:** The client takes the challenge text, encrypts it using its configured static WEP key, and sends it
   back to the AP in an authentication response frame.
4. **Verification and Result:** The AP attempts to decrypt the received response using its own copy of the static WEP key. If
   the decrypted text matches the original challenge text sent in step 2, the AP validates the client, confirms success, and
   allows the association to proceed.

---

### Why Shared Key Authentication is Dangerous

Although Shared Key Authentication sounds more secure on paper than Open System Authentication because it checks a key, it is
actually **less secure** and poses a severe risk:

- **The Flaw:** During the challenge-response handshake, an attacker can passively monitor the wireless airwaves and capture
  _both_ the unencrypted challenge text (sent by the AP) and the encrypted version of that same text (sent by the client).
- **The Explaxit:** Having both the plaintext and ciphertext versions of the exact same data allows an attacker to
  mathematically derive the underlying WEP keystream. Once that keystream is known, the static WEP key is compromised,
  allowing unauthorized full access to the network.

Because of these catastrophic vulnerabilities, both WEP and Shared Key Authentication are obsolete, deprecated, and should
never be used in modern network environments.
