A **site-to-site VPN** creates an encrypted tunnel between two routers/firewalls, so devices on LAN A can communicate with
devices on LAN B as if the networks were connected.

A common setup looks like this:

```text
LAN A                         Internet                    LAN B
192.168.1.0/24                                         192.168.2.0/24
     │                                                       │
     │                                                       │
┌────┴─────┐          IPsec VPN tunnel                 ┌─────┴────┐
│ Router A │══════════════════════════════════════════│ Router B │
│ WAN: ... │              encrypted                   │ WAN: ... │
└──────────┘                                          └──────────┘
```

### What you need

For an **IPsec site-to-site VPN**, configure both routers with matching:

1. **WAN/public IP addresses**
   - Router A: e.g. `203.0.113.10`
   - Router B: e.g. `198.51.100.20`

2. **Different LAN subnets**
   - Site A: `192.168.1.0/24`
   - Site B: `192.168.2.0/24`

3. **VPN type**
   - Usually **IPsec/IKEv2** (IKEv1 is also supported by some equipment).

4. **Authentication**
   - Typically a pre-shared key (PSK), or certificates.

5. **Matching encryption parameters**
   - IKE version
   - Encryption algorithm
   - Integrity/hash algorithm
   - Diffie-Hellman group
   - Lifetime

6. **Traffic selectors / networks**
   - Router A: local `192.168.1.0/24` → remote `192.168.2.0/24`
   - Router B: local `192.168.2.0/24` → remote `192.168.1.0/24`

7. **Routing**
   - Traffic destined for the other LAN must go through the VPN.

8. **Firewall rules**
   - Allow the desired traffic between the two LANs.
   - On the Internet-facing side, IPsec commonly requires UDP **500** and **4500** when NAT-T is used, plus ESP (IP
     protocol 50) when applicable.

### Example configuration

Suppose:

|               | Site A           | Site B           |
| ------------- | ---------------- | ---------------- |
| LAN           | `192.168.1.0/24` | `192.168.2.0/24` |
| Router LAN IP | `192.168.1.1`    | `192.168.2.1`    |
| Public IP     | `203.0.113.10`   | `198.51.100.20`  |
| PSK           | `MyStrongSecret` | `MyStrongSecret` |

On **Router A**:

```text
VPN type:       IPsec
Remote gateway: 198.51.100.20
Local network:  192.168.1.0/24
Remote network: 192.168.2.0/24
Authentication: PSK
```

On **Router B**:

```text
VPN type:       IPsec
Remote gateway: 203.0.113.10
Local network:  192.168.2.0/24
Remote network: 192.168.1.0/24
Authentication: PSK
```

Then configure matching IKE/IPsec proposals on both sides.

### Testing

After the tunnel comes up:

```text
PC at Site A: 192.168.1.50
        │
        │ ping 192.168.2.50
        ▼
     VPN tunnel
        │
        ▼
PC at Site B: 192.168.2.50
```

Try:

```bash
ping 192.168.2.50
```

If ping doesn't work, check the **VPN status, routes, firewall rules, and whether NAT is being incorrectly applied to VPN
traffic**.
