In security, **ACL** usually means **Access Control List**.

It is a set of rules that determines **who or what is allowed to access a resource, and what they can do with it**.

### Example

Suppose a file has this ACL:

| User/Group | Permission   |
| ---------- | ------------ |
| Alice      | Read + Write |
| Bob        | Read         |
| Guest      | Deny         |

So:

- **Alice** can view and modify the file.
- **Bob** can view it but not modify it.
- **Guest** cannot access it.

### Where ACLs are used

- **Operating systems** — control access to files and folders.
- **Networks** — firewall/router ACLs allow or block traffic based on IP, port, protocol, etc.
- **Cloud platforms** — control access to resources such as storage buckets.
- **Applications** — determine which users can perform particular actions.

### ACL vs. RBAC

A useful distinction:

- **ACL:** _“What can this particular user access?”_
- **RBAC (Role-Based Access Control):** _“What can users with this role access?”_

For example, an ACL might say **Alice → read/write `/finance/report.xlsx`**, while RBAC might say **Accountants → read/write
financial reports**.

In short: **ACL = a list of access permissions attached to a resource.**
