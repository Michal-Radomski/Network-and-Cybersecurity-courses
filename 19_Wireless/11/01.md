### What is WLAN Architecture?

**WLAN (Wireless Local Area Network) architecture** refers to the structural framework that defines how wireless devices
(like laptops, smartphones, and IoT gadgets) connect to a wired network infrastructure using radio waves.

Depending on the size of the network, the number of users, and administrative needs, WLAN architectures range from simple
home setups to massive, centrally managed enterprise systems.

---

### Key Components of a WLAN

- **Wireless Clients (Stations / STA):** End-user devices equipped with wireless network interface cards (NICs), such as
  laptops, tablets, and phones.
- **Access Points (APs):** Hardware devices that act as a bridge between wireless clients and the wired Ethernet network.
- **WLAN Controllers (WLC):** Centralized devices or cloud platforms used in enterprise settings to manage, configure, and
  monitor multiple access points simultaneously.
- **Distribution System:** The wired backbone (usually Ethernet switches and routers) that connects access points to each
  other, local servers, and the internet.

---

### Types of WLAN Architecture

#### 1. Autonomous (Fat / Standalone) AP Architecture

- **How it works:** Each access point operates independently. It contains its own configuration, security settings, and
  management interface.
- **Use Case:** Small offices or home networks where there are only one or two APs.
- **Drawback:** Difficult to scale. If you have 50 APs, an administrator must log into each individual device to update
  firmware, change passwords, or modify configurations.

#### 2. Centralized (Split-MAC / Controller-Based) Architecture

- **How it works:** Management and decision-making are split between the AP and a central WLAN Controller (WLC). The AP
  handles real-time physical layer functions (like radio frequency transmission), while the controller handles heavy tasks
  like security, authentication, roaming, and configuration management.
- **Use Case:** Large enterprise environments, universities, and corporate offices.
- **Benefit:** Allows for **Zero-Touch Provisioning**, seamless roaming between APs without dropping connections, and
  centralized security policy enforcement.

#### 3. Cloud-Managed Architecture

- **How it works:** Similar to centralized architecture, but instead of a physical on-site controller hardware, the control
  plane lives in the cloud (managed by providers like Cisco Meraki, Aruba Central, or Ubiquiti).
- **Use Case:** Distributed organizations, retail chains, and multi-branch businesses.
- **Benefit:** Administrators can manage thousands of access points across different global locations from a single web-based
  dashboard.

#### 4. Controllerless (Distributed / Virtual Controller) Architecture

- **How it works:** A group of access points work together as a cluster. One AP dynamically acts as the "master" or virtual
  controller for the group, coordinating configurations and roaming without needing a separate hardware controller box.
- **Use Case:** Medium-sized businesses looking for enterprise features without the extra cost of a dedicated controller.
